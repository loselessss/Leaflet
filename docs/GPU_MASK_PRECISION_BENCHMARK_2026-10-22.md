# 마스크 합성 정수화·저정밀 비교 — 2026-10-22

개발 버전 1.37.1 / ABI 24 / 기준은 전날 타일 계획·선택 binding까지의 개발 DLL.

## 실험 범위

사용자 요청에 따라 투명 마스크의 마지막 합성 셰이더만 바꿨다. 그리기 명령, 타일 계획, 자원 준비, 캡처·backdrop 복사, Flush 경계와 BGRA8 저장은 모두 같다. 일반 source-over 전체, 복잡한 blend mode나 gradient 생성 자체를 정수 구현으로 교체한 실험은 아니다.

비교한 구현:

- float: 기존 ps_4_0, /Gis /O3. source와 backdrop 항을 각각 8비트 기준으로 반올림한 뒤 더한다.
- fixed: 실제 시간 비교는 fixed-fast 후보다. 텍스처에서 읽은 UNORM 값을 0~255 정수로 복원하고 uint32 곱셈·덧셈·shift로 계산한다. 첫 fixed 후보의 중복 floor/saturate를 제거했다. 정수화가 메모리 저장 형식이나 텍스처 크기를 바꾸지는 않는다.
- relaxed: ps_5_0, /O3, /Gis 제외인 float32 대조군. min16과 비교해 정밀도와 컴파일 옵션 영향을 구분한다.
- min16: min16float/min16float4, ps_5_0, /O3, /Gis 제외. 현재 FXC는 /Gis와 최소 정밀도 조합을 X4028 오류로 거부했다. HLSL의 half는 이 실험에서 쓰지 않았다.

정수 계산의 핵심은 다음과 같다(각 RGBA 채널에 적용).

```hlsl
uint4 divide255(uint4 value) {
    value += 128u;
    return (value + (value >> 8u)) >> 8u;
}
uint4 outside = divide255(backdrop * (255u - coverage));
uint4 inside = divide255(source * coverage);
return float4(outside + inside) / 255.0;
```

0~65,025의 모든 곱셈 결과 65,026개에서 정수 나눗셈식이 nearest-round /255와 같은지 확인했다. 각 항을 따로 반올림하는 기존 규칙은 유지한다. 입력은 네이티브 코드의 backdrop/source/mask BGRA8 bitmap 세 개라 0~1 범위를 전제로 한다.

## 정밀도와 검사

Intel Iris Xe 하드웨어. CheckFeatureSupport가 pixel/other stage 모두 0x2(16비트 최소 정밀도 지원)를 보고했고, min16 DXBC에 enableMinimumPrecision과 min16f 연산이 있음을 확인했다. 다만 이 정보가 드라이버의 실제 기계 명령을 완전히 증명하는 것은 아니다. 최소 정밀도 지원과 32비트 확장 동작은 [Microsoft 설명](https://learn.microsoft.com/en-us/windows/win32/direct3dhlsl/using-hlsl-minimum-precision)을 따른다.

256×256 ramp는 256개 마스크 알파와 256개 채널 값의 모든 조합을 포함한다. CPU의 독립적인 각 항 반올림 식과 GPU 출력 65,536픽셀을 비교했다. 기존 합성 검사 16개는 투명 backdrop, 마스크 transfer, 중첩·DPI·타일 경계도 포함한다.

| 후보 | DXBC 명령 슬롯 | ramp 바뀐 픽셀 | ramp 최대 채널 차이 | 검사 수 / 실패 subcase 수 |
|---|---:|---:|---:|---:|
| float | 16 | 0 | 0 | 16 / 0 |
| fixed | 31 | 0 | 0 | 16 / 0 |
| fixed-fast | 25 | 0 | 0 | 16 / 0 |
| relaxed | 13 | 0 | 0 | 16 / 0 |
| min16 | 14 | 6,048 | 2 | 16 / 46 |

DXBC 명령 슬롯은 FXC 출력이며 GPU cycle 수나 벤더 기계 명령 수가 아니다. min16의 실패 46건은 16개 테스트 안의 subcase 실패 45건(반올림)과 worker 경계 검사 1건이다. 경계 차이는 기존 허용 3을 넘어 4가 됐다. 허용치를 바꾸지 않았다.

정수 후보는 초기 31슬롯에서 중복 변환을 제거해 25슬롯으로 줄였지만 float의 16슬롯보다 많다. UNORM 샘플이 float로 들어오므로 float→uint→float 변환이 필요하고, 실제 integer 텍스처나 더 작은 입력 버퍼로 바뀐 것은 아니다. 모든 후보에서 custom mask effect 평가 카운터가 증가해 일반 합성 fallback만 측정한 것이 아님을 확인했다.

## 적용 판단

기본 구현은 기존 float를 유지한다. 정수화는 정확도를 보존하지만 이번 전체 완료 측정에서 ACB 2015 맞춤·100%가 약 2~3% 단축되고 200%가 약 3% 악화되는 등 조건별로 결과가 섞였다. ACB 2019에서도 맞춤은 느려지고 확대는 빨라졌다. 정수 변환으로 DXBC 명령 슬롯이 늘고 중간 화면 크기는 같으므로 일관된 속도·버퍼 메모리 이득이 확인되지 않은 상태에서 기본 경로를 복잡하게 만들지 않는다.

min16은 실제 저정밀 지원 GPU에서 반올림·경계 검사 일부를 실패했고, 전체 완료도 일관되게 개선되지 않았다. relaxed float 역시 기존 방식보다 항상 빠르지 않아 strict 설정 변경을 채택하지 않는다. 입력·출력 형식과 복사·합성 호출 수를 줄이는 후속 설계와, 이 산술 형식만의 실험을 구분한다.

## 재현과 보존

네이티브 정수 후보는 C++17 /W4 /WX /O2와 strict /Gis shader 빌드, 저정밀·대조군은 같은 C++ 옵션과 별도 non-strict shader 빌드를 통과했다. 실험 DLL에는 동일한 mask 평가 카운터와 최소 정밀도 조회 함수만 추가했고 일반 개발 DLL에는 추가하지 않았다.

기존 개발 DLL SHA-256: a70088460d3ec1d2678a80d3ecb7ab6a8ba3b4214d34179e14bc4e342ba1f429. 실험 후 같은 해시임을 확인했다. 기존 작업 트리의 구조 개편·버전·설치 이름 변경도 보존했다. 공개 ABI·CPU fallback·릴리스 버전은 변경하지 않는다.

개인 원자료는 tmp/gpu-alpha-integer/의 HLSL·DXBC·DLL·quality.json·검사 로그·comparison/results.json·comparison/mask-evaluations.json·pixel-summary.json에 있다. 입력 PDF와 BGRA, 진단 DLL은 커밋하거나 공개하지 않는다.

재현: 기존 tests/benchmark_gpu_pipeline.py에 --mode sharp --repeats 15 --poll-ms 5와 네 개 --library를 지정한다. fixed는 fixed-fast 빌드를 가리킨다. 이 수치는 해당 GPU·드라이버·화면의 관측 결과이며 모든 GPU에서 같은 성능 순서를 보장하지 않는다.
