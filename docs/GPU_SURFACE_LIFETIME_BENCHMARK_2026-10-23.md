# 임시 GPU 표면 수명 계획·묶음 할당 비교

측정일: 2026-10-23 · Leaflet 1.37.1 개발 중 · Intel Iris Xe · ABI 24

## 채택한 변경

**타일당 최대 256슬롯의 수명 계획을 기본 개발 경로에 적용했다.** 타일 안의 합성 그룹이 필요로 하는 임시 표면의 크기와 겹치는 수명을 분석하고, 같은 크기의 표면들을 D3D11 texture array에 묶어서 할당한다. 최대 4096슬롯의 전체 계획보다 일부 속도 이득은 작지만, 저장소 보관량을 제한하면서 반복 할당을 줄이는 절충안이다.

문서 결과 이미지를 저장하거나 다음 프레임의 그리기를 생략하는 캐시가 아니다. 매 표본 새 장면을 만들고 도형·마스크·혼합을 다시 실행한다. 표면 크기·색상·해상도·shader 계산·합성 순서·명시적 Flush 경계를 바꾸지 않았다. Direct2D 도형 래스터화와 D3D11을 유지하며 DX12는 도입하지 않았다.

## 구현 범위와 수명

- 타일 계획과 binding을 준비한 다음, 실제 replay 전에 합성 스택을 분석한다. 부모의 crop 원점, transform, passthrough clip, 단순 layer, isolated clip 경계, mask 생성→적용 전환을 따라가며 필요한 표면 크기를 계산한다.
- source·coverage·mask content·backdrop의 필요한 개수를 그룹 종류별로 계산한다. 같은 크기의 활성 그룹이 겹치는 최대 개수를 추적한다. 첫 구현은 표면 전체를 그룹의 시작부터 닫기까지 보수적으로 예약한다. 각 입력의 실제 생성 시점을 모두 세분한 최소 메모리 계획은 아니다.
- 크기별 요청 수/필요 슬롯 수가 높은 항목을 먼저 준비한다. 크기를 반올림하거나 다른 크기의 표면을 억지로 공유하지 않는다. array당 최대 128개 slice, 타일당 최대 256개 bitmap 슬롯이다. 분석 종류와 중첩 깊이는 각각 4096개로 제한한다. 기존 타일 계획의 입력 명령 상한도 유지한다.
- 같은 크기의 target용 slice와 닫기용 복사 입력 slice를 하나의 array로 만들고, 각각 DXGI subresource surface와 D2D bitmap으로 연결한다. 실제 borrower는 정확한 크기·용도와 미사용 상태를 다시 확인한다. 계획이 부족하거나 맞지 않으면 원래 scratch 경로로 할당한다. 계획을 그대로 믿고 살아 있는 입력을 덮어쓰지 않는다.
- GPU 입력의 마지막 사용은 기존 닫기 draw가 예약되는 시점이다. 원래 target 전환 순서와 복사 Flush를 유지한다. 마스크 raw source는 원래처럼 mask scope 닫기까지 유지한다. 취소·작업 교체·문서 해제는 기존 worker 수명 규칙을 따른다.
- 계획 저장소와 기존 scratch pool은 기존 pixel-byte 예산을 나눠 쓴다. 할당 전에 기존 pool을 trim하고, 다음 타일 또는 작업 종료 때 계획 저장소를 해제한다. 활성 capture 예산이 부족해지면 선택적 계획 저장소 참조를 포기하고 원래 경로를 계속 쓴다. 활성 capture가 가진 참조는 남으며, 해당 array slice가 일반 bitmap pool로 이동하지 않도록 반환 시 identity를 확인한다.
- D2D에서 직접 bitmap brush로 isolated clip을 채우는 source는 원래 bitmap 할당을 유지한다. 이 경로까지 array로 바꾼 초기 후보는 기존 기울어진 경계 검사에서 최대 차이 18로 허용치 6을 넘었다. 해당 경로를 제외한 뒤 기존 허용치를 그대로 유지하고 통과했다.
- 분석 실패, 지원하지 않는 command-list mask, 메모리·슬롯 한도, array/DXGI/D2D wrapper 생성 실패는 기존 할당 경로를 사용한다. 계획·저장소 생성은 worker에서 실행하고 UI에 새 대기를 추가하지 않는다.

API 연결 근거: [DXGI subresource surface](https://learn.microsoft.com/en-us/windows/win32/api/dxgi1_2/nf-dxgi1_2-idxgiresource1-createsubresourcesurface), [D2D bitmap from DXGI surface](https://learn.microsoft.com/en-us/windows/win32/api/d2d1_1/nf-d2d1_1-id2d1devicecontext-createbitmapfromdxgisurface%28idxgisurface_constd2d1_bitmap_properties1_id2d1bitmap1%29). API 객체·slice 수와 드라이버 내부의 실제 할당 개수·byte 수는 구분한다.

## 비교 조건

- ACB 2019·2015 첫 페이지, 1200×900 viewport, 96 DPI, 맞춤·100%·200%, raster scale 1.
- 요청부터 전체 정밀 atlas 완료·UI import까지 측정한다. 초기 Python 장면 추출·불변 geometry upload·retained scene 생성은 타이머 밖이다. 타일 수명 분석·사전 할당·worker replay는 타이머 안이다. GPU timestamp만의 측정은 아니다.
- 각 조건 3회 예열 후 15회 측정하고, 같은 프로세스에서 library 실행 순서를 교차·회전했다. UI polling은 1ms다. 측정 중 다른 GPU 테스트·빌드·진단을 실행하지 않았다.
- 전체 계획 후보는 최초 2개 DLL 비교 후 별도의 3개 DLL 비교에서 재측정했다. 메모리를 제한한 256슬롯 후보를 고른 다음, 개발 빌드 통합·byte 예산 보강·전체 검사 후 실제 최종 DLL과 기준 DLL을 다시 15회씩 비교했다. 실행 간 절대 시간은 직접 비교하지 않는다.
- 별도의 2회 표본 진단은 API 호출 수와 메모리만 확인한다. 해당 진단의 시간은 성능 표에 섞지 않는다. 메모리는 library당 별도 프로세스, 문서당 별도 실행으로 관찰했다.

## 출력·검증

- 그룹별 후보 6개, 최초 전체 계획 6개, 재측정 전체 계획·256슬롯 각각 6개, 통합 후 확인 6개, 최종 15회 비교 6개 등 저장된 후보 화면 36개가 각각 기준과 byte 단위로 같다. 최종 포스터 두 문서·세 배율 모두 바뀐 픽셀 0이다.
- 모든 benchmark case가 오류 없이 예정된 표본 수를 완료했다.
- 관련 GPU 검사 107개 통과. 최종 소스 정리와 공유 예산 trim 보강 후 합성 검사 17개도 통과했다.
- 별도 WARP 16개+새 수명 검사 1개, 계획 저장소 확보 실패 16개+새 수명 검사 1개, 활성 capture가 있는 동안 저장소를 포기하는 강제 retirement 검사 17개를 통과했다.
- 새 수명 검사는 72개 크기의 중첩 mask·비선형 transfer·15종 blend를 세 번 반복하고, 96→192→96 DPI에서 독립 direct replay와 완전히 비교한다. 기존 DLL에서도 같은 엄격 검사가 통과한다.
- C++17 /W4 /WX /O2와 기존 strict shader 빌드를 통과했고 ABI는 24다.

처음 isolated clip source까지 array로 바꿨을 때 실패한 기존 경계 검사는 허용치를 변경하지 않고 해당 경로를 제외해 해결했다. 다수의 표면 크기를 반복하는 별도 진단에서 144 DPI의 direct/worker 참조는 원래 DLL에서도 일부 경계 차이가 있었고 후보 worker 출력은 원래 worker와 byte 단위로 같았다. 새 회귀 검사는 96→192→96 DPI와 물리 pixel에 맞춘 좌표로 독립 direct replay와 완전 일치를 요구한다. 기존 테스트의 허용치는 바꾸지 않았다.
