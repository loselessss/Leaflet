# sPDF 편집 모드 업데이트 계획

작성일: 2026-09-09 · 기준 구현: sPDF 1.30.2

상태: 1.31.0 기반 시제품 구현 중. 아래 전체 단계의 배포 일정은 미정이다.

### 1.31.0 착수 범위와 남은 기반 작업

- 사각형·이미지 생성, 단일 선택·이동·모서리 크기 조절, mm 속성 입력·삭제를 연결했다. 드래그는 경계 미리보기이며 확정 시에만 PDF 내용을 변경한다.
- 자체 개체의 ID·원본 스트림·변형 정보를 PDF 내부 참조로 저장한다. 기존 안전 PDF 저장·복구 경로를 사용하며 별도 조판 작업 형식은 아직 만들지 않았다.
- 기존 PDF 스냅샷 이력에 통합해 문자 편집·페이지 연산·개체 변경을 동일 순서로 되돌린다. 메모리 효율적인 개체 명령 기반 어댑터는 후속이며, 아래 0단계를 모두 완료한 것은 아니다.
- 회전·CropBox가 있는 페이지의 좌표를 검증한다. 생성 후 페이지 박스가 바뀌거나 개체 스트림이 외부에서 수정되면 오래된 모델을 적용하지 않고 재편집을 비활성화한다.
- 다중 선택·회전 핸들·비율 잠금·색상 속성·텍스트 프레임과 독립 작업 형식은 후속 범위다. 개체 내용 전체의 드래그 미리보기와 변경 영역만 갱신하는 최적화도 남아 있다.

## 1. 목표와 기존 계획의 관계

현재의 PDF 글자 수정 중심 편집기를 글·그림·도형을 정확하게 배치하는 작업 공간으로 확장한다. 자주 쓰는 명령은 짧은 도구 모음과 선택 속성 패널에서 실행하고, 세부 명령은 파일·편집·개체·문자·보기 메뉴에서 찾을 수 있게 한다.

이 문서는 [조판·레이아웃 편집 계획](LAYOUT_EDITING_PLAN.md)의 기능 범위를 메뉴와 구현 순서로 구체화한다. 스타일·연결 텍스트 프레임·마스터·인쇄 출력의 상세 요구는 기존 계획을 따른다. 기존 문서의 과거 버전별 구현 설명은 이 문서의 기준 현황과 구분한다. 메뉴에 항목이 있다는 이유만으로 모든 고급 기능을 첫 배포 범위에 포함하지 않는다.

완성된 사용 흐름은 다음과 같다.

1. 편집기에서 PDF를 수정하거나 새 배치 문서를 만든다.
2. 텍스트·이미지·도형을 넣고 위치·크기·정렬을 조절한다.
3. 작업을 저장하고 PDF로 출력한다.
4. 리더로 돌아가기를 누르면 미저장 변경을 확인하고, 대상이 문서를 연 뒤 편집 탭을 닫는다.

기존 PDF의 원래 경로·글리프를 렌더링할 수 있다는 사실은 해당 요소를 자유롭게 편집할 수 있다는 뜻이 아니다. PDF 표시 장면과 편집 모델을 분리한다. 기존 PDF 전체를 자동으로 분해해 그룹·문단·레이어까지 복원하는 기능은 약속하지 않는다.

새 조판 문서는 원본 PDF를 잠긴 배경 또는 배치 개체로 보존하고 새 개체부터 편집한다. 원래 PDF 글자를 수정하는 명령은 현재 기능으로 별도 제공한다. 스캔 이미지에 OCR을 적용해도 사진 속 도형이 편집 개체로 바뀌지는 않는다.

## 3. 메뉴 설계

메뉴 순서는 **파일 / 편집 / 개체 / 문자 / 선택 / 페이지 / 보기 / 창 / 도움말**을 목표로 한다. 주석·OCR은 편집기의 전용 도구 진입점과 보조 메뉴에 유지하며 기존 기능을 제거하지 않는다. 메뉴 이동 시 기존 단축키와 접근성을 함께 검증한다. 아직 구현하지 않은 기능으로 긴 비활성 메뉴를 채우지 않는다.

### 파일

| 명령 묶음 | 적용 계획 |
| --- | --- |
| 새로 만들기·열기·최근 파일·닫기 | 기존 열기 유지. 새 배치 문서와 빈 페이지는 개체 모델·저장 왕복과 함께 제공 |
| 저장·다른 이름으로 저장·사본 저장 | 일반 PDF 저장과 조판 작업 파일 저장 대상을 명확히 표시. 사본 저장은 현재 작업 대상 유지 |
| 가져오기·배치 | 이미지·PDF·SVG를 현재 페이지의 개체로 넣기. 문서 열기와 구분 |
| 내보내기 | PDF·페이지 이미지부터, 선택 개체·영역 출력은 후속 |
| 문서 설정·색상·인쇄 | 캔버스·도련의 기존 명령 연결. 색상 프로필·PDF/X는 별도 검증 단계 |
| 템플릿·패키지 | 마스터·스타일·자산 관리 이후. 글꼴 포함은 허용된 범위만 |
| 버전 기록·협업·스크립트·외부 서비스 | 첫 배포 제외. 자동 복구를 사용자 버전 기록으로 표시하지 않음 |

### 편집

- 실행 취소·다시 실행은 기존 Ctrl+Z / Ctrl+Y를 유지한다.
- 잘라내기·복사·붙여넣기·삭제는 포커스에 따라 문자 범위 또는 선택 개체에 적용한다. 입력란에서 Delete를 눌렀을 때 페이지 개체가 삭제되지 않아야 한다.
- 제자리에 붙여넣기를 우선 제공한다. 앞·뒤에 붙여넣기는 겹침 순서 모델 이후, 여러 페이지에 붙여넣기는 적용 범위와 한 번의 실행 취소를 포함해 후속 제공한다.
- 찾기와 기존 PDF의 일괄 바꾸기는 구분한다. 새 텍스트 프레임의 찾기·바꾸기를 먼저 지원하며 임의 PDF 본문의 일괄 재조판은 제외한다.
- 색상 편집은 기존 계획의 색조·채도·단색화·HEX 색상 맞추기에 통합한다.
- 단축키 설정·환경 설정은 문서 편집 명령과 분리한다. 맞춤법·사전은 문자 조판 기반 이후 검토한다.

숨김은 새 조판 문서의 출력에서도 제외하는 개체 상태로 정의하고, 안내선·선택 경계의 화면 표시 토글과 구별한다. 향후 화면 전용/비인쇄 개체가 필요하면 별도 속성으로 추가한다.

### 문자

- 첫 단계: 새 텍스트 프레임의 글꼴·크기·색상·가로 정렬·줄 간격·프레임 내부 여백. 기존 PDF 수정 도구는 별도 대상임을 표시한다.
- 다음 단계: 자간·커닝·문단 간격·들여쓰기·문단/문자 스타일·글머리 기호·번호 매기기·특수문자 삽입.
- 영역 문자 맞춤은 프레임 크기와 넘침 표시로 제공한다. 글자가 넘칠 때 자동으로 글자 크기를 줄이지 않는다.
- 연결 텍스트 프레임·기준선 격자·누락 글꼴 점검은 기존 조판 계획에 통합한다. 원문과 프레임 연결 관계를 함께 저장한다.
- 윤곽선 만들기는 원문을 보존한 출력 옵션부터 제공한다. 편집 개체 자체의 윤곽선 변환은 별도 명령으로 후속 검토한다.
- 세로쓰기·경로 위 문자·합성 글꼴·금칙/간격 조정은 정밀 조판 후속 과제다. 외부 폰트 서비스와 문자 인식 기반 재작성은 기본 의존성으로 넣지 않는다.

### 선택·보기·창

| 영역 | 적용 계획 |
| --- | --- |
| 선택 | 개체 전체 선택·해제·추가 선택, 잠금/숨김 제외. 문자 입력 중에는 문자 선택. 종류별 선택은 후속 |
| 확대·맞춤·회전 보기 | 기존 기능 유지. 화면 회전과 페이지 자체 회전을 이름으로 구분 |
| 선택 경계·투명 격자 | 화면 보조 요소만 토글하며 PDF 출력에는 포함하지 않음 |
| 눈금자·안내선·문서 격자·스냅 | 정밀 배치의 핵심. 표시와 스냅을 각각 설정, 드래그 중 일시 해제 |
| 트림 보기·도련 보기 | 페이지 박스 모델과 연결한 출력 영역 확인. 캔버스 변경과 구분 |
| CPU/GPU 미리보기 | 기존 렌더러 설정에 통합. 상시 표시는 탭의 실제 CPU/GPU 경로 중심 |
| 실제 크기 | 일반 100%와 구분. 모니터 보정은 기존 계획의 후순위 유지 |
| 오버프린트·색상 교정·픽셀 미리보기 | 색상 관리·출력 검증 이후. 명칭만 먼저 제공하지 않음 |
| 창 | 속성·개체 목록·페이지·문자 패널 열기/닫기, 기본 배치 복원 |

선택 메뉴의 상세 항목은 sPDF의 개체 선택 모델을 기준으로 제안한다. 편집기에 프레젠테이션·전체화면 기능을 다시 추가하는 것은 이번 범위에 포함하지 않는다.

## 4. 화면 구성과 조작 원칙

상단은 현재의 얇은 메뉴와 명령 모음을 유지한다. 리더 복귀·열기·저장·실행 취소를 고정하고, 선택에 따라 자주 쓰는 명령만 보강한다. 큰 리본이나 과도한 설명 문구로 작업 면적을 줄이지 않는다.

| 위치 | 역할 |
| --- | --- |
| 왼쪽 얇은 도구 모음 | 개체 선택·텍스트·기본 도형·손 도구. 미구현 도구는 숨김 |
| 왼쪽 패널 | 기존 페이지 썸네일·책갈피. 페이지 순서 편집은 별도 구성 창 유지 |
| 중앙 | 문서, 선택 핸들, 필요할 때 눈금자·안내선 |
| 오른쪽 접이식 패널 | 선택 종류에 따라 변형·모양·문자·이미지 속성 표시 |
| 하단 | 페이지·문서 치수·실제 확대 배율. 내부 장면 정보는 상시 노출하지 않음 |

선택이 없으면 페이지 속성, 하나면 해당 개체 속성, 여러 개면 공통 속성과 정렬 도구를 보여준다. 서로 다른 값은 혼합 상태로 표시하고 0으로 오인시키지 않는다. 좁은 창에서는 보조 패널을 접고 명령 모음의 넘침 메뉴를 사용한다. 한국어·영어, 키보드 포커스, Windows 100/125/150/200% 배율을 검증한다.

기존 Ctrl+E(텍스트 편집), Ctrl+B(책갈피), Ctrl+Shift+P(페이지 구성)와 충돌하는 단축키를 그대로 가져오지 않는다. 새로운 명령은 충돌표를 먼저 작성하고, 문자 입력 중 한 글자 도구 단축키는 실행하지 않는다.

## 5. 편집 모델과 구현 구조

### 데이터와 이력

- 안정적인 문서·페이지·개체 ID와 개체별 종류, 변환 행렬, 겹침 순서, 잠금·숨김, 자산 참조, 스타일을 정의한다.
- 화면 픽셀과 분리된 문서 좌표를 사용한다. 내부는 PDF pt와 정밀 변환을 유지하고, 패널의 mm/pt 표시에만 반올림을 적용한다.
- Create/Delete/Transform/SetProperty/Group 명령에 실행·취소 정보를 보관한다. 드래그 중에는 임시 변환만 표시하고 마우스를 놓을 때 한 명령으로 확정한다. Esc는 원래 상태로 복원한다.
- 기존 PDF 스냅샷 명령과 새 개체 명령을 공통 순서로 관리하는 어댑터를 먼저 설계한다. 별도 undo 스택 두 개가 서로 다른 순서로 되돌아가게 만들지 않는다. 페이지 삭제·재정렬도 개체 ID와 참조를 복원해야 한다.
- 저장·복구는 원본과 명령을 재생할 수 있는 문서 상태를 보존한다. 현재 PDF 저장 경로를 한꺼번에 교체하지 않고 통합 이력의 저장 왕복을 먼저 검증한다.

### 모듈 경계 제안

| 위치 | 책임 |
| --- | --- |
| `editor_workspace.py` | 편집 화면 조립과 모드 전환 연결 |
| 새 명령 레지스트리 | 메뉴·도구 모음·단축키의 동일 명령, 대상별 활성화 |
| 새 개체 모델·이력 모듈 | 문서/개체 상태, 명령 적용·취소·재생 |
| 새 선택·변형 컨트롤러 | hit-test, 선택, 드래그, 스냅, 확정/취소 |
| 새 속성 패널 | 모델 값의 표시와 명령 발행, 직접 PDF 변경 금지 |
| `core.py` 및 저장 어댑터 | 기존 PDF 연산, 안전 저장, 문서 세대 관리 |
| 렌더러 어댑터 | 배경 PDF 장면과 편집 개체 표시, GPU/CPU 결과 일치 |

새 모듈 이름과 파일 형식은 구현 단계에서 확정한다. `app.py`는 창 조립 역할을 유지한다. 내장 모드의 접근 제한·업데이트 비활성 정책은 바꾸지 않는다.

### 표시와 저장

- 원본 PDF 배경은 기존 캐시를 재사용한다. 개체 드래그 때 전체 PDF 장면 추출·디스크 저장을 반복하지 않는다.
- 새 개체는 GPU가 벡터·문자·이미지를 직접 그리는 경로로 연결하고, CPU 대체에서도 동일 좌표와 출력 결과를 유지한다.
- 원래 PDF glyph 윤곽의 재현과 새 텍스트의 조판은 별도 책임이다. 새 텍스트는 화면과 PDF 출력이 같은 배치 결과를 사용하도록 엔진을 검증한다.
- 작업 파일은 원문·자산·개체·그룹·스타일을 보존하고, PDF 내보내기는 독립 결과물을 만든다. 출력 실패 시 기존 파일을 유지한다.
- 일반 PDF의 Ctrl+S 의미는 유지한다. 새 조판 작업의 저장 대상을 명확히 하며, 다른 프로그램에서 수정된 PDF에 오래된 편집 모델을 조용히 덧씌우지 않는다.
- 리더 인계 시 미저장 조판 문서의 저장/출력 필요 여부를 명확히 처리한다. 리더가 열 수 있는 PDF가 성공적으로 준비되기 전에는 편집 탭을 닫지 않는다.

## 6. 단계별 실행 계획

| 단계 | 구현 묶음 | 완료 조건 |
| --- | --- | --- |
| 0. 기반 시제품 | 명령 체계, 개체 ID, 변환, 통합 undo, 최소 작업 파일 | 사각형 한 개 생성→이동→취소→저장→재개방→PDF 출력이 일치 |
| 1. 실용 배치 | 새 문서/빈 페이지, 기본 도형·이미지·텍스트 프레임, 다중 선택, 속성 패널 | 그림 6개와 제목·라벨을 배치하고 재편집 가능하게 저장 |
| 2. 정밀 작업 | 정렬·간격·같은 크기·그룹·잠금·겹침 순서, 눈금자·스냅, PDF/SVG 배치·자르기 | 회전·CropBox·고배율에서도 수치 입력과 드래그·PDF 출력 좌표 일치 |
| 3. 문자 조판 | 문자/문단 스타일, 연결 프레임, 기준선, 넘침·누락 글꼴 점검 | 한글·영문 혼합 문서의 편집·저장·출력에서 줄바꿈과 원문 보존 |
| 4. 반복 제작 | 개체 스타일, 색상 보정, 배열 복제, 마스터·템플릿·문서 규칙 | 공통 스타일 변경의 영향과 페이지별 예외가 보존되고 한 번에 취소 가능 |
| 5. 출력 강화 | ICC/CMYK·PDF/X·재단표시·사전 점검 | 대상 출력 조건을 독립 검증하고 실패 시 기존 결과물 보존 |

기존 계획의 ‘첫 배포’ 항목은 이 문서의 0~2단계에 걸친 구현 묶음이다. 일부 기능만 개발됐을 때 기존 첫 배포 범위를 모두 완료한 것으로 표시하지 않는다. 고급 패스·효과 편집은 별도 후속 계획으로 결정한다.

## 7. 성능·품질 검증

- 첫 화면, 캐시 재사용, 입력 후 첫 반응, 드래그 프레임 p50/p95, 확정 후 정밀 화면, 저장 시간을 따로 측정한다. 기준 장비와 문서 크기를 함께 기록하며 수치 목표는 초기 측정 후 확정한다.
- GPU와 CPU 경로에서 같은 모델 좌표·선택 영역·텍스트·이미지 자르기·클리핑을 비교한다. 장면 생성 성공만으로 GPU 성능 개선을 완료 처리하지 않는다.
- 1/100/1,000개 자체 생성 개체와 고해상도 이미지 조합으로 화면 밖 항목 제외·자원 재사용·메모리 상한을 점검한다. 모든 페이지를 미리 렌더링하지 않는다.
- 이동 한 번은 실행 취소 한 번, Esc 취소는 이력 추가 없음, 그룹 변형·페이지 재정렬 후 ID와 선택 상태 복원을 확인한다.
- 텍스트 프레임 편집 중 단축키 충돌, 미저장 전환 취소, 출력 실패, 닫기/재실행 복구를 확인한다.
- 문서 권한·암호·원본 비파괴 저장을 유지하고, 조판 작업에서도 편집 제한을 우회하지 않는다.
- 최종 번역 검사는 코드·문서 변경이 끝난 뒤 수행한다. 검증용 문서는 자체 생성한 일반 자료로 만들며 개발 문서에는 문서 내용·경로를 기록하지 않는다.

## 8. 첫 착수 범위

첫 구현은 **개체 모델 + 사각형/이미지 선택·변형 + 오른쪽 속성 패널 + 저장/undo 왕복**으로 제한한다. 메뉴 재배치는 작동하는 명령부터 함께 연결한다. 텍스트 프레임은 최소 글꼴·배치·출력 시제품으로 엔진을 먼저 검증한 뒤 1단계에 합류시킨다.

이 묶음을 통과하면 단순한 메뉴 외형 변경을 넘어 실제 배치 편집의 기반이 된다. 이후 정렬·그룹·문자 조판을 같은 모델 위에 확장한다.
