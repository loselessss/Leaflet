# sPDF Studio 조판·레이아웃 편집 업데이트 계획

작성일: 2026-08-31 · 구현 현황 갱신: 2026-09-02

상태: 검토용 초안 — 기능 구현·배포 전

2026-09-09 보완: 최신 편집 구현을 기준으로 한 메뉴·화면 구성과 단계별 실행 순서는 [편집 모드 업데이트 계획](EDITOR_UPDATE_PLAN.md)을 따른다. 아래의 과거 구현 설명과 미구현 요구사항을 구분하며, 조판 기능의 상세 요구는 이 문서에 유지한다.

기준: 1.19.2 — 기존 편집 작업 공간 위에 추가할 미구현 기능 계획

## 제1원칙 — 한 파일은 한 작업 모드만 소유한다

**sPDF Studio는 하나의 제품이며, 리더와 편집·조판은 별도 OS 프로세스로 실행한다. 같은 파일은 인계가 끝난 뒤 하나의 작업 모드만 계속 소유한다.** 대상 프로세스의 문서 열기 성공을 확인한 뒤 원래 탭을 닫고, 마지막 탭이면 원래 프로세스도 종료한다. 이 원칙은 조판 기능 추가보다 먼저 검증할 필수 조건이다.

- 창만 분리하거나 같은 프로세스의 작업 스레드로 나누는 것으로 완료 처리하지 않는다. 리더와 편집기는 각각 이벤트 루프, 문서 상태, GPU 컨텍스트와 캐시를 소유한다. GPU 렌더러의 코드 재사용은 허용하되 실행 상태를 결합하지 않는다.
- 읽기 창에서 편집 모드를 열면 편집 프로세스를 필요할 때 실행한다. 시작 모드는 설정에서 리더 우선 / 편집 우선으로 선택하도록 계획하며, 기존 기본 동작은 리더 우선이다. 리더에 조판 의존성을 선행 로드하지 않는다.
- 프로세스 간 문서 열기·저장 완료 알림은 비동기로 전달한다. 대상의 열기 실패·연결 끊김·시간 초과에는 원래 탭을 유지하고, 성공 응답 뒤에만 원래 탭과 빈 창을 닫는다.
- 저장은 임시 파일에 완성한 후 안전하게 교체한다. 파일 핸들 조정·재개방도 실패와 시간 초과를 처리하고, 편집기 중단 시 리더가 문서 없는 상태로 남지 않도록 한다. 완료된 문서만 갱신하며 읽던 위치를 보존한다. 편집기의 미저장 작업 복구는 리더 수명과 독립적으로 관리한다.
- 일반적인 2D PDF·조판 작업에서 개발 중 오류·네이티브 충돌·무응답을 격리하는 것이 핵심이다. 3D·전지 크기 조판은 고부하 예시이며 이번 요청으로 구현 범위를 넓히지 않는다. 극단적 메모리 부족을 주된 전제로 삼지는 않되, RAM/VRAM 캐시 상한과 자원 회수는 유지한다. 시스템 전체 자원 고갈·GPU 드라이버 장애까지 완전한 격리를 보장하지는 않는다.

**구현 현황(2026-09-02):** sPDF 1.20.0에서 리더·기존 편집기의 OS 프로세스 분리, 시작 모드, 비동기 알림, 안전 저장과 독립 복구를 구현했다. 1.22.0에서는 독립 실행 리더·편집기에 같은 제한형 타일 표시를 적용했고, 1.23.0에서는 실제 Windows 창에 D3D11/DXGI/Direct2D 표면을 연결해 타일과 선택 표시를 합성한다. 지원되는 페이지는 MuPDF CPU 파서의 벡터 경로와 원래 글꼴 glyph 윤곽을 Direct2D가 직접 래스터화하고, 디코딩한 이미지를 GPU에서 확대·합성한다. 1.24.0에서는 중첩된 벡터 경로 클리핑과 색상 스텐실 이미지 마스크를 연결했고, 1.25.0에서는 정확한 글자 윤곽 클리핑, 제한된 shading 이미지와 일반 격리 투명도 그룹을 추가했다. 미지원 PDF 명령은 완전한 CPU 대체 경로를 유지한다. [구현·검증 범위](PROCESS_ISOLATION.md)를 참고한다. 소프트 마스크·특수 혼합 모드와 조판 개체의 전체 GPU 렌더링 및 아래 조판 기능은 여전히 계획이다. 외부 리더 API의 기존 접근·업데이트 정책은 유지한다.

## 1. 목표와 범위

### 선행 조건 — GPU 기반의 반응성 있는 편집 화면

리더·편집기 양쪽의 GPU 렌더링 기반을 조판 기능 확장보다 먼저 검증한다. 제1원칙에 따라 공통 렌더러 코드는 각 프로세스에서 독립 실행하며 GPU 컨텍스트·문서 상태를 공유하지 않는다.

1.25.0에서는 PyMuPDF가 CPU에서 만든 저해상도 미리보기와 보이는 512px 타일을 Direct2D로 합성한다. 탭당 이미지 캐시는 64 MiB로 제한하며 GPU를 사용할 수 없으면 같은 좌표·편집 결과를 유지하는 Qt 표시 경로로 전환한다. 지원되는 페이지는 CPU에서 PDF를 해석한 뒤 단순 선·사각형·베지어, 단색 fill/stroke, 원래 글꼴 glyph 윤곽을 Direct2D geometry로 올려 GPU에서 래스터화하고, 디코딩한 배치 이미지와 색상 스텐실 마스크를 원래 행렬로 확대·합성한다. 중첩된 벡터·텍스트 클리핑, 제한된 shading 이미지와 일반 격리 투명도 그룹도 지원한다. 소프트/클리핑 마스크·특수 혼합 모드·비격리 반투명 그룹·복잡한 선 모양·조판 개체까지 GPU 경로가 완성된 것은 아니다.

Windows용 다음 백엔드는 **D3D11 + DXGI flip-model swap chain + Direct2D device context + DirectWrite** 조합을 우선한다. Direct2D는 PDF 해석기가 아니므로 초기에는 현재 타일을 Direct2D bitmap으로 합성하고, 실제 PDF 벡터·글자 GPU 표시는 별도 엔진 경로로 검증한다. 기존 PDF의 glyph 배치를 DirectWrite로 임의 재조판하지 않는다. 세부 경계와 완료 기준은 [Windows 렌더링 백엔드 설계](WINDOWS_RENDERING_BACKEND.md)를 따른다.

- 확대·축소·이동뿐 아니라 선택 개체의 드래그·크기 조절·회전·색상 미리보기까지 빠르게 갱신하는 경로를 목표로 한다. 정적인 배경·자산은 재사용하고 변경 개체와 영향을 받는 영역만 다시 그린다.
- 현재 CPU가 만든 이미지를 GPU로 확대·합성하는 수준과 PDF 벡터·글자·조판 개체 자체를 GPU로 그리는 수준을 구분한다. 전자만으로 이 선행 조건을 완료 처리하지 않는다. 엔진 이름만으로 GPU 지원을 가정하지 않고 실제 배포 가능한 렌더링 경로를 검증한다.
- PDF 해석, 문자 배치·재흐름, 정렬 계산, 저장·출력 등 CPU 작업은 유지한다. 변경 부분 계산과 취소 가능한 비동기 작업으로 UI 대기를 줄인다. GPU 렌더링만으로 모든 편집 작업이 빨라진다고 보장하지 않는다.
- 동일 장비·문서에서 기존 경로와 비교해 입력 후 첫 화면 반응, 연속 드래그 중 프레임 지연, 확정 후 선명한 화면까지 걸린 시간, RAM/VRAM 사용량을 측정한다. A4 그림 배치와 많은 개체·고해상도 이미지, 최대 800% 확대에서 글꼴·투명도·클리핑 품질도 검사한다. 수치 목표는 기준 장비와 샘플을 정한 뒤 확정한다.
- GPU 미지원 환경에는 CPU 대체 경로와 안내를 제공한다. GPU 화면 표시와 PDF 출력 모델은 분리하고, 대체 경로에서도 편집 내용·저장 결과는 유지한다.

### 조판 기능 범위

Illustrator 없이 PPT로 작업할 때 번거로운 **글·그림·도형의 정확한 배치와 문자 조판**을 sPDF 편집 창에서 처리한다. 반복적인 위치·크기·간격 맞추기를 줄이고, 편집 가능한 작업 파일과 선명한 배포용 PDF를 남기는 것이 목표다.

이 계획에서 ‘조판’은 한 페이지의 개체 배치뿐 아니라 **여러 페이지의 텍스트 흐름·공통 스타일·마스터·배치 규칙을 유지하고 인쇄용 PDF로 출력하는 작업**까지 포함한다. 사용자가 요청한 기능 범위는 아래에 통합하며, 배포 순서는 기술 검증 후 확정한다. 인쇄용 여러 쪽 모아 찍기·책자 접지 순서 배치는 별도 후속 과제로 구분한다.

‘기존’은 구현 완료가 아니라 기존 계획에 있던 항목을 뜻한다. 아래 항목은 모두 개발 예정이며 현재 기능으로 홍보하지 않는다.

### 이번 범위에서 제외

- Illustrator의 전체 기능 복제, 임의 AI 파일의 원본 편집 구조 복원.
- 모든 PDF의 기존 글·그림·패스를 자동으로 완벽한 편집 개체로 변환.
- 베지어 점 편집, 패스 합치기·빼기, 복잡한 마스크·블렌드·필터. 개체별 색조·채도·단색화는 6.1절의 기본 색상 보정으로 포함한다.
- 수식 엔진, 세로쓰기, 긴 책의 자동 페이지 생성·목차·색인. 명시적으로 연결한 프레임의 여러 페이지 텍스트 흐름은 5.3절에 포함한다.
- 별색 제작·분판을 포함한 모든 인쇄 공정의 완전한 지원. CMYK·ICC 기반 출력과 PDF/X는 7절의 단계별 검증 대상으로 포함한다.
- PPTX 직접 편집·왕복 저장. 초기에는 PPT에서 내보낸 PDF나 이미지로 가져온다.
- EPS 직접 가져오기·출력은 보류한다. PDF·이미지·SVG를 조판 재료로 사용한다.
- 문서 파싱·조판 계산·저장까지 CPU를 전혀 쓰지 않는 구성. 읽기·편집 모두 GPU 화면 렌더링을 목표로 하되 엔진 검증은 별도 기술 단계로 진행한다.
- 내장 모드 정책 변경, 자동 OCR 실행.

## 2. 현재 코드에서 출발할 지점

- `pdfeditor/editor_workspace.py`: 상세 편집 진입과 별도 바둑판 페이지 구성 창의 연결이 있다.
- `pdfeditor/editing.py`, `pdfeditor/core.py`: 기존 글자 교체와 새 글자 삽입, 크기·색상 변경이 있다. 현재 `add_text_box()`는 좌표에 글자를 쓰는 방식으로, 크기 조절 가능한 문단 프레임 모델은 아니다.
- `pdfeditor/widgets.py`: 텍스트 선택·손 도구·편집 영역 표시가 있다. 조판용 개체 선택·변형·그룹 모델은 아직 없다.
- `pdfeditor/conversions.py`: 이미지의 PDF 페이지 변환은 있지만, 여러 그림을 한 페이지에 자유롭게 배치하는 작업 공간은 아니다.
- 현재 일반 PDF 편집의 실행 취소는 PDF 바이트 스냅샷을 보관한다. 기존 `PLAN.md`의 연산 재생 구상과 실제 구현이 다르므로, 드래그할 때마다 전체 PDF를 복제하는 방식으로 확장하지 않는다.
- 현재 저장은 임시 파일 생성 후 교체한다. 이 안전성은 조판 작업 파일과 출력 PDF에도 유지한다.

기존 PDF의 줄 단위 수정과 새 조판용 텍스트 프레임은 다른 기능이다. 새 기능을 추가해도 ‘기존 PDF의 모든 문단이 자동으로 다시 흐른다’고 안내하지 않는다.

## 3. 사용 흐름과 화면 구성

1. 설정된 시작 모드에 따라 리더 또는 편집 프로세스로 시작한다. 읽기 창의 큰 **편집 모드** 버튼은 별도 편집 프로세스에 문서를 넘기고, 열기 성공 뒤 같은 파일의 읽기 탭을 닫는다. 마지막 탭이면 리더 프로세스도 종료한다.
2. 편집 창은 상세 편집 화면으로 시작한다. 조판 작업에는 **새 조판 문서**와 **빈 페이지 추가**를 제공한다.
3. 페이지 구성은 별도 바둑판 창에서 처리하고, 페이지를 두 번 누르면 해당 쪽의 상세 편집으로 돌아온다. 여기서 **개체 선택 / 글자 편집 / 손 도구**를 명확히 구분한다.
4. 그림·PDF 일부·텍스트·도형을 배치하고 정렬한다.
5. 작업 파일을 저장하거나 **PDF로 내보내기**를 실행한다. 별도 페이지 구성 창을 열어도 개체·그룹·미저장 변경을 유지한다.

화면 배치는 다음 안을 우선 검토한다.

- **리본:** 캔버스 크기·여백·도련, 삽입, 정렬·간격, 그룹·겹침 순서, 안내선·격자 표시. 자주 쓰는 배치 버튼에는 아이콘과 짧은 이름을 함께 표시한다.
- 1.29.0 첫 구현은 현재 쪽 캔버스 크기, 현재 쪽 TrimBox/BleedBox 도련 설정, 편집 가능한 텍스트 요소 크기 조절을 기존 편집/undo 흐름에 연결했다. 전체 layout object 모델, guide/grid, SVG 직접 배치, crop mark/slug 출력은 아직 남아 있다.
- **왼쪽:** 기존 페이지 썸네일·책갈피 영역. 상세 편집의 썸네일은 페이지 이동용이며 순서 변경은 별도 바둑판 창에서만 한다.
- **중앙:** 페이지와 선택 핸들, 눈금자·안내선. 안내선은 출력되지 않는다.
- **오른쪽 접이식 속성 패널:** 선택 종류에 따라 위치·크기·각도 또는 문자·문단 속성을 표시한다. 스타일·마스터·문서 규칙 관리는 전환 가능한 패널로 제공하며 모두 동시에 펼치지 않는다.
- **개체 목록:** 이름, 표시·숨김, 잠금, 겹침 순서를 관리한다. PDF 내부의 모든 패스를 자동 나열하지 않고 sPDF 조판 개체부터 표시한다.

`[편집 전용]` 표시는 탭에만 유지한다. 편집 창에 프레젠테이션·전체화면 버튼을 다시 추가하지 않으며, 기존 UI보다 글자와 패널을 불필요하게 키우지 않는다.

## 4. 1차 기능: 정확한 배치

### 4.1 개체 생성과 선택

- 빈 페이지: A4·A3, 가로·세로, 사용자 지정 가로·세로 mm. 생성 후에도 캔버스 크기·여백을 변경할 수 있다(4.6·4.7절).
- 텍스트 상자, 이미지, PDF 페이지·영역, 사각형·타원·직선·화살표.
- 클릭·범위 드래그·Shift 추가 선택, 개체 목록에서 선택, 선택 해제.
- 개체 이동·복제·삭제, 그룹·해제, 잠금·해제, 앞으로·뒤로 보내기.
- 잠긴 배경을 끌지 않게 하고, 겹친 개체는 목록에서 정확하게 고른다.
- 새 개체의 붙여넣기·복제는 sPDF 내부에서 우선 지원한다. 외부 클립보드는 일반 텍스트·비트맵부터 지원하며 PPT 개체가 벡터로 그대로 붙는다고 보장하지 않는다.

### 4.2 정렬·간격·크기

- 좌·가운데·우 / 위·중간·아래 정렬.
- 기준 선택: 페이지, 여백 안쪽, 선택 범위, 지정한 기준 개체.
- 같은 폭·높이·크기, 가로·세로 동일 간격.
- ‘중심 간격 동일’과 ‘개체 가장자리 사이 빈 간격 동일’을 구분한다.
- 간격을 mm로 직접 입력한다. 그룹은 하나의 경계 상자로 계산하며 잠긴 개체는 이동하지 않는다.
- 개체 하나만 선택했을 때의 페이지 정렬 등, 선택 수에 따라 가능한 명령만 활성화한다.

### 4.3 정밀 이동·변형

- X/Y, W/H는 기본 mm 단위로 입력하고 회전 각도와 9점 기준점을 함께 표시한다. 내부 좌표는 정밀도를 유지하고 표시만 반올림한다. 문자 크기·행간의 pt 단위와 혼동하지 않는다.
- 기본 원점은 재단된 페이지의 왼쪽 위다. 도련·slug를 추가해도 개체의 페이지 기준 좌표는 바뀌지 않으며, mm↔pt 변환은 공통 좌표 계층에서 처리한다.
- 비율 잠금, 크기 조절 핸들, 키보드 미세 이동. 이동 단위는 설정 가능하게 한다.
- 눈금자·안내선·문서 격자는 4.8절에서 통합 관리하고, 여백·페이지 중심선·개체 가장자리·중심 스냅과 함께 사용한다.
- 현재 스냅 대상과 간격을 표시하고 일시 해제 수단을 제공한다.
- 회전 페이지·잘린 페이지·고해상도 화면에서도 같은 문서 좌표를 사용한다.
- 개체 회전과 PDF 페이지 자체 회전은 서로 다른 명령으로 유지한다.

### 4.4 그림 배치

- 파일 드롭 → 배치 미리보기 → 원하는 위치에 넣기.
- 비율 유지, 프레임 안에 맞춤 / 프레임 채움, 비파괴 자르기.
- 그림 교체 시 프레임·정렬 위치·크기는 유지한다. 새 원본의 비율이 다르면 미리보기로 확인한다.
- PDF의 한 쪽 또는 사각 영역을 **배치된 PDF 개체**로 가져온다. 내부 글자·패스는 이 단계에서 각각 편집하지 않는다.
- PDF 호환 `.ai`는 기존처럼 PDF 표현만 사용하고 AI 원본에 저장하지 않는다.
- **SVG 직접 배치:** `.svg` 파일을 변환 프로그램 없이 드롭하거나 파일 선택으로 삽입한다. 원본을 자산으로 보관하고, 하나의 배치 개체로 이동·크기 조절·회전·자르기·교체한다. SVG 내부 패스를 개별 편집하는 기능과 구분한다.
- `viewBox`·치수·비율·변형·채움·선·그라데이션·클리핑·텍스트의 지원 범위를 샘플로 검증한다. 화면과 PDF 출력에서 가능한 요소는 벡터로 유지한다. 누락 글꼴·미지원 필터/마스크는 알리고, 조용히 저해상도 이미지로 대체하지 않는다. 제한적 래스터 변환이 필요하면 명시적 동의와 해상도 설정을 받는다.
- 스크립트·애니메이션·외부 네트워크/임의 로컬 파일 참조·XML 외부 엔티티는 실행·조회하지 않는다. 내장 자산에도 크기·중첩·처리 시간 상한을 둔다. 정적 자산 처리의 근거는 [W3C SVG 2의 secure static mode](https://www.w3.org/TR/SVG2/conform.html#secure-static-mode)이며, 보안 모드 선택만으로 파서 자원 제한이 해결된다고 보지 않는다.

### 4.5 첫 배포의 기본 문자 기능

- 설치된 글꼴 선택, 글자 크기·색상, 실제 글꼴이 제공하는 굵기·기울임.
- 프레임 내부 줄바꿈, 좌·가운데·우 정렬, 내부 여백.
- 프레임 넘침 표시. 글자를 몰래 줄이거나 잘라 저장하지 않고, 축소·상자 확장·내용 수정 중 사용자가 선택한다.
- 글꼴 누락·대체를 분명하게 알리고 원본 스타일 정보를 남긴다.

### 4.6 캔버스 크기 변경

조판에서 캔버스는 각 페이지의 **최종 재단 크기(TrimBox)**를 뜻한다. 화면 확대 비율이나 이미지 DPI 변경, 도련·재단표시를 포함한 출력 용지 크기와 구분한다.

- A4·A3 등의 규격, 가로·세로 전환, 사용자 지정 가로·세로 수치 입력. 기본 단위는 mm이며 pt 표시도 지원하는 안으로 잡는다.
- 새 문서 생성뿐 아니라 작업 도중 변경도 지원한다. 현재 페이지 / 바둑판에서 선택한 페이지 / 전체 페이지에 적용하고, 서로 다른 크기의 페이지를 한 문서에 둘 수 있다.
- **기본은 내용 크기 유지:** 캔버스만 바꾸며 그림·글자·선 두께를 자동 확대·축소하지 않는다. 기본 기준점은 왼쪽 위이며, 가운데·모서리 등을 고르는 9점 기준점으로 내용의 상대 위치를 결정한다.
- **내용도 비율 유지해 맞춤**은 별도 선택 사항으로 제공한다. 이 경우 글자·선·그룹까지 포함한 전체 배치의 균일 배율과 위치 변화를 미리 보여주며, 가로·세로를 서로 다르게 늘려 왜곡하지 않는다.
- 캔버스를 줄였을 때 바깥으로 나가는 개체를 강조한다. 임의 삭제·자동 축소는 하지 않으며, 취소·크기 재조정·바깥 개체를 유지한 적용 중 선택한다. 바깥 개체는 작업 파일에 남겨 다시 가져올 수 있게 한다.
- 적용 전 새 경계와 내용 위치를 겹쳐 보여주고, 여러 페이지 변경도 한 번의 실행 취소로 되돌린다. 잠금 개체도 페이지 전체 변환에는 함께 따라가되 잠금 상태는 유지한다.
- PDF 내보내기의 TrimBox 치수는 변경한 캔버스와 일치해야 한다. 도련·표시용 출력 영역은 4.9절에 따라 별도로 확장하고 MediaBox·CropBox 불일치로 내용이나 재단표시가 잘리지 않게 검증한다.
- 기존 PDF의 **페이지 여백 자르기**와 별도 명령으로 제공한다. 초기에는 조판 문서에 적용하며, 가져온 PDF를 배치 개체로 썼다면 그 소스 파일 자체는 바꾸지 않는다.

### 4.7 조판용 여백과 배치 영역

- 위·아래·왼쪽·오른쪽 여백을 mm로 각각 설정하고, 연결 버튼으로 네 값을 함께 바꿀 수 있게 한다.
- 현재 / 선택 / 전체 페이지 적용과 문서 기본값을 구분한다. 새 페이지는 기본값을 따르되 페이지별 예외를 저장한다.
- 여백 안쪽을 배치 가능 영역으로 표시하고, 그 경계·중앙에 정렬·스냅할 수 있게 한다. 표시·숨김과 스냅 켜기·끄기는 독립적이다.
- 여백은 **출력되지 않는 조판 기준선**이다. 기본적으로 변경해도 내용 이동·크기 조절·자르기·문단 재배치를 자동 실행하지 않는다. 여백 영역에 맞추기와 문서 규칙 적용은 별도 명령으로 실행한다(6.3절).
- 캔버스 크기를 바꿔도 여백 수치는 기본적으로 같은 mm를 유지한다. 여백 합이 페이지 폭·높이 이상이 되거나 음수이면 적용을 막고 수정할 값을 알린다.
- 캔버스 바깥으로 나간 개체와 여백 안쪽 영역을 벗어난 개체를 다르게 표시한다. 여백 침범은 허용 가능한 배치 경고이며 저장을 무조건 막지 않는다.
- 페이지 여백, 텍스트 상자 내부 여백, 프린터의 인쇄 가능 영역, 재단용 도련은 서로 다른 설정으로 다룬다. 프린터를 바꿨다고 조판 여백이나 개체 위치가 바뀌면 안 된다.
- 첫 배포는 네 방향 여백을 필수로 한다. 안쪽·바깥쪽 맞쪽 여백과 제본 여유는 3단계의 마스터·문서 규칙에 통합한다. 단 수·단 사이 간격 안내선은 4.8절에 포함하며 텍스트 프레임의 실제 다단 흐름과 구분한다.

### 4.8 안내선·문서 격자(guide/grid)

- 눈금자에서 드래그하거나 mm 수치로 가로·세로 안내선을 만든다. 선택·이동·삭제·잠금과 페이지별/문서 공통 적용을 제공한다.
- 문서 격자는 X/Y 간격·원점·세분 눈금을 설정한다. 단 안내선은 여백 안의 단 수·단 사이 간격으로 계산하되 텍스트를 자동으로 생성하거나 연결하지 않는다.
- 표시·숨김, 스냅 사용, 잠금을 각각 제어한다. 스냅 후보가 겹칠 때 우선순위를 표시하고 일시 해제를 지원한다. 저배율에서는 눈금을 성기게 그리되 실제 스냅 간격은 바꾸지 않는다.
- 안내선과 격자는 작업 파일·마스터에 저장하며 PDF 내용으로 출력하지 않는다. 문서 격자는 개체 배치용이고, 글줄을 맞추는 기준선 격자(baseline grid)는 5.4절의 별도 설정이다.

### 4.9 재단 크기·도련·slug·재단표시

- **TrimBox:** 최종 재단 경계. 문서 기본값과 페이지별 재정의를 지원하며, 캔버스 치수와 같은 값으로 관리한다.
- **Bleed / BleedBox:** 재단 밖으로 인쇄 내용을 연장하는 도련 영역. 상하좌우 mm를 각각 설정하고 연결 입력을 제공한다. 0 mm도 허용한다. 도련 값을 늘린다고 이미지 가장자리를 임의 복제·확대하지 않으며, 실제 내용의 도련 부족을 검사한다.
- **Slug:** 도련 바깥의 작업 지시·문서명 등 제작 정보 영역. 작업 파일에 별도로 저장하고, 출력 시 포함 여부를 고른다. 조판 여백이나 도련으로 합치지 않는다.
- **Crop marks:** 재단 경계를 알리는 출력용 표시. 길이·선 두께·오프셋을 설정하고 도련 내용과 겹치지 않도록 검증한다. 편집 안내선과 달리 명시적으로 선택한 출력에만 포함한다. [표시·오프셋·출력 옵션 참고](https://helpx.adobe.com/indesign/using/printers-marks-bleeds.html)
- sPDF가 생성하는 인쇄용 PDF는 `TrimBox ⊆ BleedBox ⊆ MediaBox`가 되도록 구성한다. MediaBox는 선택한 slug·재단표시까지 담을 만큼 확장한다. CropBox는 화면 배포/인쇄 프리셋에 맞게 정하고, 재단표시를 포함하는 출력에서 해당 표시가 잘리지 않게 미리보기와 함께 검사한다. slug를 임의의 PDF 표준 박스 이름으로 기록하지 않는다.
- 일반 화면용 PDF와 도련·재단표시가 있는 인쇄용 PDF를 구분한다. 기본 화면 배포에 제작 메모가 노출되지 않게 slug 출력은 기본 OFF로 둔다. 현재·선택·전체 페이지 변경을 한 번에 취소할 수 있고, 회전·혼합 크기 페이지의 경계도 검증한다.
- 1단계에서 치수·영역 모델과 미리보기를 만들고, 재단표시·slug가 포함된 완성 출력은 4단계의 인쇄 검증을 통과한 뒤 제공한다.

## 5. 2차 기능: 텍스트 흐름·문자·문단 조판

개체 배치와 저장이 안정화된 뒤, 문자 조판을 다음 기능 배포의 중심으로 삼는다.

### 5.1 문자·문단 속성과 정밀 간격

- **문자:** 선택 구간별 서식, 행간, 위·아래 첨자, 기준선 이동.
- **Tracking:** 선택 구간 전체의 글자 간격을 조절한다. **Kerning:** 특정 글자 쌍의 간격을 조절한다. 글꼴 메트릭 사용/수동 보정/해제를 구분하고 수치 단위와 초기화를 제공한다. 광학 커닝은 별도 엔진 검증을 통과할 때 추가하며, 지원하지 않는데 같은 이름의 옵션을 노출하지 않는다.
- **문단:** 문단 앞·뒤 간격, 들여쓰기, 탭 위치, 양끝 정렬, 프레임 내 세로 정렬.
- **한국어·영문 혼용:** IME 조합, 문장부호 줄바꿈, 숫자·기호·그리스 문자, 글꼴 대체를 샘플로 확인한다.
- **넘침 확인:** 출력 전 넘치는 텍스트와 누락 글꼴 목록에서 해당 상자로 이동한다.
- 합자·결합 문자·한글 조합을 임의로 쪼개지 않고, 조판 엔진의 글리프 측정과 배치를 화면·PDF 출력에 공통 사용한다. 글자 가로 비율과 광학 커닝의 세부 범위는 0단계에서 확정한다.

### 5.2 문단·문자 스타일 관리

- **문단 스타일**과 **문자 스타일**을 별도 목록으로 관리한다. 문단 스타일은 글꼴·문단 간격·들여쓰기·정렬·기준선 격자 적용 등을, 문자 스타일은 선택 구간의 글꼴·크기·색·tracking 등 필요한 속성만 정의한다.
- 생성·복제·이름 변경·삭제·정의 갱신·선택 항목에 적용·사용 위치 찾기와 문서 내 그룹 관리를 제공한다. 삭제 시 대체 스타일을 선택하거나 현재 모양을 직접 서식으로 보존한다.
- 기반 스타일 상속과 부분 재정의를 지원하고 순환 상속을 차단한다. 적용 우선순위는 문단 기본값 → 문자 스타일 → 직접 지정한 예외 서식으로 명시한다.
- 원본 스타일 수정은 연결된 모든 페이지에 반영한다. 예외 서식은 눈에 띄게 표시하고, 유지/지우기/스타일에 반영을 구분한다. 일괄 변경 전 영향 페이지와 넘침을 확인하고 한 번의 실행 취소로 복원한다.
- 스타일 ID로 참조를 보관하며 문서·템플릿 간 가져오기 시 같은 이름의 충돌을 확인한다. 단순 서식 복사와 연결된 스타일 적용은 다른 명령이다.

### 5.3 연결 텍스트 프레임

- 여러 프레임이 하나의 원문(스토리)을 순서대로 표시한다. 같은 페이지·여러 단·다른 페이지로 연결할 수 있으며, 글자를 프레임별 사본으로 중복 저장하지 않는다.
- 입력/출력 연결점, 흐름 방향·순서, 마지막 프레임의 넘침 표시와 해당 위치로 이동을 제공한다. 프레임 크기·문자·스타일 변경 시 뒤쪽 프레임으로 다시 흐르되 자동 축소하지 않는다.
- 연결·해제·중간 프레임 삽입·순서 변경을 명시적 명령으로 제공하고 연결 순환을 막는다. 프레임/페이지 삭제는 원문 삭제와 구분하며, 내용은 남은 흐름이나 넘침 원문에 보존한다. 원문 자체를 지우는 명령은 별도로 확인한다.
- 페이지 재정렬만으로 스토리 순서를 임의로 바꾸지 않는다. 연결 변경·재배치·삭제·복구가 실행 취소와 저장 왕복에 참여한다. 초기에는 사용자가 마련한 프레임 안에서만 흐르고 페이지 무한 자동 생성은 하지 않는다.

### 5.4 기준선 격자(baseline grid)

- 글줄의 기준선을 페이지·프레임 사이에서 일정하게 맞추는 격자다. 개체 배치용 문서 격자와 별도로 원점·시작 위치·간격·표시 배율을 설정한다.
- 문서 기본 격자와 프레임별 재정의를 지원하고, 문단 스타일에서 미적용/모든 줄/첫 줄 정렬을 선택한다. ‘격자 표시’와 ‘문단을 격자에 맞춤’은 별도 옵션이다.
- 행간·문단 간격·첫 기준선·세로 정렬이 충돌할 때 처리 우선순위를 명시하고, 격자 적용으로 흐름·넘침이 바뀌면 미리보기에서 알린다. 한글·영문 혼합, 서로 다른 글자 크기와 연결 프레임에서도 화면·출력의 기준선이 일치해야 한다.

기존 PDF의 본문을 조판 프레임으로 바꾸는 것은 자동 기본 동작이 아니다. 후속의 **선택 영역을 새 텍스트로 재작성** 기능으로 검토하며 원본 비교·글꼴 대체 확인이 필요하다. 스캔본은 OCR을 해도 사진 속 개체가 분리되는 것은 아니다.

## 6. 3차 기능: 개체 스타일·마스터·문서 전체 규칙

### 6.1 개체 스타일(object style)

- 선 두께·색·채움·투명도·모서리, 이미지 맞춤/자르기 방식, 텍스트 프레임 내부 여백·단 설정 등을 이름 있는 스타일로 저장한다. 기본 도형 속성 보강도 이 항목에 통합한다.
- 적용할 속성만 선택하고 개체 종류에 맞지 않는 속성은 구분한다. 위치·크기까지 강제하는 배치 규칙은 기본 개체 스타일과 분리하여, 모양을 적용했는데 개체가 뜻밖에 이동하지 않게 한다.
- 문자 스타일과 공통 관리 틀을 사용하되 별도 유형으로 저장한다. 상속·부분 예외·초기화·사용 위치·일괄 갱신·삭제 대체를 지원한다. 텍스트 프레임의 기본 문단 스타일은 참조로 연결한다.

#### 개체별 비파괴 색상 보정 — Hue / Saturation / Colorize

- 선택 개체의 속성 패널에 **색조(Hue)·채도(Saturation)·단색화(Colorize)**를 둔다. 슬라이더와 수치 입력, 보정 ON/OFF, 원본 비교, 초기화를 제공한다. 초기 상태는 보정 없음이며, 슬라이더 드래그 한 번을 실행 취소 한 번으로 묶는다.
- 색조는 기존 색의 계열을 이동시키고, 채도는 색의 강도를 줄이거나 높인다. 단색화는 사용자가 지정한 색조·채도로 명암을 살린 단색 계열을 만드는 별도 모드다. 회색 개체에도 색을 입힐 수 있게 하며, 단순히 불투명한 색 사각형으로 덮는 기능과 구분한다. [비파괴 색조·채도 보정 참고](https://helpx.adobe.com/photoshop/desktop/adjust-color/selective-color-adjustments/replace-object-colors-by-applying-a-hue-or-saturation-adjustment.html)
- 적용 대상은 이미지·텍스트·도형·배치된 PDF/SVG·그룹 등 **sPDF 조판 개체**다. 기존 PDF의 모든 내부 요소를 자동 분해하는 기능은 아니다. 이미지와 sPDF에서 만든 텍스트·도형부터 검증하고, 배치 PDF/SVG·그룹은 합성·출력 검증 후 같은 조작 방식으로 확장한다.
- 원본 이미지/PDF/SVG와 원래 채움·선·문자 색은 보존하고 **개체 인스턴스별 보정값**만 저장한다. 같은 자산을 두 번 배치해도 한 개체의 보정이 다른 개체를 바꾸지 않아야 한다. 텍스트 편집 가능 여부·자르기·위치·투명도는 유지한다.
- 여러 개 선택 시에는 각 개체에 적용하고, 그룹 선택 시에는 해당 그룹 범위에만 적용한다. 부모/자식 보정의 적용 순서와 그룹 합성 방식을 명시하며, 뒤쪽 페이지 배경이나 선택하지 않은 이웃 개체까지 보정하지 않는다. 투명 픽셀·마스크 경계의 색 번짐을 검증한다.
- 보정값을 개체 스타일의 선택 속성으로 저장·복사·재사용하고 직접 지정한 예외도 표시한다. 원본 이미지 교체 시에는 보정 유지/초기화를 선택하며, 저장·재개방·복제·미저장 탭 이동에서도 같은 결과를 유지한다.
- GPU 미리보기에서 선택 개체만 빠르게 갱신하는 경로를 검증한다. CPU 대체 표시와 PDF 출력에도 같은 보정 정의·작업 색상 공간을 사용한다. 보정 슬라이더마다 전체 문서를 다시 렌더링하거나 원본 크기의 사본을 계속 쌓지 않는다.
- PDF 출력에서는 이미지의 출력용 사본과 지원하는 벡터·텍스트 색상에 보정을 반영한다. GPU 화면을 통째로 캡처해 저장하지 않는다. 그라데이션·투명도·별색·복잡한 배치 PDF/SVG에서 벡터 유지가 불가능하면 대상을 알리고, 해당 개체만 명시적 동의·해상도 설정으로 래스터화하거나 출력을 취소한다. 텍스트 유지 출력과 충돌하는 변환도 조용히 적용하지 않는다.
- 색상 보정과 출력용 ICC/CMYK 변환은 별도 단계로 정의한다. 보정 후 출력 프로필로 변환하고 PDF/X를 검증하되, 원래 색상·프로필·보정값은 작업 파일에 보존한다. 화면 색과 인쇄 색의 동일성을 무조건 보장하지 않는다.

#### 컬러코드로 PNG·SVG 색상 맞추기

기존 색상 보정 패널에 **목표 색상 코드**를 추가한다. 배치한 로고·아이콘·도해의 색을 동일한 코드로 맞추는 기능이며, 별도 이미지 편집 프로그램이나 SVG 패스 편집기로 범위를 확장하지 않는다.

- **입력:** `#RRGGBB`와 축약형 `#RGB`를 우선 지원한다. 예: `#2563EB`. HEX는 sRGB로 해석하고 색상 견본·정규화된 코드를 함께 표시한다. 잘못된 입력은 적용 전에 알리며 기존 상태를 바꾸지 않는다. 투명도는 색 코드와 별도로 유지한다. [HEX 색상 표기 기준](https://www.w3.org/TR/css-color-4/#hex-notation)
- **지정 색 그대로 적용:** 대상의 RGB를 입력 색으로 바꾸고 원래 알파·마스크를 유지한다. 단색 로고·아이콘용이다. **명암 유지 색 입히기:** 기존 Colorize와 연결하여 밝고 어두운 구조를 살린다. 이 모드는 모든 픽셀이 입력 HEX와 같아지는 기능이 아님을 명시한다. 두 모드는 선택 가능한 대안이며 기본적으로 겹쳐 적용하지 않는다.
- **PNG:** 전체 개체 또는 사용자가 찍은 원래 색의 범위를 대상으로 한다. 특정 색 교체에는 허용 오차와 대상 미리보기를 제공하고 다른 색은 보존한다. 투명 배경·반투명 테두리·안티앨리어싱을 유지하고 색 테두리 번짐을 검사한다. 불투명한 흰 배경을 자동으로 배경 제거하지 않으며, 전체 적용 시 함께 바뀌는 부분을 미리 보여준다.
- **SVG:** 전체 개체 / 원래 색상별 교체와 **채움만 / 선만 / 둘 다**를 구분한다. 지원하는 단색 채움·선은 벡터 상태로 색상만 바꾸며, `none`, 불투명도, 클리핑과 마스크는 보존한다. 상속·스타일·`currentColor`를 해석한 실제 적용 대상을 기준으로 처리하고 문자열 일괄 치환으로 구현하지 않는다. [SVG 채움·선 규칙](https://www.w3.org/TR/SVG2/painting.html)
- SVG의 그라데이션·패턴·필터·내장 래스터는 단색 속성 교체와 별도로 취급한다. 미지원 대상과 남는 색을 표시하며 단색으로 몰래 평탄화하거나 래스터화하지 않는다. 그라데이션 색상점 교체 등은 검증 후 지원 범위를 넓히고, 미지원 상태에서 ‘전체 색상 일치’로 완료 표시하지 않는다.
- 여러 PNG·SVG 개체를 선택해 같은 코드를 적용할 수 있다. 원본 파일과 같은 자산의 다른 배치 인스턴스는 유지하며, 각 인스턴스의 보정값·색상 매핑으로 저장한다. 원본 비교·초기화·스타일 재사용·실행 취소를 기존 보정 체계에 통합하고 다른 효과와의 적용 순서를 명시한다.
- GPU 미리보기와 CPU 대체 경로, PDF·PNG 출력에 같은 색상 변환 정의를 사용한다. 지정 색의 수치 일치는 sRGB의 완전 불투명한 단색 영역에서 검증한다. 반투명 합성·명암 유지·다른 ICC 공간이나 CMYK 출력에서 화면 픽셀 또는 인쇄 색까지 HEX와 같다고 보장하지 않는다. 색상 맞추기 요청만으로 별도의 SVG 파일 내보내기 기능을 추가하지 않는다.

### 6.2 마스터 페이지·템플릿과 공통 요소

- **마스터 페이지:** 여러 페이지가 참조하는 공통 배경·머리말·꼬리말·로고·페이지 번호·프레임·여백·안내선·단 구성이다. 단순 복사본이 아니라 마스터 수정이 적용 페이지에 전파된다.
- 여러 이름의 마스터, 왼쪽/오른쪽 맞쪽 구성, 기반 마스터 상속, 선택한 페이지 범위에 적용을 지원한다. 상속 순환을 막고, 최종 적용 출처를 표시한다.
- 페이지별 예외는 어떤 속성을 바꿨는지 기록한다. 잠금/재정의/예외 초기화/마스터 연결 해제를 구분하고, 공통 요소 변경이 본문·예외 서식을 덮어쓰지 않게 한다. 삭제·재적용 시 대체 마스터와 유지할 요소를 미리 확인한다.
- 페이지 번호·총 페이지 수·문서 제목 등의 반복 필드를 지원한다. 페이지 삽입·삭제·재정렬과 장/절별 번호 시작값 변경 시 일관되게 갱신한다.
- **템플릿:** 페이지 구성·마스터·스타일·규칙·자산을 담아 새 작업 파일을 만드는 시작 틀이다. 템플릿에서 만든 문서가 원본 템플릿을 자동 수정하거나 원격 변경을 자동 수신하지 않는다. 같은 문서 내 반복 요소 동기화는 마스터가 담당한다.

### 6.3 페이지 전체 규칙과 일관성 검사

- 개체 몇 개를 정렬하는 명령을 넘어, 문서/마스터/페이지 범위에 여백·단·기준선 격자·필수 스타일·정렬 기준·간격·반복 요소 위치 규칙을 지정한다. 페이지 범위와 허용 예외를 명시한다.
- 규칙은 **검사만 / 선택 영역에 적용 / 적용 범위에서 준수 강제**로 구분한다. 기본은 검사이며, 사용자가 강제 모드를 선택한 범위에서는 위반 편집을 막거나 적용 전 해결 방법을 제시한다. 잠금 개체·상충 규칙을 몰래 이동·삭제해서 해결하지 않는다.
- 우선순위는 문서 기본 → 기반/현재 마스터 → 허용한 페이지·개체 예외로 정한다. 예외 허용 여부도 규칙에 포함한다. 모순·순환 제약은 위치를 짚어 안내하고 자동 진동/반복 배치를 막는다.
- 규칙·캔버스·여백 변경 시 영향을 받는 페이지·개체와 텍스트 넘침을 미리 보여준다. 위치 조정·줄바꿈 변화는 사용자가 적용을 확정할 때 실행하고 전체를 한 번의 실행 취소로 묶는다.
- 문서 점검 패널에 위반 페이지·개체·원인·해결 방법을 표시하고 바로 이동한다. 사전 점검에는 도련 부족, 저해상도 이미지, 누락 자산·글꼴, 넘침, 승인되지 않은 스타일 예외도 통합한다.
- 규칙 위반이어도 **작업 파일 저장·복구는 허용**한다. 출력은 사용자가 선택한 검사 프로필에 따라 경고/차단하며, PDF/X 필수 오류는 우회한 파일을 규격 준수로 표시하지 않는다. 여백 침범 경고와 재단 바깥으로 의도적으로 연장한 도련 개체를 구분한다.

### 6.4 반복 배치와 재사용

- 행·열 개수와 간격을 입력하는 배열 복제, 여러 그림의 그리드 배치.
- A/B/C 또는 1/2/3 패널 라벨의 시작값·순서·위치·스타일 지정. 자동 갱신 여부는 사용자가 선택한다.
- 선택 개체·그룹·영역의 PDF·PNG/JPEG 내보내기. PDF 출력의 색상·재단·글자 처리 규칙은 7절을 공통 사용하고, 이미지 출력은 해상도와 색상 프로필을 명시한다.

재단선·도련과 색상 관리는 더 이상 별도 보류 항목이 아니라 4.9·7절의 개발 범위다. 여러 쪽 모아 찍기와 책자 접지 순서 배치만 후속 과제로 남긴다.

## 7. 저장·재편집 설계안

### 작업 파일과 결과물을 구분

- **일반 PDF 편집:** 현재의 Ctrl+S·다른 이름으로 저장을 유지한다. 기존 파일을 동의 없이 조판 프로젝트로 전환하지 않는다.
- **조판 문서:** 새 전용 작업 형식 `*.spdf-layout`을 제안한다. 확장자·형식은 구현 전 확정한다. Ctrl+S는 편집 가능한 작업 파일을 저장하고, 별도의 **PDF로 내보내기**가 배포 결과물을 만든다.
- 작업 파일은 버려도 되는 임시 중간파일이 아니라 **재편집용 원본**이다. PDF 출력 방식과 관계없이 원래 문자열·서식·개체 구조를 유지한다. 자동 복구용 임시파일과도 구분한다.
- 결과 PDF는 다른 PDF 뷰어에서 열 수 있어야 한다. 그러나 결과 PDF만 다시 열어서 그룹·스타일·편집 이력까지 복원하는 것은 첫 버전에서 보장하지 않는다.
- 기존 PDF를 조판 재료로 사용할 때는 원본을 유지한 파생 작업 문서를 만든다. 기존 PDF 수정 기능과 새 배치 작업의 저장 대상을 UI에서 구분한다.

### PDF 안의 휴대용 편집 정보

- PDF catalog의 표준 `PieceInfo` 아래 `/sPDF` application data dictionary를 두고, `/Private` stream에 스키마 버전이 있는 작은 편집 모델을 선택 저장할 수 있다. 문서 전체 또는 필요한 page/Form XObject 단위로 연결한다.
- 개체 ID·그룹·스타일 참조·프레임 연결·안내선·원본 문자열·출력 설정을 우선 대상으로 삼고, 데이터의 `LastModified`·내용 checksum·sPDF 스키마 버전을 기록한다. 다른 응용 프로그램의 `PieceInfo` 항목은 보존한다.
- 일반 PDF 뷰어는 private data 없이도 같은 PDF를 열고 인쇄할 수 있어야 한다. 읽기나 출력에 이를 필수로 만들지 않는다.
- 다른 프로그램의 최적화·재저장이 private data를 제거하거나 PDF 내용만 바꿀 수 있으므로, 불일치하면 조용히 적용하지 않고 경고한다. 완전한 원본·큰 자산·복구 이력은 `*.spdf-layout`에 유지한다.
- 암호·전자서명 PDF, 압축 폭탄, 과도한 stream 크기와 잘못된 참조를 제한한다. PDF에 private data를 추가하는 저장은 기존 전자서명을 변경할 수 있음을 먼저 알린다.

### 작업 파일에 포함할 정보

- 형식 버전, 안정적인 페이지·개체 ID, 페이지별 캔버스·TrimBox·도련·slug·여백과 문서 기본값, 위치·변형·겹침 순서, 그룹·잠금, 안내선·문서/기준선 격자.
- 원래 유니코드 문자열, 스토리와 프레임 연결 순서, 문자 구간별 서식·kerning/tracking·문단 설정·격자 적용·넘침 상태. 윤곽선 PDF를 내보낸 뒤 저장해도 이 정보를 경로 데이터로 대체하지 않는다.
- 문단·문자·개체 스타일의 ID·상속·예외, 마스터 계층·페이지별 재정의·반복 필드, 문서 규칙·허용 예외·출력 검사 프로필. 참조 무결성과 형식 업그레이드를 검증한다.
- 원본 또는 명시적으로 선택한 기준 PDF 사본과 사용한 그림·PDF·SVG 자산. 기본은 자산 포함으로 제안해 파일 이동 후 경로 단절을 줄인다.
- 원본 색상 공간·ICC 프로필 참조, 출력 대상 프로필·변환 정책·PDF/X 프리셋·재단표시 설정. 인쇄용 변환 결과로 작업 원본 색상·자산을 덮어쓰지 않는다.
- 개체별 색조·채도·단색화의 활성 상태·보정값·대상 범위·적용 순서·작업 색상 공간과 계산 방식 버전. 원본 자산과 스타일 색은 별도로 유지하고, 효과를 끄거나 초기화하면 원래 표시로 복원한다.
- PNG·SVG 색상 맞추기의 목표 HEX·sRGB 해석, 지정 색/명암 유지 모드, 원래 색→목표 색 매핑·허용 오차, SVG 채움/선 대상과 미지원 범위. 개체 인스턴스별로 저장하고 원본 자산은 수정하지 않는다.
- 글꼴 이름·특성·대체 기록. 글꼴 파일의 포함 여부는 사용 허용 범위를 확인하고, 무조건 수집·재배포하지 않는다.
- 하나의 컨테이너 안에 모델과 자산을 묶되 원본 자산은 중복 저장을 줄인다. 컨테이너는 원자적으로 교체한다.

암호 PDF를 평문 프로젝트 자산으로 몰래 복사하지 않는다. 첫 버전은 보호된 소스의 프로젝트 포함을 제한하는 안을 우선 검토하고, 암호 저장 금지·명시적 안내를 적용한다. 외부 작업 파일을 열 때 경로 탈출, 과도한 압축 해제 크기, 악성 외부 참조를 제한한다.

### PDF 출력 시 글자 처리 선택

여기서 outline은 **글자 윤곽선(벡터 경로)**이다. 기존 TXT → PDF 책갈피(outline) 가져오기와 다른 기능이므로 UI에는 ‘outline’만 단독으로 쓰지 않는다.

| 저장·출력 종류 | 남기는 정보 | 용도 |
| --- | --- | --- |
| 작업 파일 저장 | 원래 글·서식·개체·그룹·캔버스·여백·자산 | 다음 작업에서 계속 수정할 원본 |
| PDF — 텍스트 유지 (기본) | 글자를 PDF 텍스트로 유지, 허용되는 글꼴 포함 | 일반 배포, 글자 선택·검색·복사 |
| PDF — 글자를 윤곽선으로 변환 | 글자 모양을 벡터 경로로 출력 | 글꼴 의존성을 줄인 고정 모양 결과물 |

- **텍스트 유지:** 글꼴 포함 가능 여부와 누락 글꼴을 사전 점검하고 임의 대체하지 않는다. 선택·검색·복사 결과도 확인한다. 텍스트가 남는다는 것이 원래 텍스트 프레임·문단·그룹이나 Illustrator 전용 편집 정보까지 보존한다는 뜻은 아니다.
- **윤곽선 출력:** 작업 문서가 아닌 출력용 사본에서만 변환한다. 그림으로 찍어내는 래스터화와 구분하고, 원래 글을 수정하려면 작업 파일을 다시 연다. 글자를 경로로 바꾸면 문자 속성을 잃어 텍스트 도구로 수정할 수 없다는 점은 [Adobe 공식 설명](https://helpx.adobe.com/illustrator/web/add-and-edit-artwork/create-text/create-outline-text.html)과 같다.
- 윤곽선으로 바뀐 글자는 일반 텍스트 선택·검색·복사 및 보조기기의 읽기에 제약이 생긴다는 경고를 출력 창에 표시한다. 검색 기능을 남기려고 숨은 원문/OCR 텍스트를 몰래 덧붙이지 않는다. 변환하지 않은 원본 PDF의 OCR 레이어를 일반 저장 경로에서 없애지도 않는다.
- 대상은 최종 PDF에 포함되는 글자 전체를 목표로 한다. 다만 **sPDF에서 작성한 글자**와 **가져온 PDF·PDF 호환 AI·SVG 내부 글자**의 변환 경로를 따로 검증한다. 내부 글자·숨은 텍스트·지원하지 않는 글꼴이 남는 경우 ‘전체 윤곽선 변환 완료’로 표시하지 않는다. 해당 출력은 중단하고 원인과 텍스트 유지 출력 대안을 안내한다. 부분 변환을 제공하게 되면 대상 범위를 명시한 별도 옵션으로 구분한다.
- 글꼴이 없거나 변환이 허용되지 않는 경우 윤곽선 변환이 해결책이라고 가정하지 않는다. 잘못된 대체 글꼴로 모양을 확정하거나 조용히 이미지로 바꾸지 않는다. 전체 윤곽선 출력이 안전한 문서 범위는 0단계 실험 후 확정한다.

### 저장 UI와 원본 보호

- 조판 문서의 **저장 / 다른 이름으로 저장**은 작업 파일을, **PDF로 내보내기**는 결과 PDF를 다룬다. 일반 PDF 문서의 기존 저장 방식은 바꾸지 않는다.
- 내보내기 창 안에 **글자 처리: 텍스트 유지 / 글자를 윤곽선으로 변환**을 둔다. 새 문서의 기본값은 텍스트 유지이며, 문서별 마지막 출력 설정을 기억하더라도 실행 전에 현재 선택과 경고를 보여준다.
- 기본 출력 이름은 `문서.pdf`와 `문서_outlined.pdf`처럼 구분한다. 작업 파일·입력 자산과 같은 경로로 출력하지 못하게 하고, 기존 결과 PDF 교체는 확인을 받는다.
- 미저장 작업은 먼저 작업 파일 저장을 권한다. 사용자가 출력만 선택하더라도 ‘작업 원본은 아직 저장되지 않음’을 유지하며, PDF 출력 성공을 프로젝트 저장 완료로 처리하지 않는다.
- 작업 파일과 PDF 모두 임시 새 파일에 쓴 뒤 검증에 성공했을 때만 대상 파일을 교체한다. 출력 실패·취소 시 기존 파일과 편집 상태를 유지한다.

### 4차 기능: CMYK·PDF/X 인쇄용 내보내기

- **일반 PDF / ICC 기반 CMYK PDF / PDF/X**를 구분한 출력 프리셋으로 제공한다. 화면용 기본 출력이나 작업 파일을 CMYK로 강제하지 않는다. 색상 모드 변경만으로 PDF/X 준수라고 표시하지 않는다.
- 출력 대상 ICC 프로필과 렌더링 의도, 원본 프로필이 없는 자산의 처리 방침을 선택한다. 프로필 없는 RGB/CMYK를 조용히 특정 인쇄 조건으로 간주하지 않는다. 기존 CMYK 수치 보존, 검정 글자 정책, 투명도·오버프린트·총 잉크량은 지원 범위와 검증 결과를 명시한다.
- PDF/X는 우선 **PDF/X-4를 검증 후보**로 삼는다. 색 관리된 RGB를 허용하는 경로와 ‘CMYK로 변환’ 옵션을 구분한다. PDF/X-1a는 별도 수요와 투명도 병합·색상 변환 검증 후 확장한다. 모든 PDF/X 규격을 한 번에 지원한다고 약속하지 않는다. [PDF Association의 규격별 기술 요건](https://pdfa.org/technical-side-and-requirements-of-pdfx/)을 검증 범위의 참고로 삼는다.
- 선택한 규격에 맞는 OutputIntent·ICC, 글꼴 포함, 페이지 박스·도련, 색상·투명도·금지 요소를 검사한다. 가져온 PDF·SVG의 내부 자원도 검사 대상이며, 미지원 별색·프로필·효과는 명시적으로 중단하거나 별도 일반 PDF 출력을 제안한다.
- 임시 결과 PDF를 **해당 PDF/X 규격을 검사할 수 있는 독립 검증기**로 확인한 뒤 성공으로 처리한다. 검증 도구·프로필·결과를 기록하고, 실패 시 기존 출력 파일을 보존한다. 메타데이터 태그만 넣거나 뷰어에서 열리는 것으로 적합성을 판정하지 않는다. 검증기와 색상 엔진의 선택·라이선스·배포 크기는 0단계에서 확인한다.
- 색상·윤곽선 변환은 출력 사본에서만 수행한다. GPU 화면 표시가 출력 색상 검증을 대신하지 않으며, 소프트 프루프와 실제 인쇄 결과도 동일하다고 보장하지 않는다.

색상 변환과 OutputIntent가 별개 설정이라는 점은 [Adobe PDF 출력 옵션](https://helpx.adobe.com/indesign/using/pdf-options.html)을 참고한다. 이 문서는 sPDF의 구현 목표이며, 특정 규격 적합성과 인쇄소 수용 여부는 대상 프로필·검증 샘플을 정한 뒤 판단한다.

### Physical Size / Actual Size Calibration (후속 계획)

**상태: 미구현·후순위.** 현재 GPU/rendering 작업의 범위나 우선순위를 바꾸지 않는다. GPU 렌더링 기반이 안정화된 뒤 DTP / Print Preview 확장으로 검토하며, 조판 첫 배포의 필수 조건으로 추가하거나 버전·일정을 예약하지 않는다.

#### 목표와 크기의 의미

- `View → Actual Size`에서 PDF의 물리적 크기와 화면 실측 크기를 최대한 일치시킨다. A4의 해당 페이지 박스가 210 × 297 mm이면 실제 자로 잰 표시 크기도 이를 목표로 한다. 화면에 한 장이 들어가지 않으면 스크롤하며, 자동 쪽맞춤으로 줄이지 않는다.
- 일반적인 Windows DPI scaling은 UI 가독성을 위한 배율이고, 이 기능은 물리 치수 표시용이다. **논리 DPI만으로 실제 PPI를 단정하지 않으며 `100% zoom = Actual Size`로 취급하지 않는다.**
- Actual Size를 독립적인 보기 모드로 유지한다. 일반 zoom·폭맞춤·쪽맞춤을 선택하면 해당 모드로 전환하며, 일반 zoom 상태에서는 모니터 이동 때문에 사용자 배율을 임의 변경하지 않는다.
- 물리 표시 배율만 바꾼다. PDF 좌표·페이지 박스·개체 크기·저장 결과·프린터 출력 배율·실행 취소 이력은 변경하지 않는다. 회전·CropBox·TrimBox·PDF UserUnit을 해석한 문서 치수와 기존 좌표 변환을 사용한다.

#### 모니터별 자동 감지 우선

- Windows의 현재 디스플레이 구성에서 모니터별 활성 해상도, 방향, DPI scaling과 가능한 EDID 기반 physical size를 조회하는 경로를 설계한다. 구체적인 API와 신뢰도 판정은 구현 단계에서 검증한다.
- 물리 폭·높이와 대응하는 실제 표시 픽셀 수를 이용해 축별 PPI를 산출한다. 회전된 모니터의 축 교환, 해상도/출력 신호 차이, 비기본 해상도·디스플레이 확대 방식도 검사한다. DPI scaling은 물리 픽셀과 Qt/Direct2D 논리 좌표 사이의 변환에 사용하고 이중 적용하지 않는다.
- EDID가 없거나 0·비현실적인 크기·불일치 정보를 반환하면 자동값을 정확한 값으로 표시하지 않는다. 원격/가상 디스플레이·복제 화면 등 물리 크기를 확정하기 어려운 경우도 `감지 불가 / 보정 필요`와 추정 상태를 구분한다.
- Custom 프로필이 없는 모니터는 유효한 자동값을 우선 사용한다. 사용자가 직접 보정한 모니터에서는 Custom이 자동값보다 우선하며, 감지값은 비교·초기화를 위해 별도로 유지한다.

#### 창 이동과 프로필 수명

- 창 클라이언트 영역과 **가장 큰 면적으로 겹치는 모니터**를 선택한다. 면적이 같으면 직전 모니터를 유지하고, 초기 선택의 동률은 창 중심이 있는 모니터로 해소한다. 모니터를 찾지 못하면 안전한 추정 표시와 보정 안내를 제공한다.
- 여러 모니터에 걸친 창에는 선택된 한 모니터의 배율을 적용한다. PPI가 다른 두 화면에서 동시에 실측 크기를 맞출 수 있다고 보장하지 않으며 현재 기준 모니터를 표시한다.
- Actual Size 모드에서는 창의 기준 모니터가 바뀔 때 해당 프로필을 자동 적용한다. 짧은 이동 이벤트는 묶어 처리하고 보기 중심·선택·편집 상태를 유지해 경계에서 배율이 불필요하게 진동하지 않게 한다.
- hot-plug, 해상도·모니터 방향·DPI scaling 변경 시 감지값과 좌표 변환을 재평가한다. 반복적인 프레임 렌더마다 하드웨어 정보를 조회하지 않는다.
- 프로필은 세션 한정 모니터 핸들·화면 번호만이 아닌 **안정적인 monitor identifier**를 키로 저장한다. 식별자 구성과 동일 모델·일련번호 누락·도킹 포트 변경 시의 구분은 구현 시 검증한다. 모호한 일치에는 다른 모니터의 Custom을 조용히 적용하지 않는다.
- 저장 항목: 스키마 버전, 모니터 식별 정보, Auto/Custom, 감지 PPI·신뢰도, 보정된 물리 크기/기준 픽셀 밀도, 보정 당시 해상도·방향·배율과 보정 시점. 일회성 zoom 값만 저장하지 않는다. 모드 변경 후 재사용 가능 여부를 판단하고 검증할 수 없는 Custom은 보존하되 재보정을 안내한다.
- 모니터가 분리돼도 프로필을 삭제하지 않아 재연결·재시작 시 재사용한다. PC별 디스플레이 설정으로 관리하며 PDF나 조판 작업 파일에 포함하지 않는다. 리더·편집 프로세스는 공통 프로필 형식만 사용하고 GPU 컨텍스트·실행 상태를 공유하지 않는다.

#### 수동 calibration fallback과 UI

- 모니터 인치 수나 사용자의 PPI 계산을 기본 입력으로 요구하지 않는다. 화면의 **100 mm 보정 막대**에 실제 자를 대고 `- / +` 또는 슬라이더로 길이를 맞추는 방식을 우선한다.
- 수평 보정 후 수직 막대로도 확인할 수 있게 하여 축별 크기·화면 회전 문제를 검사한다. 저장/취소를 구분하고 취소는 기존 프로필을 유지한다.
- 설정의 `Display / Physical Size`에 현재 모니터, Detected PPI, 감지 신뢰도, Calibration Auto/Custom, 적용 중인 보정값을 표시한다. 아래 UI의 `100%`는 **감지 기준에 대한 보정 비율**이며 일반 문서 zoom과 구분해서 표기한다.

```text
View
  Actual Size

Settings → Display / Physical Size
  Monitor: [현재 모니터]
  Detected PPI: [감지값 또는 감지 불가]
  Calibration: Auto / Custom
  <-------------- 100 mm -------------->
             실제 자로 길이를 맞추세요
           [-] [보정 비율 100%] [+]
  [슬라이더]  [수직 크기 확인]
  [Reset to detected value] [저장] [취소]
```

- 초기화는 현재 모니터의 Custom만 제거하고 Auto로 복귀한다. 감지값이 없다면 정확한 Actual Size가 설정됐다고 표시하지 않는다. 다른 모니터의 프로필은 바꾸지 않는다.

#### Print Preview·품질 검사 연계와 완료 기준

- DTP 보기와 Print Preview가 같은 물리 치수→화면 변환을 사용한다. 미리보기에서는 용지·TrimBox·BleedBox와 인쇄 배율을 구분하고, 모니터 보정이 인쇄 명령의 배율을 바꾸지 않도록 한다.
- effective image PPI는 이미지 픽셀 수와 문서에 배치한 물리 크기로 계산한다. 모니터 PPI/zoom과 혼동하지 않으며, preflight의 저해상도 경고·bleed/trim 표시가 공통 문서 단위를 사용하도록 연결한다. 화면 실측 일치가 프린터 정확도·색상·PDF/X 적합성을 보증하지 않는다.
- [ ] 자로 수평·수직 100 mm 막대를 확인하고 A4의 210 × 297 mm를 검증한다. 화면에 안 들어가는 경우에도 스크롤만 바뀌고 축척은 유지된다. 측정 오차 목표와 허용 범위는 기준 장비·사용자 보정 실험에서 정한다.
- [ ] 서로 다른 PPI와 Windows 배율의 두 모니터에서 한 번씩 보정한 뒤 창 이동·재시작·분리/재연결 때 각 프로필이 독립적으로 복원된다.
- [ ] 걸친 창의 모니터 선택, 동일 모델 식별, 해상도·방향·DPI scaling 변경, EDID 누락/오류, 원격/가상 화면에서 잘못된 정확도 보증이나 다른 모니터 프로필의 자동 오적용이 없다.
- [ ] GPU/CPU 표시 경로에서 같은 물리 치수·포인터·선택 좌표를 유지하고, 일반 zoom·기존 인쇄·문서 저장·undo/redo가 영향을 받지 않는다.

## 8. 구현 구조와 주요 기술 검증

새 코드는 `app.py`에 몰아넣지 않고 기존 창 조립·문서 처리 구조에 연결한다. 아래 모듈명은 제안이며 아직 생성하지 않는다.

프로세스 경계는 제1원칙을 따른다. 아래 조판 모듈은 편집 프로세스에 속하며 리더의 시작·응답·종료에 의존성을 추가하지 않는다. 현재 같은 프로세스의 문서 핸들을 닫고 다시 여는 저장 연동은 그대로 재사용하지 않고, 실패 복구와 시간 제한이 있는 프로세스 간 저장·갱신 절차로 설계한다.

- `layout_model`: Qt와 독립적인 페이지 박스·개체·그룹·스토리/프레임·스타일·마스터·규칙 데이터. 화면용 사본과 원본 모델을 분리한다.
- `layout_commands`: 추가·이동·크기·정렬·삭제·그룹·캔버스 치수·여백의 재생 가능한 연산. 드래그 전체를 실행 취소 한 번으로 묶고, Esc 취소 시 연산을 남기지 않는다.
- `layout_canvas` / `layout_inspector`: 선택·핸들·스냅과 속성 패널. 텍스트 선택과 개체 선택을 분리한다.
- `layout_store` / `layout_export`: 작업 파일 저장과 PDF 출력을 분리한다. 출력 실패가 편집 상태를 지우거나 원본을 교체하지 않아야 한다. 선택형 PDF `PieceInfo` 사본은 별도 adapter로 다루고 작업 파일의 기준 모델로 사용하지 않는다.
- 스타일·마스터 참조와 규칙 해석, 텍스트 조판, 자산 가져오기, 색상 변환·출력 검증은 별도 책임으로 나눈다. 특정 PDF/렌더링 엔진이나 선택형 private data만을 작업 파일의 유일한 저장소로 삼지 않는다.

### 먼저 검증할 네 가지

1. **좌표:** 페이지 회전·CropBox·배율·화면 배율을 통합 변환하고 UI와 출력에 같은 수치를 쓴다.
2. **문자:** 글꼴 측정·줄바꿈·자간 결과가 화면과 PDF에서 맞아야 한다. 한 렌더링 결과를 미리보기와 출력에 공통 사용하고, 입력 중 임시 미리보기와 확정 결과의 차이를 검증한다. 텍스트 유지·윤곽선 출력 모두 한글·합자·기호·회전·변형·채움·선의 모양과 위치를 비교한다. 기존 PDF 내부 글자의 윤곽선 변환은 별도 검증하며, 현재 API 후보만으로 구현이 확정됐다고 보지 않는다.
3. **실행 취소:** 현재 PDF 스냅샷 체계와 조판 연산 기록을 문서 종류에 맞게 연결한다. 같은 작업 공간에서 서로 모르는 두 Ctrl+Z 스택을 만들지 않는다. 페이지 순서 변경 시 개체는 페이지 ID를 따라가야 한다.
4. **저장 왕복:** 저장 후 다시 열어 모든 개체의 좌표·그룹·스타일·그림 자르기·텍스트 연결·마스터 예외·규칙·출력 프로필이 유지돼야 한다. 복구 사본과 미저장 탭 이동도 조판 모델·자산을 함께 다룬다.

영역 모델·SVG 벡터 출력·문자 엔진·ICC 변환·PDF/X 검증의 작은 실험을 0단계에서 먼저 수행한다. 고난도 항목이 검증되지 않으면 해당 단계의 배포 조건으로 남기며, 확인되지 않은 엔진 기능을 UI 옵션만 만들어 완료 처리하지 않는다.

### PDF·텍스트 처리 후보의 근거

현재 개발 환경의 PyMuPDF는 1.28.2이며 `show_pdf_page()`와 `insert_htmlbox()` API가 존재한다. 존재 여부만 확인했으며 조판 품질 검증이 끝났다는 뜻은 아니다.

- `show_pdf_page()`는 다른 PDF 페이지를 이미지화하지 않고 배치할 수 있어 PDF 그림 배치 후보로 삼는다. 단, 주석·폼·링크를 자동 복사하지 않고 잘라 보이지 않는 자원도 남을 수 있다. 따라서 자르기를 개인정보 제거 기능으로 안내하지 않으며, 필요한 주석 보존·지원 불가 안내를 검증 항목으로 둔다. 일반 PDF 저장 경로를 이 API만으로 대체하지 않는다. [공식 문서](https://pymupdf.readthedocs.io/en/latest/page.html#Page.show_pdf_page)
- `insert_htmlbox()` / Story는 서식 있는 텍스트 배치 후보로 검토한다. 자동 축소를 허용하지 않는 설정과 넘침 결과를 활용하되, 필요한 한글 조판·정밀 자간을 충족하는지는 별도 실험한다. [공식 문서](https://pymupdf.readthedocs.io/en/latest/page.html#Page.insert_htmlbox)

### 성능 원칙

- 드래그 중 PDF 전체를 다시 저장·렌더링하지 않고 선택 개체의 미리보기 변형을 우선 표시한다. 확정 후 영향을 받는 부분을 갱신한다.
- 활성 페이지와 주변 미리보기만 유지한다. 큰 이미지의 원본·썸네일·화면용 사본이 무제한 중복되지 않게 캐시 상한을 둔다.
- 스타일·마스터 수정은 의존하는 개체만 갱신하고, 텍스트는 변경 위치부터 줄 배치가 안정화될 때까지 재계산한다. 여러 페이지에 흐르는 원문 계산과 모든 페이지의 선행 이미지 렌더링을 구분한다. 긴 계산은 취소 가능하게 하고 숨김·닫기 뒤 GPU/RAM 자원을 회수한다.
- 기능을 쓰지 않는 읽기 창에 조판 편집 의존성이나 글꼴 전체 분석을 미리 올리지 않는다.
- 많은 개체가 있는 페이지에서 드래그 지연·메모리·탭 닫기 시간을 측정한다. 숫자 목표와 지원 규모는 0단계 기준 장비·샘플을 정한 뒤 기록한다.
- 읽기·편집 창 모두 공통 GPU 렌더링 경로를 목표로 한다. 현재 CPU 래스터화+GPU 이미지 합성과 PDF 벡터·글자 자체의 GPU 렌더링을 구분하고, 후자는 별도 엔진 검증 단계로 관리한다. 파싱·문자 배치·저장은 필요한 CPU 작업을 유지하며 GPU 미지원 환경의 대체 경로와 RAM/VRAM 상한을 둔다.

### 대표 작업의 완료 기준

- [x] 리더와 편집기의 프로세스 ID가 다르고, 어느 시작 모드를 선택해도 두 모드가 같은 프로세스로 합쳐지지 않는다.
- [x] 편집기를 강제 종료하거나 충돌·무응답을 유발해도 리더에서 쪽 이동·확대·검색·인쇄가 가능하며, 편집기를 다시 열 수 있다.
- [x] 모드 인계는 대상 열기 성공 뒤 원래 탭을 닫고, 실패·시간 초과에는 원래 창을 유지한다. 저장 전·교체 전후 중단에도 마지막 정상 완성본과 미저장 복구 사본을 보존한다.
- [x] 편집 프로세스가 종료되면 그쪽 자원을 회수하며, 리더가 편집기의 조판 모듈이나 GPU 컨텍스트를 소유하지 않는다.
- [ ] 리더·편집기 양쪽에서 실제 GPU 렌더링 경로를 확인하고, 동일 문서·장비의 기존 경로와 확대·이동·개체 변형 지연을 비교한다. CPU 래스터 이미지 합성만으로 완료 판정하지 않는다.
- [ ] 최대 800% 확대에서 글꼴·투명도·클리핑 품질을 유지하고, GPU 미지원 시 CPU 대체 경로에서도 개체 상태·실행 취소·저장 결과가 유지된다.
- [ ] A4에서 사용자 지정 크기와 가로 방향으로 바꿔도 기본 모드에서는 글자·그림 크기가 유지되고 선택한 기준점에 맞게 배치된다.
- [ ] 내용 함께 맞춤은 명시적으로 선택했을 때만 적용되며, 미리보기와 PDF 출력의 배율·위치가 일치한다.
- [ ] 캔버스 축소 시 바깥 개체를 경고하고 작업 파일에는 보존한다. 실행 취소로 크기·배치·여백을 복구할 수 있다.
- [ ] 상하좌우 여백을 다르게 설정하고 여백 기준 정렬·스냅을 사용한다. 여백 변경만으로 개체가 움직이지 않고 안내선이 출력되지 않는다.
- [ ] 크기가 다른 여러 페이지에 여백을 일괄 적용할 때 잘못된 값은 적용 전에 알리고, 설정 저장·재개방 후 페이지별 값이 유지된다.
- [ ] 빈 A4 페이지에 그림 6개를 놓고 폭 55 mm, 가장자리 간격 4 mm로 3열 배치한다.
- [ ] 제목과 A–F 라벨, 설명을 추가하고 각 그림과 그룹으로 묶어 함께 이동한다. 첫 배포의 라벨은 일반 텍스트로 작성해도 된다.
- [ ] 그림 하나를 교체해도 프레임 크기·위치가 유지된다.
- [ ] 마우스 드래그·수치 입력·정렬 결과가 같은 좌표로 저장되며 반복 변형 후 값이 누적해서 틀어지지 않는다.
- [ ] 움직임 하나를 실행 취소·다시 실행하고, 페이지 순서 변경 후에도 개체가 올바른 페이지를 따라간다.
- [ ] 작업 파일을 닫고 다시 열어 그룹·서식·자르기를 계속 편집한다.
- [ ] 안내선·문서 격자의 표시/스냅/잠금이 독립적으로 작동하고, 저장 후에도 원점·간격·단 구성이 유지된다.
- [ ] 도련 3 mm와 slug·재단표시를 적용한 테스트 PDF에서 TrimBox는 지정한 최종 크기를 유지한다. MediaBox·BleedBox·CropBox와 표시 위치를 검사하며, 혼합 크기·회전·0 mm 도련도 확인한다. 3 mm는 테스트 값이지 모든 출력의 강제 기본값이 아니다.
- [ ] SVG를 직접 배치·교체·저장·재개방하고, 800% 표시와 PDF 출력에서 지원 벡터 요소가 이미지로 바뀌지 않는다. 악성 외부 참조는 조회하지 않고 미지원 요소는 알린다.
- [ ] 여러 페이지의 연결 프레임에서 원문 수정·중간 프레임 삭제·페이지 재정렬을 해도 원문 유실/중복이 없고, 넘침·흐름·실행 취소가 일치한다.
- [ ] 문단·문자·개체 스타일을 일괄 수정한 뒤 직접 예외 서식을 유지하거나 초기화할 수 있다. 상속·삭제·이름 충돌·저장 왕복을 검증한다.
- [ ] 같은 이미지 자산을 두 개 배치해 한 개체에만 Hue/Saturation/Colorize를 적용하고, 다른 개체·원본 파일·투명도가 유지되는지 확인한다. 보정 끄기·초기화·실행 취소·저장 왕복으로 결과를 복원한다.
- [ ] 회색 이미지의 단색화, 텍스트·도형의 색 보정, 투명 PNG와 중첩 그룹을 검사한다. GPU/CPU 미리보기와 출력의 보정 결과를 비교하고, 지원 벡터·텍스트는 유지하며 미지원 배치 PDF/SVG의 래스터화는 동의 없이 실행하지 않는다.
- [ ] 투명 PNG 로고와 단색 SVG에 같은 `#2563EB`를 지정 색 모드로 적용해 불투명 영역의 sRGB 값이 일치하고, 투명 테두리·SVG 벡터 구조가 유지되는지 검사한다. `#RGB` 입력과 잘못된 코드도 검증한다.
- [ ] 다색 PNG의 특정 색 교체, SVG 채움만/선만 교체가 대상 밖 색·`none`·마스크·다른 인스턴스에 영향을 주지 않는다. 명암 유지 모드와 미지원 그라데이션·패턴 안내를 별도로 검증한다.
- [ ] 여러 개체의 색상 코드 일괄 적용을 한 번에 취소하고, 저장·재개방·초기화로 원본을 복원한다. GPU/CPU 표시와 PDF·PNG 출력은 같은 보정 정의를 따르며, ICC/CMYK 출력의 수치 변화는 구분한다.
- [ ] 서로 다른 크기의 한글·영문과 합자에서 kerning/tracking·baseline grid·줄바꿈의 화면 위치와 PDF 출력이 일치한다.
- [ ] 20페이지에 마스터 머리말·로고·쪽번호를 적용하고 공통 수정이 전파된다. 한 페이지의 허용 예외, 맞쪽 배치와 페이지 재정렬 후 번호도 유지한다.
- [ ] 규칙 검사/적용/강제를 구분하고 위반 위치로 이동한다. 충돌 규칙·잠금 개체·불허 예외는 알리되 작업 파일 저장은 막지 않고, 일괄 적용은 한 번에 취소한다.
- [ ] 텍스트 유지 PDF를 다른 뷰어에서 열어 글자·그림·선의 위치와 모양, 한글·영문 선택·검색·복사를 확인한다.
- [ ] 윤곽선 PDF의 글자 모양·위치를 텍스트 유지 출력과 비교하고, 실제 벡터 경로인지 확인한다. 변환 대상 글자가 일반 텍스트 추출에 남거나 숨은 텍스트로 복제되지 않았는지도 확인한다.
- [ ] 두 출력 방식 모두 작업 파일의 원문·서식·그룹을 바꾸지 않는다. 출력 후 작업 파일을 저장하고 다시 열어 문구를 수정할 수 있다.
- [ ] 가져온 PDF 내부 글자 등 변환 불가능한 대상이 있으면 전체 윤곽선 출력 완료로 처리하지 않고, 기존 결과물을 보존한 채 원인을 안내한다.
- [ ] PDF 출력만으로 미저장 표시가 사라지지 않으며, 취소·실패·기존 출력 교체에서도 작업 원본과 입력 자산이 보존된다.
- [ ] 글꼴 누락·넘침·읽기 전용 폴더·저장 실패·보호된 소스를 조용히 무시하지 않는다.
- [ ] ICC 기반 CMYK 출력과 일반 PDF의 원본 색상 보존을 각각 확인한다. 프로필 누락·미지원 별색·투명도 사례를 검사하고, PDF/X 후보는 독립 검증 결과 없이 성공으로 표시하지 않는다.
- [ ] 텍스트 유지/윤곽선 출력과 CMYK/PDF/X 프리셋을 조합해 검증하며, 실패하면 기존 파일을 보존하고 원본 글·스타일·색상은 바꾸지 않는다.
- [ ] 많은 개체와 고해상도 이미지, 회전·잘린 페이지에서 응답성·메모리를 측정하고 숨긴 탭의 불필요한 작업이 멈추는지 확인한다.
- [ ] 읽기 모드·기존 PDF 편집·수동 OCR·내장 모드가 퇴행하지 않는다.

## 10. 구현 전 확인할 사용자 선택

초안을 막는 질문이 아니라, 실제 개발을 시작할 때 범위를 좁히기 위한 확인 사항이다.

1. 가장 힘든 실제 작업 한 가지: 그림 여러 개 정렬인지, 문단·자간·행간인지, 인쇄용 모아 찍기인지.
2. 대표 결과물 한 장 또는 익명화한 예시: 종이 크기, 가져오는 원본 형식, 자주 쓰는 글꼴, 원하는 출력 방식.
3. 작업 파일의 최종 확장자와 자산 포함 정책. 저장·출력은 7절의 ‘재편집 원본 + 텍스트 유지/윤곽선 PDF’로 구분하는 안을 기준으로 한다.
4. 인쇄 대상의 최종 규격, 도련·slug·재단표시 요구, 출력 ICC와 수용하는 PDF/X 종류. 임의의 인쇄소 조건을 기본값으로 확정하지 않는다.
5. 여러 페이지 샘플의 맞쪽·공통 요소·텍스트 흐름과 반드시 강제할 규칙/허용할 예외. 기능 목록은 본문에 반영했으므로 이 선택들은 구현 검증용이다.

현재 추천 시작점은 **정확한 개체 배치 + 기본 문자 서식 + 재편집 가능한 저장**이다. 실제 불편의 중심이 문자 조판이면 0단계에서 문자 엔진을 먼저 검증하고 1·2단계의 배포 범위를 조정한다.
