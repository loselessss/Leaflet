# 미리보기·썸네일 RGB 전달 개선

2026-11-01. 미배포 1.37.3 유지.

## 변경

기존 열람 미리보기와 사이드바 썸네일은 MuPDF가 그린 RGB 픽셀을 `pix.samples`로
Python `bytes`에 복사한 뒤, `QImage(...).copy()`로 Qt 소유 메모리에 다시 복사했다.
새 경로는 `Document.render(copy_pixels=False)`가 Qt에 의존하지 않는 `RasterBuffer`로
SDK pixmap의 수명을 유지한다. Rust `copy_rgb_rows`가 `samples_mv`와 Qt가 할당한
이미지의 쓰기 가능한 버퍼를 받아 행을 직접 복사한다. 큰 Python 픽셀 `bytes`는
만들지 않으며, MuPDF에서 Qt로 전달하는 전체 픽셀 복사가 두 번에서 한 번이 된다.

RGB 색상·해상도·AA·렌더 엔진·표시 순서는 바꾸지 않는다. Qt는 반환 이미지의
메모리를 직접 소유하므로 문서 종료, SDK pixmap 해제, Qt 이미지의 암묵적 복사와
회전 이후에도 Python 속성이나 외부 포인터 수명에 의존하지 않는다. 일시적인
`RasterBuffer`를 새 캐시에 보관하지 않는다.

Rust는 쓰기 전에 RGB 너비·높이·행 간격·버퍼 크기·연속성·쓰기 가능 여부·메모리
겹침을 검사한다. 크기 연산은 오버플로를 검사하고 각 버퍼는 최대 256MiB로
제한한다. Qt 행 끝의 정렬 패딩은 0으로 채운다. 복사 중 두 버퍼 export와 GIL을
유지하며 SDK 객체나 Qt 이미지를 다른 스레드에서 동시에 다루지 않는다.

기본 `Document.render()`의 `(width, height, stride, bytes)` API와 기존 CPU 타일,
편집·인쇄 호출 경로는 유지한다. Rust 확장이 없는 개발 환경은 같은 빌린 뷰를
즉시 Qt 소유 이미지로 복사하는 경로를 사용한다.

## 비교 방법

`tests/benchmark_raster_handoff.py`로 ACB 2015/2019 각각 다음 세 방식을 순서를
번갈아 새 프로세스 5회씩 비교했다. 미리보기와 썸네일을 합해 총 60개 프로세스다.

- 기존 Python bytes → Qt 복사
- SDK 뷰 → Rust → Qt 소유 이미지
- SDK 뷰 → Qt 자체 복사: 개발용 대체 경로와 비교

미리보기는 실제 reader의 1,000,000픽셀 제한과 배율 상한 0.75를 사용했다.
썸네일은 HiDPI의 일반적인 예인 가로 240 물리 픽셀로 측정했다. 전달만의 시간은
같은 SDK pixmap을 준비한 뒤 워밍업 3회, 측정 40회의 중앙값을 사용하고 다시
프로세스 5회의 중앙값을 구했다. PDF 그리기와 QPixmap 변환은 이 시간에서 제외한다.

Python 임시 할당은 별도 1회 전달을 `tracemalloc`으로 측정했다. **Qt·MuPDF의
네이티브 메모리는 이 값에 포함되지 않는다.** 전체 과정은 별도로 새 display list
생성부터 MuPDF 그리기·Qt 이미지·QPixmap 변환까지 측정하고 프로세스 최대 working
set도 기록했다. 프로세스 시작·문서 열기·GPU 업로드·실제 창 표시는 포함하지 않는다.

## 결과

| 전달만, 중앙값 | 기존 | Rust 직접 복사 | Qt 뷰 복사 |
|---|---:|---:|---:|
| ACB 2015 미리보기 | 1.4215ms | 0.7582ms | 0.7458ms |
| ACB 2019 미리보기 | 1.3986ms | 0.7298ms | 0.7297ms |
| ACB 2015 썸네일 | 0.01555ms | 0.01230ms | 0.01250ms |
| ACB 2019 썸네일 | 0.01605ms | 0.01190ms | 0.01270ms |

| 전달 중 Python 임시 할당 최대값 | 기존 | Rust 직접 복사 |
|---|---:|---:|
| ACB 2015 미리보기 | 3,003,600 bytes | 1,174 bytes |
| ACB 2019 미리보기 | 3,001,918 bytes | 1,280 bytes |
| ACB 2015 썸네일 | 245,996 bytes | 1,195 bytes |
| ACB 2019 썸네일 | 232,367 bytes | 1,299 bytes |

효과의 대부분은 큰 Python bytes 버퍼와 전체 복사 한 번을 없앤 데서 나온다.
Qt의 뷰 복사도 비슷한 속도로 처리한다. 이 결과를 Rust가 Qt보다 크게 빠르다는
근거로 사용하지 않는다.

| 전체 준비, 중앙값 | 기존 | Rust 직접 복사 |
|---|---:|---:|
| ACB 2015 미리보기 | 400.65ms | 352.40ms |
| ACB 2019 미리보기 | 541.51ms | 515.80ms |
| ACB 2015 썸네일 | 295.25ms | 298.82ms |
| ACB 2019 썸네일 | 472.62ms | 482.91ms |

전체 시간은 CPU PDF 그리기가 지배하고 실행 편차가 크다. 전달 단계에서 절약한
약 0.7ms로 위 전체 시간 차이를 설명할 수 없으므로 전체 속도의 유의미한 개선율은
주장하지 않는다. 미리보기 프로세스의 최대 working set도 2015 약 98.9MiB,
2019 약 100.4MiB로 사실상 같았다. 기존 경로가 SDK pixmap을 먼저 해제하고 Qt로
복사하는 동안 새 경로는 SDK pixmap과 Qt 이미지를 함께 유지하므로, Python 임시
할당 감소가 같은 크기의 프로세스 최대 메모리 감소를 뜻하지 않는다.

## 검증

- 실제 ACB 두 문서의 미리보기와 썸네일, QPixmap 전달, 90도 회전에서 기존/새
  RGB 픽셀이 정확히 같다. 변경된 채널 수와 최대 차이는 모두 0이다.
- 홀수 너비, 다른 행 간격, 회전·crop, 비정수 배율, DPR 2를 검사했다.
- Python `Pixmap.samples`를 호출하면 실패하도록 막아 새 경로가 이 복사를
  실행하지 않는지 확인했다.
- 문서 종료 후 전달, SDK 픽셀 변경·해제 후 Qt 이미지 사용, Qt 암묵적 복사,
  오래된/없는 Rust 확장의 대체 경로를 검사했다.
- 짧거나 읽기 전용인 버퍼, 비연속 뷰, 겹치는 버퍼, 잘못된 크기·행 간격과
  오버플로는 대상 버퍼를 변경하지 않고 거절한다. 행 패딩과 뒤쪽 보호 바이트도
  검사했다.

개인 PDF·측정 JSON·빌드 산출물은 소스에 포함하지 않는다. 원시 결과는 로컬
`tmp/rust-audit/rgb-handoff-*.json`에 둔다.
