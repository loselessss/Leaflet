# 병합 도형의 직접 packed 추출

2026-10-31 · 미배포 1.37.3 유지 · 기준 295c1b8

## 범위

기존 Rust 병합기가 최종 Python float/tuple을 만드는 대신 가변 길이 float64
버퍼를 직접 생성한다. worker의 새 추출에 `packed_paths=True`를 적용한다.
큰 병합 도형은 추출→경계 계산→직렬화→복원→GPU 업로드까지 packed 상태를 유지한다.
경계 계산도 Rust가 버퍼를 직접 순회한다. 병합 판단·수치 연산 순서는 기존과 같다.

MuPDF 경로/글자 윤곽 callback과 병합되지 않는 경로는 여전히 Python tuple을
생성한다. 추출 전체를 네이티브로 전환한 것은 아니다. 옵션 없는 직접 호출은 기존
tuple 결과를 유지하고, 확장이 없거나 특수 수치인 경우 기존 경로로 돌아간다.
기존 scene cache 형식과 ABI는 바꾸지 않는다.

## 방법

`python -m tests.benchmark_packed_extraction <PDF...> --output <JSON>`

이전 packed 소비 경로를 두 방식 모두 유지한 상태로 직접 packed 병합만 비교한다.
페이지 1/source scale 1, 매 표본 새 PDF/추출/직렬화/복원/네이티브 장면 생성.
워밍업 1회 뒤 순서를 번갈아 각각 7회, 문서 순서를 바꿔 두 차례 실행했다.
GC와 파일 열기는 타이머 밖이다. 총계는 추출 시작부터 GPU 장면 생성까지이며
파일 입출력·프로세스 시작·장면 비용 계산·디스크 캐시 저장·최종 그리기는 제외한다.

출력 JSON의 `pickle`은 이전 tuple 추출 + packed 전달, `packed`는 직접 packed
추출 + 같은 전달 방식이다. 배열은 추출/인코딩/복원/업로드/총계 순서다.

## 결과

| 실행 | 문서 | 추출→전달→GPU 준비 기존 → 후보 | 변화 |
|---|---|---:|---:|
| 1 | ACB 2015 | 1,348.19 → 1,227.06ms | 9.0% 단축 |
| 2 | ACB 2015 | 1,293.29 → 1,251.60ms | 3.2% 단축 |
| 1 | ACB 2019 | 1,064.40 → 1,071.62ms | 0.7% 증가 |
| 2 | ACB 2019 | 1,081.73 → 1,092.06ms | 1.0% 증가 |

2015는 개선됐지만 편차가 크며 2019는 속도 이득이 없다. 인코딩 중앙값은 2015
약 90→61~63ms, 2019 약 64→58~60ms로 줄었다. 복원/업로드 등 나머지 구간의
변동도 있으므로 인코딩 감소를 전체 속도 개선으로 그대로 환산하지 않는다.

ACB 2015는 packed 병합 56개/명령 97,248개(전체 121,123개), 2019는
52개/84,082개(전체 84,788개)였다. 명령 수는 중복 경로 인스턴스를 포함한다.

worker의 최종 장면을 `_gpu_scene_cost`로 계산한 예산 값:

| 문서 | 이전 객체 장면 | 직접 packed 장면 |
|---|---:|---:|
| ACB 2015 | 28,130,813 bytes | 12,888,757 bytes |
| ACB 2019 | 41,286,812 bytes | 28,047,350 bytes |

이는 공유 객체를 중복 제거한 앱의 메모리 예산 계산값이다. 프로세스 RSS/peak RSS나
VRAM 실측이 아니며, 이미 packed 형식이던 UI 수신 장면의 추가 절감량도 아니다.
worker가 보유하는 최종 Python 좌표 객체가 줄어든 효과를 보여준다.

두 비교 모두 맞춤·100%·800%(1200×900, source scale 1) 픽셀 해시가 일치했다.
직접 병합의 float64 좌표·경계·GPU 배열 일치, 이미지 갱신과 디스크 저장 호환성,
iterator 금지 상태의 경계 계산/업로드 검사를 추가했다.
원본 및 표본은 비공개 `tmp/rust-audit/direct-extraction-results.json`,
`direct-extraction-second.json`에 보관한다.
