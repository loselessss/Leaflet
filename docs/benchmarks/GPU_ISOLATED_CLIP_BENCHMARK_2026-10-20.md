# 격리 그룹·단일 도형 클립 파이프라인 비교 (2026-10-20)

기준은 main에 푸시한 45a828a의 1.37.0 개발 DLL이다. 기존 UNORM8 반올림 보정 셰이더, 화면 밖 명령 묶음 제외와 전체 target 사각형 클립 생략을 포함한다. 이번 변경은 렌더 결과를 저장하지 않고 Normal 격리 그룹과 그 안의 단일 도형 클립을 함께 처리한다.

## 줄이는 작업과 적용 조건

- 기존에는 투명한 격리 그룹 source를 만든 뒤, 자식 클립이 별도 source·coverage mask를 만들고 시작/종료 때 배경을 복사했다. 종료한 클립 결과를 다시 그룹 불투명도로 합성했다.
- 새 경로는 투명 source와 coverage mask 하나씩을 만들고, 자식 명령을 원래 순서로 실행한다. 종료 시 source bitmap brush의 opacity와 FillOpacityMask로 coverage·그룹 불투명도를 적용해 부모에 source-over한다. 적용 가능한 쌍마다 클립 배경 복사 2회→0회, 명시적 Flush 2회→1회다. 시작 Flush는 풀의 mask 입력을 덮어쓰기 전에 유지한다. 실제 전체 실행 횟수나 GPU pass 수를 측정한 주장은 아니다.
- mask는 기존과 같은 안티앨리어싱으로 래스터화한다. FillOpacityMask 호출에만 문서에서 요구하는 aliased 상태를 쓰고 즉시 복원하므로, mask 경계를 계단 모양으로 다시 그리는 방식이 아니다. 근거: [Microsoft bitmap mask 사용법](https://learn.microsoft.com/en-us/windows/win32/direct2d/how-to-clip-with-bitmap-masks).
- 그룹의 유일한 자식이 명시적 geometry clip이고, 그룹 자체가 Normal·격리·비knockout이며 기존 simple layer 경로가 아닌 경우를 정적으로 표시한다. 부모 primitive가 COPY이거나 마스크를 만드는 조상이 있으면 적용하지 않는다. 비격리·다른 혼합·knockout 그룹과 실제 형제 그리기가 있는 그룹도 기존 경로를 쓴다.
- 마스크 생성 중에는 작은 반올림 차이가 비선형 transfer LUT에서 커질 수 있어 통합하지 않는다. 이미 전체 target과 2물리px 여유를 덮는 축 정렬 사각형은 기존의 mask 없는 생략 경로가 더 짧으므로 유지한다.
- ACB 2015의 상위 장면에서 Normal 격리 그룹의 유일한 자식이 ClipPush인 구조는 3,155개다. 이 중 simple 경로·runtime 제외 조건이 있으므로 실제 통합 횟수와 같지 않다. ACB 2019에는 이 구조가 없다.
- 기존 비트맵 풀·예산 안에서 사용하며 통합 capture는 source+mask 2개를 예약한다. 별도 결과 캐시, 타일 크기·출력 밀도·PDF 저장 내용·공개 ABI 변경은 없다. 즉시 그리기 경로는 그대로이고 정밀 worker에 적용한다.

## 비교 조건

- Windows / Intel Iris Xe hardware / PyMuPDF 1.28.2 / 숨김 HWND / 1200×900 물리px / 96 DPI. ACB 2019·2015 첫 페이지의 화면 맞춤·100%·200%를 비교하며 이미지 준비 배율은 1이다.
- 조건마다 준비 3회 + 측정 15회, 기준/후보를 번갈아 실행하고 순서도 교대한다. 두 번째 회차는 DLL 준비 순서도 뒤집는다. 측정 중 다른 GPU 테스트나 빌드를 병행하지 않는다.
- 매 표본 새 장면 identity를 써 페이지·그룹·기존 정밀 타일 결과 재사용을 막는다. immutable geometry·이미지 업로드는 타이머 밖에서 준비한다. 최초 PDF 열기·추출·업로드·확대 이미지 재추출, 입력 안정화 90ms와 Present/vsync는 제외한다.
- 기존 512px 타일과 리더의 완료 확인 간격 30ms를 유지한다. 정밀 요청부터 전체 viewport atlas 준비·가져오기 완료까지다. P95는 15표본의 nearest-rank 값이다.
- 절대시간은 시스템/GPU 부하에 크게 달라진다. 과거의 441ms나 아래 초기 후보 표본과 직접 빼지 않고 같은 회차의 두 DLL을 비교한다. ACB 2019처럼 이 구조가 없는 문서는 제어 비교다.

ACB 2015의 전체 정밀 완료 중앙값 감소율은 화면 맞춤 -6.0~+45.6%, 100% +14.2~+17.0%, 200% +10.9~+25.9%였다. 음수는 느려진 결과다. 화면 맞춤은 회차별 방향이 달라 일관된 개선으로 보지 않는다. ACB 2019도 일관된 가속으로 해석하지 않는다. 특정 구조를 가진 PDF에 대한 결과이며, 모든 문서나 확대 단계에 같은 개선율을 약속하지 않는다.

## 출력·회귀 검사와 한계

- 최종 관련 테스트 99개 통과: gpu_raster 80개, d2d_backend 9개, gpu_composite_integration 10개. 마스크·15 blend mode·반투명 배경·knockout·중첩·정수 반올림 검사를 포함한다.
- 새 검사는 두 경로 모두 같은 정밀 worker·타일 조건으로 비교한다. 기준 장면은 Normal 격리 그룹에 투명 source-over 형제 그리기를 넣어 픽셀을 보존하면서 단일 자식 통합 조건을 해제한다. 즉시 그리기와 worker 사이의 기존 AA 위상 차이를 성능 변경의 오류로 섞지 않는다.
- DPI 2개 × 그룹 불투명도 3개 × 구조 10개 × 변환 4개 = 240개 조건에서 BGRA 최대 채널 차이 3 이하를 확인한다. 회전·반사·shear, COPY 부모, 비격리·knockout·blend 그룹, 실제 형제 개체, 중첩 통합, 마스크 생성과 hard-step LUT, 같은 크기 scratch의 반복 덮어쓰기, 전체 사각형 생략을 포함한다. 일반 opacity mask 합성은 이전 8비트 중간 저장 순서와 작은 반올림 차이가 날 수 있으므로 모든 문서의 완전 일치를 보장하지 않는다.
- C++ /W4 /WX 및 FXC ps_4_0 /Gis 빌드, Python 구문 검사와 git diff --check를 통과했다. 앱·설치 프로그램의 미배포 1.37.0과 공개 ABI 24는 유지한다.
- GPU timestamp·VRAM 최고 사용량은 측정하지 않았다. 원자료의 메모리는 두 DLL을 함께 가진 프로세스 RSS/commit이므로 DLL별 메모리 비교가 아니다. 이 측정은 FPS나 전체 파일 열기 시간의 개선율이 아니다.
