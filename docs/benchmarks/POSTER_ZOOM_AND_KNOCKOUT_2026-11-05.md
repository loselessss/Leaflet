# 포스터 확대 후 정밀 표시와 작은 녹아웃 영역

2026-11-05, Windows 하드웨어 Direct2D, PyMuPDF 1.28.6.
렌더러 ABI 26·MuPDF 입력 ABI 3·장면 저장 의미 버전 22.
실제 PDF와 화면·측정 원본은 비공개 로컬 검증 폴더에 보관한다.

## 더모아젠의 CPU 영역

더모아젠 1쪽의 작은 녹아웃 합성 두 곳은 각각 222개·132개 명령이며,
면적 합계는 페이지의 약 0.2764%다. 미지원 구조 때문에 남은 영역이 아니라
작고 복잡한 그룹을 미리 계산하던 기존 성능 정책에 해당한다. 2쪽에는 없었다.

모든 작은 영역을 GPU로 바꾸는 후보는 더모아젠에서는 속도가 비슷했지만,
ACB 2015에서는 맞춤 화면 GPU 완료가 101.6→1170.9ms,
확대 영역은 약 60→500~670ms로 느려졌다. 이 후보는 채택하지 않았다.

최종 정책은 기존 후보 조건(128~65,536개 명령·페이지 면적 0.5% 이하·
텍스트/반복 패턴 제외)을 유지하되, 후보 명령의 페이지 합계가 512개 이하면
GPU 벡터로 남긴다. 초과하면 최대 64영역을 CPU에서 준비한다.
문서명에 따른 예외는 없다. 더모아젠은 두 쪽 모두 CPU 합성 영역이 없어지고,
ACB 2015는 이전 정책을 유지한다. 이미지 해독과 최초 페이지 미리보기 등의
CPU 준비 작업까지 없어진다는 뜻은 아니다.

1200×900 화면, 새 장면으로 준비, 워밍업 1회 제외 후 순서를 번갈아 3회 측정한 중앙값.
장면 업로드는 제외하고 정밀 GPU 완료·readback을 포함한다.
확대 영역은 두 후보의 중심을 800%로 표시하며 주변 준비 영역을 포함한다.

| --- | ---: | ---: | ---: |
| 더모아젠 1쪽 맞춤 | 1069.6 | 1100.8 | 0.0027 |
| 더모아젠 1쪽 영역 1 | 1020.9 | 1024.7 | 0.0287 |
| 더모아젠 1쪽 영역 2 | 1054.8 | 1023.3 | 0.0304 |

| ACB 2015 영역 1 | 56.2 | 52.9 | 0 |

더모아젠의 GPU 전환은 속도 향상으로 해석하지 않는다. 작은 CPU 비트맵 대신
확대 배율에 맞는 GPU 합성을 유지하는 변경이다. RGB 채널 차이가 16을 넘는
픽셀은 맞춤 화면 0.0072%, 확대 영역 0.0606~0.0668%였다.

## 확대 종료 후 표시 파이프라인

기존에는 확대 애니메이션이 끝나면 동기식 중간 화면을 다시 합성하고,
90ms 대기 후 최종 배율의 정밀 GPU 타일을 요청했다. 복잡한 포스터에서
같은 합성을 반복하며 선명한 영역이 보이기 시작하는 시점을 늦췄다.

변경 후에는 이미 있는 미리보기 위에 완료된 정밀 타일을 덧그린다.
미리보기를 사용할 수 있는 복잡한 장면은 중간 합성과 90ms 대기를 생략한다.
요청 거절·작업 실패 시 기존 벡터 표시로 돌아가고, 이동·취소 후에는 같은
위치에서도 다시 요청할 수 있다. 단순 페이지의 직접 벡터 표시는 유지한다.

같은 최종 장면으로 두 표시 순서만 비교했다. 맞춤 화면을 준비한 뒤 중심을
고정해 1.5배 확대하고, 확대 종료 시점부터 측정한다. 실제 타일 확인 주기와
같은 30ms 간격으로 완료 여부를 확인했다. 1200×900, 새 장면마다 초기
미리보기 준비를 측정에서 제외하고 워밍업 1회+교대 3회 중앙값을 사용했다.
측정용 프레임은 종료까지 제출하며, 마지막 화면의 readback은 시간에서 제외한다.

| 문서 | 첫 정밀 타일 ms 이전→이후 | 전체 정밀 완료 ms 이전→이후 | 동기식 표시 제출 ms 이전→이후 |
| --- | ---: | ---: | ---: |
| ACB 2015 | 141.9→32.0 | 172.2→94.5 | 19.4→1.0 |
| ACB 2019 | 145.6→31.7 | 176.1→62.7 | 23.5→0.5 |
| 더모아젠 1쪽 | 203.8→49.7 | 1012.1→900.7 | 69.2→1.1 |

3문서 모두 최종 BGRA 픽셀이 일치했다. 확대 애니메이션 중에는 여전히 빠른
미리보기를 사용한다. 모든 프레임을 벡터로 직접 그린다는 변경은 아니다.
GPU·드라이버·화면 크기·배율에 따라 시간은 달라진다.

## 검증

- 작은 녹아웃은 GPU에 남고, 명령이 많은 후보는 제한된 CPU 영역으로 준비되는 회귀 검사.
- 포스터의 즉시 요청·부분 타일 표시·요청 거절·작업 실패·취소 후 재요청 회귀 검사.
- ReaderView 및 네이티브 컴파일러·작업 프로세스·GPU·캐시 관련 테스트 222개 통과.
  설정 파일 교체에서 일시적으로 접근 거부가 발생한 1건은 단독 재실행으로 통과했다.
- 기존 CPU 영역이 저장된 장면을 재사용하지 않도록 저장 의미 버전을 22로 변경했다.
- 개발 실행 파일을 다시 빌드하고 ACB 2015·2019, 더모아젠 두 쪽, 계산서의
  맞춤·800%·3200% 총 15조건에서 실제 GPU 프레임과 소스/패키지 장면 일치를 확인했다.
  더모아젠 6조건 모두 CPU 합성 영역이 없었다.
- 실행 파일의 문서 열기와 일반 열람 시 AI 런타임이 적재되지 않는 동작을 확인했다.
