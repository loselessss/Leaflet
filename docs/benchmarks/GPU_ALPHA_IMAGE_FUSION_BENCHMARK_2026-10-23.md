# 래스터 알파 마스크 결합 비교

측정일: 2026-10-23 · Leaflet 1.37.1 개발 중 · Intel Iris Xe · native ABI 24 유지

후속 [알파 소스 수명 단축 비교](GPU_ALPHA_SOURCE_LIFETIME_BENCHMARK_2026-10-23.md)에서는 결합 시점을 각 범위 종료 시점으로 옮겨, 아래에서 한도에 걸렸던 ACB 2019의 source bucket 2도 같은 64MiB 예산 안에서 추출할 수 있게 했다. 이 문서는 앞선 추출 후 일괄 결합 단계의 측정 이력이다.

## 결론과 적용 범위

**보간 방식이 같은 이미지·알파 마스크만 한 BGRA 소스로 결합하는 경로를 기본 적용했다.** ACB 2019의 마스크 23개가 없어져 준비된 장면의 맞춤 그리기는 63.68→22.70ms, 별도 프로세스의 peak RSS는 약 114MiB 낮았다. 추가 준비 비용을 포함한 첫 화면 완료 시간은 1,345.86→1,350.38ms로 거의 같았다. 첫 화면 전체가 세 배 빨라진 결과는 아니다.

ACB 2015의 14개 마스크는 nearest, 색 이미지는 linear 보간이다. 이를 합치면 마스크의 날카로운 경계를 보존할 수 없어 제외했다. 2015의 최종 장면과 픽셀은 바뀌지 않는다. 이전 삽화 컴파일 이후 기준 4,756개 항목을 유지한다. 2019는 323→277개로 줄었다.

두 문서에서 남은 마스크 37개는 이미 래스터였고, 모두 `MaskBegin → mask image → MaskEnd → color image → ClipPop`인 단일 이미지 범위였다. 벡터 마스크를 추가로 이미지화하는 대신 이 중간 합성을 없앴다. 새 페이지·그룹 결과 캐시는 추가하지 않았다. 글자·벡터 경로와 원본 PDF 저장 내용은 바꾸지 않는다.

## 조건과 구현

- 일반 알파 마스크, 투명 배경, 빈 transfer, 마스크 opacity=1, 동일한 크기·변환·보간 방식, 밀집 BGRA 버퍼인 단일 이미지 범위만 선택한다. luminosity·transfer·여러 그리기 명령·서로 다른 보간은 유지한다.
- `pdfeditor/gpu_alpha.py`에서 premultiplied BGRA 각 채널에 mask alpha를 한 번 곱한다. 원본 이미지가 이미 반투명이면 원래 A도 함께 곱하며 원래 opacity는 유지한다. 전체 65,536가지 source alpha×mask alpha 조합을 정수 참조와 검사했다.
- MuPDF `Pixmap.set_alpha`는 색 변환 없이 각 채널을 곱한다. 이를 이용해 BGRA↔RGBA 왕복 복사를 제거했다. 별도 7회 변환 중앙값은 2019에서 약 143→54ms였고, 최종 전체 준비 비교의 변환 중앙값은 50.90ms였다.
- 기존 마스크 영역을 사각형 clip으로 유지하고 원래 위치·그리기 순서를 보존한다. 후보 하나의 변환이 실패하면 원래 범위를 유지한다.
- 최종 고유 이미지 bytes와 누적 파생 이미지 생성량 모두 기존 64MiB 한도를 넘지 않게 검사한다. 공유 원본을 여러 번 참조하는 경우도 계산한다. deadline을 변환 전후에 확인하며 취소/시간 초과는 기존 fallback을 따른다.
- 파생 이미지의 `source_index`는 비워 잘못된 원본 픽셀이 디스크 캐시에 복구되지 않게 한다. 유효한 두 원본 callback ID를 `alpha` refresh recipe에 보관해 확대 시 색·마스크를 모두 다시 읽고 결합한다. 한 소스가 없거나 두 소스의 크기·보간 등이 달라지면 전체 추출로 돌아간다. recipe가 없는 파생 이미지는 기존 전체 추출을 따른다.
- 장면 디스크 형식 11→12. 앱·설치 프로그램 버전은 미배포 1.37.1을 유지한다. native DLL과 ABI는 변경하지 않았다.

선형 필터링과 사전 곱셈은 교환되지 않으므로 보간 방식이 같아도 출력이 byte 단위로 같지는 않다. 필터링된 이미지 경계의 차이를 허용한 최적화다.

## 준비된 입력의 그리기 비교

1200×900, 96 DPI, source raster bucket=1. 표본마다 새 retained scene을 만들고 그룹/타일 결과를 재사용하지 않았다. 3개 후보를 번갈아 실행한 15회 표본이다. 타이머는 worker가 필요하면 정밀 작업 완료를 기다려 그 결과를 그리고, 필요 없으면 직접 command list를 그린 뒤, **두 경로 모두 BGRA readback과 end_frame까지** 포함한다. PDF 추출·변환·불변 자원 upload·retained scene 생성은 이 표에서 제외한다. 2019의 마스크가 없어지면서 worker가 필요 없는 직접 경로가 됐다.

| ACB 2019 | 기존 중앙값 / P95 | 보수적 결합 중앙값 / P95 |
|---|---:|---:|
| 맞춤 | 63.68 / 111.11ms | 22.70 / 34.57ms |
| 100% | 62.17 / 91.19ms | 20.26 / 31.27ms |
| 200% | 34.77 / 47.86ms | 16.57 / 21.72ms |

위 100%·200%는 같은 source bucket=1 장면의 화면 배율 비교다. 앱의 더 높은 source bucket 추출 비용을 포함하지 않는다. 실제 2019 포스터는 1보다 높은 bucket에서 기존 경로와 새 경로 모두 원본 이미지 추출 중 64MiB 한도에 걸려 CPU fallback을 사용했다. 이번 변경으로 이 기존 제약이 해소됐다고 주장하지 않는다.

2015 보수적 후보는 실제로 변환 0개다. 기존/보수적 맞춤 중앙값 93.95/94.86ms였으며, 같은 입력의 타이밍 편차를 개선으로 해석하지 않는다. 모든 마스크를 강제로 합친 공격적 후보는 이득도 있었지만 보간 차이가 큰 2015까지 바꿔 기본에서 제외했다.

최종 코드가 생성한 소스 bytes와 범위는 위 보수적 시제품과 두 문서 모두 일치했다. refresh recipe만 추가됐다. 공개 측정 도구에 `--mode completed`, `--no-alpha-fusion`을 추가했고 최종 2019 직접 경로도 실행 확인했다. 기존 `sharp` 모드는 worker 완료만 측정하므로, worker가 필요 없는 장면과 비교하려면 `completed`를 사용한다.

## 새 PDF부터 첫 화면 완료

Qt/window/device 생성은 타이머 밖이다. 각 표본은 새 PDF 열기→전체 추출→알파 변환→전체 불변 자원 upload→새 retained scene→그리기→동기 readback/end_frame을 포함한다. MuPDF store를 표본 전에 비우고 결과/장면 소유권을 표본 뒤 해제했다. 1회 warm-up 뒤 순서를 뒤집어가며 각 7회 측정했다. source bucket=1, 맞춤 화면이다.

| ACB 2019 단계 | 기존 중앙값 | 최종 결합 중앙값 |
|---|---:|---:|
| 전체 완료 | 1,345.86ms | 1,350.38ms |
| 추출 | 962.54ms | 969.59ms |
| 알파 변환 | 0.002ms | 50.90ms |
| upload | 300.84ms | 286.16ms |
| retained scene 생성 | 2.05ms | 1.80ms |
| 그리기·readback/end_frame | 71.81ms | 30.88ms |

단계별 중앙값의 합은 전체 중앙값과 다르다. 일부 표본은 두 경로 모두 2초 이상으로 느려져 GPU/시스템 변동이 남았다. 느린 왕복 채널 복사 시제품은 두 비교에서 첫 화면이 약 6~14% 느렸다. 해당 구현은 채택하지 않았다. 최종 복사 절감 뒤 전체 중앙값 차이는 +4.52ms(+0.34%)다.

## 메모리와 화면 차이

메모리는 후보별 독립 프로세스 1회씩, 준비된 scene 입력을 읽고 변환·upload·맞춤/100%/200%를 새 장면으로 그린 관찰이다. PDF 해석은 제외했다. 여러 회 중앙값이나 VRAM 절감으로 해석하지 않는다.

| ACB 2019 | 기존 | 결합 |
|---|---:|---:|
| 이미지 픽셀 bytes 합계(중복 참조 포함) | 46,125,412 | 25,006,444 |
| peak RSS | 407.98MiB | 294.05MiB |
| 현재 RSS | 378.19MiB | 264.26MiB |
| peak commit | 444.55MiB | 331.40MiB |

장면의 고유 픽셀 저장량은 2019 결합 후 24,837,804bytes다. 위 합계와 구분한다. 2015 보수적 후보는 메모리 구조도 그대로다.

2019에서 기준 대비 맞춤 7,413픽셀(전체 1,080,000픽셀의 0.686%)이 달랐고 채널 최대 차이는 79/255, 전체 BGRA 평균 절대 차이는 0.02602이었다. 100%는 24,721픽셀/최대64, 200%는 29,482픽셀/최대63이었다. 국소 경계 차이는 최대값처럼 클 수 있으며 완전 일치를 주장하지 않는다. 전체 맞춤 화면을 시각 검토했고 레이아웃과 글자를 유지했다. 2015 보수적 후보는 세 화면 모두 byte 일치했다.

마스크 해상도만 절반으로 줄인 별도 후보는 2019 픽셀 합계가 30,294,756bytes로 줄었지만 중간 합성은 남았고 그리기 이득이 일정하지 않았다. 맞춤 화면 차이는 16,988픽셀/최대170, 평균 절대 차이 0.2595로 결합보다 커 채택하지 않았다.

## 검증과 자료

알파 전수 조합, 불일치·transfer·luminosity·공유 버퍼 예산·변환 실패·deadline, 실제 PDF 추출·디스크 직렬화·두 원본 callback 기반 확대 갱신을 검사한다. 실제 Direct2D 출력은 96/192 DPI×0/90도에서 확인한다. 전체 관련 회귀 검사 결과는 아래 최종 검증 기록을 따른다.

최종 관련 회귀 검사 **172개 모두 통과**. GPU 알파·삽화·장면 추출·색·실제 합성, 디스크/메모리 캐시, native backend, 작업 프로세스와 릴리스 패키징/노트 검사를 포함했다. 첫 실행의 샌드박스 임시 경로 접근 오류는 workspace 안의 임시 경로를 사용해 해결했다. 마지막 전체 검사에서는 정리 중 임시 PDF의 일시적인 Windows 파일 잠금 오류 1건이 있었으며 같은 172개 검사를 다시 실행해 모두 통과했다. 공개 `completed` 측정 모드의 worker/직접 경로도 각 2회 실행했다.

원본 PDF와 측정 파일은 저장소에 포함하지 않는다. 개인 작업 폴더 `tmp/gpu-alpha-raster/`에 `timing/results.json`(15회 준비된 그리기), `quality.json`, `cold-fast/results.json`(최종 7회 첫 화면), `memory/*.json`, `zoom-verification.json`과 화면 파일을 남겼다. 비교 기준은 삽화 컴파일까지 적용한 `be7c5dc`다.
