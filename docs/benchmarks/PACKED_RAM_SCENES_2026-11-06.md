# 벡터 장면의 RAM 압축 보관

2026-11-06 · 1.39.0 개발본 · Windows · 기존 Rust LZ4 코덱

첫 쪽의 실제 컴파일 패킷을 사용했다. 압축과 복원은 RAM에서만 수행했으며 디스크 장면 읽기와 PDF 재컴파일을 예외로 막은 상태에서 Document 캐시 복원을 확인했다. 패킷 바이트의 완전 일치를 검증했다. 시간은 같은 PC의 참고값이며 파일 열기·GPU 업로드·화면 합성은 제외한다. 최초 코덱 로딩은 압축 시간에 포함될 수 있다.

| 문서 | 원본 패킷 | 압축 RAM | 벡터 추출·컴파일 | RAM 복원 |
| --- | ---: | ---: | ---: | ---: |
| ACB 2019 | 24.63 MB | 3.04 MB | 1093 ms | 44.2 ms |
| ACB 2015 | 3.93 MB | 1.44 MB | 874 ms | 8.5 ms |
| 더모아젠 | 6.00 MB | 1.37 MB | 726 ms | 11.2 ms |

압축 작업은 각각 약 39 / 14 / 18ms였으며 앱에서는 백그라운드에서 실행한다. 복원 코덱 자체는 7회 중앙값으로 약 48 / 10 / 11ms였다. 표의 복원 값은 Document 경로를 한 번 측정한 것으로 반복 측정의 중앙값과 구별한다. 이미 압축 해제된 최근 장면의 조회와 비교한 속도 향상을 뜻하지 않는다.

- 원래 RAM 캐시 예산의 3/4는 바로 쓸 장면에, 최대 1/4(256MiB 이내)는 압축 보관에 사용한다. 압축 보관은 128개, 한 작업의 원본 패킷은 32MiB 이내다. 압축 중 원본도 예산에 포함하며 한 문서에서는 한 압축 작업만 대기·실행한다.
- 최소 10% 줄어드는 장면만 보관한다. 압축 중 필요한 쪽은 남아 있는 원본을 즉시 반환해 압축 완료를 기다리지 않는다.
- 가까운 페이지는 기존 GPU 자원 보관을 사용하고, 압축 보관으로 밀린 페이지가 GPU 캐시에 원본 패킷을 중복 보유하지 않도록 정리한다. GPU에 아직 없는 장면은 복원 후 업로드·합성이 남는다.
- 주변 준비 후보를 RAM 여유에 따라 최대 32페이지로 늘렸다. 원본·압축 합산 예산을 유지하고 현재 페이지는 보호한다. 압축 캐시 조회 때문에 준비 중인 다른 페이지를 불필요하게 해제하지 않는다.
- 문서 수정·되돌리기·닫기·같은 경로 저장과 메모리 부족에서 압축 상태를 무효화한다. 오래 걸린 압축 결과가 나중에 돌아와도 다시 설치하지 않는다.
