# 중첩 마스크 합성 통합 비교 — 2026-10-23

개발 버전 1.37.1 · 공개 ABI 24 · 기준은 타일 계획·선택 binding까지의 개발 DLL(a7008846…). 실험은 10월 22일 시작했고 최종 검증은 23일 완료했다.

성능 이득이 재측정에서 재현되지 않아 기본 코드에는 채택하지 않았다. 아래 구현·검사 결과는 보관한 실험 후보에 대한 기록이다.

## 범위와 의존성

타일 계획에서 클립/적용 마스크의 콘텐츠가 다른 클립/적용 마스크 하나뿐인 구간을 찾았다. 앞뒤에 다른 그리기·상태 변경이 없어 부모의 원본 콘텐츠 표면이 공통 배경으로 남는 조건이다. 마스크 생성 단계의 그리기는 콘텐츠와 구분하고, COPY·knockout·비격리·마스크 생성 중인 상위 문맥은 제외했다.

실행 시에도 부모·자식의 실제 캡처 명령 ID, bitmap 연결, 크기·원점, mask·opacity·합성 상태를 다시 확인한다. 단순/무효 그룹 생략이나 기존 격리 클립 통합 때문에 논리 그룹과 실제 캡처 스택이 달라지면 기존 경로를 쓴다. 이번 후보는 자식이 부모 표면 전체와 같은 크기·원점을 쓰는 경우만 처리한다. 서로 다른 범위의 합성이나 세 마스크 이상을 한 셰이더로 합치는 기능은 포함하지 않는다.

자식 닫기를 지연한 뒤 네 입력(B, C, inner mask, outer mask)의 엄격한 FP32 셰이더로 부모 닫기에서 한 번 그린다. 기존 자식·부모의 배경 복사 두 번과 닫기 DrawImage 한 번을 없앤다. 마스크를 곱해서 근사하지 않고 각 항의 UNORM8 반올림 및 중간 표면 clamp를 유지한다.

```
L(B, C, m) = Q8(B × (1−m)) + Q8(C × m)
result = L(B, clamp(L(B, C, inner)), outer)
```

자식 입력 bitmap과 raw mask는 부모 합성이 끝날 때까지 유지한다. 자식의 예약량도 부모에 합쳐 활성 메모리 예산에서 빠지지 않게 한다. 이미 지연 입력이 있는 그룹과 겹쳐 통합하지 않는다. 새 effect 생성·shader load 실패는 상태 변경 전에 감지해 기존 합성으로 돌아간다. 취소 시 기존 캡처 스택 정리로 입력 수명도 끝난다.

## 전체 정밀 완료 시간

계측 코드를 뺀 두 DLL을 같은 프로세스에서 순서를 교차·회전하며 비교했다. 각 문서·배율에서 3회 예열 후 15회 측정했다. 1200×900 viewport, 96 DPI, 5ms polling, Intel Iris Xe. 매 표본 새 retained scene으로 결과 캐시 재사용을 막았다. 요청부터 전체 atlas 완료·UI import까지이며 초기 장면 생성·자원 업로드는 타이머 밖이다. GPU timestamp만의 측정은 아니다. 다른 GPU 검사·빌드는 동시에 실행하지 않았다.

단위 ms. 감소율은 양수가 단축, 음수가 악화다. 15회 표본의 nearest-rank P95는 최대값이므로 안정적인 꼬리 지연 추정으로 일반화하지 않는다.

기본 경로에는 채택하지 않는다. 최초 5ms polling 비교의 ACB 2015는 맞춤 -2.0%, 100% +1.6%, 200% +6.3% 단축으로 조건별로 달랐다. ACB 2019 200%도 통합 대상이 없는데 시간이 좋아져 실행 변동·관측 간격의 영향을 확인했다. 따라서 별도로 1ms polling, 각 15회 ACB 2015 재측정을 수행했다.

재측정 중앙값(ms): 맞춤 580.06→540.54(+6.8%), 100% 575.55→653.47(-13.5%), 200% 185.15→188.80(-2.0%). 두 실행 사이의 절대 시간은 직접 비교하지 않는다. 같은 실행 안에서도 단축 방향이 조건별로 섞였고, 두 실행 간 이득도 재현되지 않았다. 복사 횟수·픽셀 감소만으로 성능 향상을 주장하지 않는다.

후보 C++·shader·테스트·빌드 스크립트와 DLL은 개인 실험 폴더의 prototype/에 보관했다. 일반 네이티브 소스·빌드·DLL과 테스트 파일은 이번 작업 전 상태로 되돌렸고, 이전에 완료한 arena·타일 계획·선택 binding 및 다른 로컬 변경은 유지했다. 미배포 버전은 계속 1.37.1이며 사용자에게 배포하는 기능 변화는 없다.

이번 조건에서 통합 가능한 실제 쌍은 프레임당 8~12개로, 남아 있는 복사 호출 774~1,966개 중 일부다. 다음 계측 대상은 개별 작은 그룹의 복사·제출 비용과 그리기 실행 시간의 구분이다. 이 실험만으로 다른 구간을 주 병목이라고 확정하지 않는다.

- C++17 /W4 /WX /O2, 두 ps_4_0 shader의 /Gis /O3 빌드 통과. 공개 ABI는 24다.
- 실험 후보의 GPU 관련 검사 108개 통과. 별도 WARP 합성 검사 18개 및 새 shader load를 강제로 실패시킨 기존 경로 검사 18개 통과.
- 기본 코드 복원 후 기존 합성 검사 16개도 통과했다. 복원한 C++·빌드 스크립트·DLL이 실험 전 파일과 byte 단위로 같음을 확인했다. 1ms 재측정에서 저장한 ACB 2015 세 화면도 픽셀 차이가 없다.
- 새 정확도 검사는 한 색상 쌍에서 안쪽·바깥쪽 알파 256×256 조합을 독립 CPU 식과 픽셀 단위로 완전히 비교한다. 원래 DLL에서도 같은 검사가 통과한다.
- clip/mask 혼합, 3~4중 중첩, 비선형 transfer, 96/144 DPI, 회전·fractional 좌표, COPY 상위 그룹, 후속 같은 크기 scratch 덮어쓰기를 검사했다. 이 좌표 검사의 독립 참조는 투명 geometry를 추가해 통합을 막는다. 새 shader가 실패해 기존 경로만 쓰는 빌드에서도 AA 경계 1단계 차이가 확인되어 최대 1·평균 0.001 미만으로 검사한다. 기존 테스트의 허용치는 바꾸지 않았다. 포스터 6개 화면과 CPU 알파 조합 검사는 완전 일치를 별도로 요구한다.

## 메모리·한계

렌더 결과 캐시나 해상도 근사는 추가하지 않는다. 마스크 생성용 표면과 source 할당은 유지하고, 닫기용 중복 backdrop 복사를 없애는 첫 단계다. 지연 입력의 생존 기간이 부모 종료까지 늘기 때문에 줄어든 복사량을 RSS/VRAM 감소로 표현하지 않는다. 활성 예약량은 그대로 유지하며 계획·캡처의 bookkeeping 비용은 추가된다. 계획은 한 타일씩 보관하고 명령 1,048,576개·깊이 4096개·통합 후보 65,536개를 제한한다. 한도·할당·구조 실패 시 기존 전체 replay를 쓴다.
