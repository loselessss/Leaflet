# 스크롤 중 GPU 선명화 타일 재사용

## 변경

1.39.2에도 완성된 화면 캐시와 겹치는 타일을 GPU에서 복사하는 경로가 있다. 이번 변경은 새 캐시 체계를 추가하는 대신, 그 캐시가 완성되기 전에 스크롤 때문에 버려지는 작업을 줄인다.

- 같은 장면·배율·화면 크기를 유지하며 기존 작업과 겹치는 위치로 이동하면 진행 중인 작업과 완료 알림을 유지한다.
- 진행 중인 작업에서 완성된 타일도 현재 페이지 이동량만큼 옮겨 즉시 표시한다. 동일한 픽셀 위상·DPI에서만 재사용한다.
- 현재 작업이 끝나면 최신 화면 위치의 빈 영역을 기존 캐시 복사 경로로 채운다. 배율 변경, 멀리 이동, 화면에서 사라진 페이지, 장면 교체는 계속 취소한다.
- 화면·작업자·캐시의 기존 메모리 상한을 유지한다. 전체 페이지를 미리 래스터화하거나 영구적인 페이지 타일 저장소를 추가한 것은 아니다.

## 비교

더모아젠 첫 페이지의 같은 벡터 장면을 미리 준비하고, 기존 DLL과 변경 DLL을 번갈아 3회씩 실행했다. 1200×900 화면에서 화면 맞춤의 4배로 확대하고 20번 세로 이동한다. 기존 정책은 이동마다 선명화를 취소하고, 변경 정책은 겹치는 작업을 유지한다. 자원 준비·앱 실행은 측정에서 제외한다.

| 조건 | 첫 선명한 타일 표시 중앙값: 기존 → 변경 | 새 선명화 요청 수 중앙값 |
|---|---:|---:|
| 40ms마다 12픽셀 이동 | 83.7 → 47.3ms | 5 → 4회 |
| 16ms마다 24픽셀 이동 | 89.4 → 31.9ms | 10 → 7회 |

이 수치는 **일부 선명한 타일이 처음 표시되는 시간**이다. 화면 전체가 완성되는 시간이나 실제 Qt 앱의 입력 지연/FPS가 아니다. 빠른 이동 조건에서 선명한 내용이 표시된 표본은 20개 중 중앙값 15→19개였다. 측정한 API 호출의 중앙 시간은 빨라지지 않았으므로 모든 프레임 처리 속도 향상을 주장하지 않는다. CPU 모드와 직접 비교한 결과도 아니다.

이동 중 타일의 65,536개 채널 표본을 동일 위치의 직접 벡터 출력과 비교해 평균 차이 0.00046/255를 확인했다. 기존 합성·DPI·회전·타일 경계 픽셀 검증과 읽기 화면 테스트도 실행했다.

로컬 원시 자료: `.test-runtime/gpu-pan-tiles/`의 `bench.py`, `results.json`(40ms), `results-16.json`, `pixels.py`. 실행 중인 타일의 보관을 개선한 1.39.3 개발 변경이며, 압축된 벡터 장면의 저장 형식은 변경하지 않는다.
