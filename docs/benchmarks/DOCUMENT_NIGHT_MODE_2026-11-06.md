# 문서 다크 모드 표시 측정

2026-11-06 · 1.39.0 개발본 · Windows 하드웨어 Direct2D

밝은 종이·글자를 읽기 편한 색으로 바꾸고 사진·이미 어두운 영역은 보수적으로 보호한다. PDF 데이터와 저장·인쇄 색상은 변경하지 않는다. 보기 → 다크 모드에서 ‘문서도 어둡게’로 선택한다.

## 측정

흰 종이, 검은 본문, 파란 글자, 사진, 어두운 패널을 포함한 합성 2쪽 PDF를 사용했다. GPU 뷰는 1148×1048 물리 픽셀, DPR 1이다. 준비된 프레임을 일반/다크 모드로 번갈아 각각 22회 측정했으며 테스트용 동기 픽셀 읽기를 포함한다. 최초 장면 준비와 present는 제외했다. 아래 수치는 이 샘플의 결과이며 모든 문서의 추가 시간을 뜻하지 않는다.

| 항목 | 결과 |
| --- | ---: |
| 일반 GPU 표시 | 15.582 ms |
| 문서 다크 GPU 표시 | 16.520 ms |
| 추가 시간 | 0.938 ms |
| 최초 미리보기 분석 | 약 5 ms |
| 분석 캐시 조회 | 약 0.0006 ms |
| 447×632 CPU 미리보기 색 변환 | 약 7.4–7.8 ms |
| CPU 변환 캐시 조회 | 약 0.009–0.014 ms |
| 이 뷰의 GPU 임시 표면 | 9.18 MiB |

## 처리와 한도

- Python은 설정·캐시·호출을 관리한다. Windows의 분석·CPU 픽셀 변환·색상표 생성은 네이티브 코드가 처리하며 GPU 표시는 색상표와 보호 마스크를 적용한다. 이전 DLL 등 호환 경로에는 NumPy/Pillow 대체 처리가 남는다.
- 분석은 최대 512×512, 분석 캐시는 최근 8개, CPU 변환 캐시는 16 MiB로 제한한다. GPU 임시 표면은 2048×2048 두 장, 최대 32 MiB이며 끄면 해제한다.
- 원본 GPU 장면과 미리보기·타일은 수정하지 않는다. 일반 표시 → 문서 다크 → 일반 표시 후 픽셀의 정확한 복원과 장면 재사용을 확인했다.
- ACB 2019, 더모아젠, 세금계산서 각 첫 쪽에서 하드웨어 GPU 표시 유지, 전환 시 추가 CPU 페이지 렌더 0회, 원본 파일 불변을 확인했다.
- 이미 어두운 페이지·사진 보호, 스캔 문서, 회전된 이미지, 굵은 글자, 96/144 DPI와 타일 경계, 임베디드 기본 원본 색상도 검증했다.

복잡한 삽화와 스캔의 사진·종이 구분은 근사다. 불확실한 영역은 원본을 유지하므로 모든 밝은 부분이 어두워지지는 않는다. 정밀 색상 확인에는 이 옵션을 끈다.
