# 확대 후 이동 중 선명한 화면 유지

직전 1.39.3 개발 변경(스크롤 중 작업 유지·부분 타일 재투영)을 기준으로 추가 비교했다. 버전 번호는 같은 미배포 1.39.3을 유지한다.

## 변경

- 이전에는 기존 캐시가 새 타일 전체를 덮어야만 복사했다. 이제 겹치는 부분을 모두 GPU에서 복사하고 남은 직사각형 띠만 다시 그린다. 여러 캐시에서 중복 없이 채우며 조각 분할에는 한도를 둔다.
- 선명한 화면의 주변 여유 폭을 물리 픽셀 기준 64→256으로 늘리고, 128픽셀 여유가 남았을 때 다음 위치의 배경 작업을 시작한다. 화면 자체가 선명할 때도 이 준비를 요청한다.
- 전체 GPU 캐시 및 작업 크기 상한은 그대로다. 1200×900 기준 단일 아틀라스의 픽셀 저장 공간은 약 5.21→9.22MiB로 늘어난다. 이는 작업자·임시 합성 표면 등을 포함한 전체 VRAM 수치는 아니다.

## 비교 및 한계

더모아젠 첫 페이지를 1200×900 화면 맞춤의 4배로 준비하고 최초 선명화 완료까지 기다린 뒤, 16ms 간격으로 24픽셀씩 세로 이동했다. 같은 장면을 사용하는 기존·변경 DLL을 교차 3회 실행했다. 기존은 화면이 캐시를 벗어나면 새 작업을 시작하고, 변경은 여유 영역을 미리 갱신한다.

최초 비교에서 화면 전체가 선명한 캐시로 표시된 횟수는 **20번 중 14→20번**으로 세 번 모두 같았다. 이전에도 20번 모두 일부 선명한 부분은 표시됐지만, 나머지 6번은 화면 전체를 선명하게 덮지 못했다. 실제 Qt 입력 지연/FPS나 CPU 모드와의 직접 비교는 아니다. 첫 화면·새 배율에서 아직 준비되지 않은 부분은 계속 선명화가 필요하다.

호출 중앙 시간은 각 반복에서 기존 1.41/1.41/1.76ms, 변경 2.23/1.76/1.47ms였다. 미리 준비하는 비용이 있으므로 모든 그리기 호출이 빨라진다고 주장하지 않는다.

별도 96픽셀 이동 후 선명화 완료 대기 비교에서 반복별 중앙값은 기존 6.64/11.02/7.46ms, 부분 복사 변경 6.60/5.92/5.50ms였다. 이 비교는 여유 폭 확대 전 부분 복사만 반영한 결과다.

원시 자료는 로컬 `.test-runtime/gpu-pan-strips/`의 `bench.py`, `results.json`, `warm.py`, `warm-results-16.json`, `warm.log`에 보관한다. `warm-final.log`는 최종 픽셀 검증을 추가한 반복 실행이다. GPU 합성·회전·DPI·타일 경계 검증 및 읽기 화면 테스트를 실행한다.

최종 반복에서도 전체 선명한 표시는 세 번 모두 14→20회였다. 이동과 캐시 복사가 끝난 전체 프레임을 직접 벡터 출력과 비교한 평균 채널 차이는 0.00080/255였다.
