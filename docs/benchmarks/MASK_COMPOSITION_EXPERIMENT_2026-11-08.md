# 투명도 합성 통합 비교 · 2026-11-08

## 판단

직접 마스크 합성 후보는 채택하지 않는다. 배경 복사와 제출 횟수는 줄었지만 실제 포스터의 속도 개선이 일관되지 않았다. 임시 표면 수명 계획의 작은 개선만 1.39.1 개발본에 남긴다. 합성 수식·배경 복사·제출 순서는 기존 동작을 유지한다.

## 합성 통합 실험

마스크 적용 내용이 source-over 이미지 하나이거나 불투명도 1의 격리 Normal 그룹 하나이면 투명 소스에 마스크를 적용한 뒤 원래 배경에 합성하는 후보를 만들었다. 배경 의존 이미지·knockout 부모·마스크 생성 중인 상위 범위는 제외했다. D2D Composite 효과와 BitmapBrush/FillOpacityMask 두 방식을 비교했다.

최초 후보는 마스크 생성 제출까지 없애 ACB 2019의 이미지 일부가 사라졌다. 이 변경은 폐기했다. 생성 제출을 유지하면 포스터의 큰 차이는 없어졌으나, 실제 출력 확인과 별개로 속도 이득은 증명되지 않았다. 예를 들어 계측 없는 BitmapBrush 후보의 ACB 2019 반복 확대 비교(3회 예열·5회 측정, 중앙값)는 맞춤 63.82→66.86ms, 100% 37.76→38.60ms, 200% 32.33→31.80ms였다. 모든 조건에서 빨라지는 변경이 아니다. 별도 15회 비교 중에는 기준·후보 모두 30초를 초과한 더모아젠 조건이 있어 해당 실패 조건의 시간은 비교 근거로 사용하지 않았다.

호출 수 계측은 별도 DLL에서 수행했다. ACB 2015·2019·더모아젠, 맞춤·100%·200%, 각 3회 예열·2회 측정, 표본마다 1.3% 배율 증가, 1200×900·96 DPI·Intel Iris Xe 하드웨어 GPU의 합계다. 이 실행의 시간은 성능 수치로 사용하지 않는다.

| 항목 | 기준 | 직접 합성 후보 |
| --- | ---: | ---: |
| 통합된 마스크 적용 | 0 | 686 |
| 배경 복사 helper 호출 | 11,106 | 9,734 |
| 명시적 D2D Flush 호출 | 11,151 | 10,465 |
| 한 타일의 최대 계획 임시 표면 바이트 | 9,742,524 | 9,011,436 |

복사 약 12.4%, Flush 약 6.2% 감소다. 최대 계획 표면의 차이는 약 0.70MiB이며 앱 전체 RAM/VRAM 절약량을 뜻하지 않는다. 후보 코드·DLL·원시 결과는 로컬 `.test-runtime/mask-fusion-1391/direct-mask-candidate*` 및 관련 로그에 보관한다.

BitmapBrush 방식의 근거: [Microsoft의 비트맵 불투명도 마스크 사용 안내](https://learn.microsoft.com/en-us/windows/win32/direct2d/how-to-clip-with-bitmap-masks). FillOpacityMask 호출 구간만 aliased 모드로 전환하고 기존 모드를 복원했다. 이 구현은 최종 기본 경로에 포함하지 않는다.

## 남긴 개선: 마스크의 임시 표면 수명 계획

마스크의 배경 복사 입력은 해당 마스크를 닫을 때만 빌린다. 기존 계획은 이를 마스크 시작부터 끝까지 살아 있는 것으로 잡아 중첩 마스크 수만큼 동시에 예약했다. 새 계획은 닫는 시점의 최대 사용량만 계산한다. 실제 그리기와 동적 할당 fallback은 그대로다.

512×512 화면에서 같은 영역의 마스크 8개를 중첩한 검사 결과:

| 항목 | 기존 계획 | 개선 계획 |
| --- | ---: | ---: |
| 최대 계획 임시 표면 | 33,817,088 B (32.25MiB) | 26,419,600 B (25.20MiB) |
| 계획 표면 할당 바이트 합계 | 34,611,200 B | 27,040,000 B |
| 복사 helper 호출 | 144 | 144 |
| 명시적 Flush 호출 | 145 | 145 |
| 출력 최대 채널 차이 | 기준 | 0 |

이 조건의 계획 표면은 21.9%, 약 7.05MiB 줄었다. 실제 앱 전체 메모리의 감소율이 아니다. 세 포스터의 측정 조건에서는 최종 계획 개선 전후의 할당 합계·최대 계획 표면·복사·Flush 수가 모두 같았다. 해당 문서에서 속도나 메모리가 개선됐다고 주장하지 않는다.

## 검증

- 최종 계획 개선의 포스터 첫·마지막 화면 18개는 기준과 픽셀 단위로 일치했다.
- 합성 통합 21개, D2D 백엔드 9개, 문서 야간 색상 8개 검사 통과. 알파/휘도 마스크·전달 함수·투명 배경·knockout·상위 마스크 생성·여러 이미지의 같은 크기 임시 표면 덮어쓰기를 포함한다.
- 네이티브 빌드는 기존 경고 오류 처리 설정으로 성공했고 ABI는 유지한다. 직접 합성 후보의 허용 오차를 기존 검사에 적용하지 않았다.
