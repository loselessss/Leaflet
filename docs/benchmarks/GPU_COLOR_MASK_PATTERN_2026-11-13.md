# GPU 색상 변환·이미지 마스크·반복 패턴

## 구현

1. 지원되는 RGB/CMYK 이미지의 원래 색상 성분과 ICC 프로필을 전달한다. MuPDF는 해독·부분 영역 선택·리샘플링을 맡고, Rust는 RGB 채널 정규화, 프로필/자원 중복 제거, 검증·예산·장면 직렬화를 맡는다. Direct2D ColorManagement가 RGB 결과 텍스처를 준비한다.
2. 이미지 마스크는 CPU에서 흰색 BGRA 그림으로 만들지 않고 1바이트 커버리지로 전달한다. GPU에서 그리기용 텍스처를 준비하고 기존 마스크 합성을 수행한다. PDF의 보간 설정을 보존하며, MuPDF가 별도 클립으로 전달한 부착 마스크를 중복 적용하지 않는다. 지원되는 RGB JPEG는 그 별도 GPU 클립 안에서도 원본 압축 스트림을 유지한다.
3. 독립된 벡터 반복 셀은 명령 목록으로 한 번 보관해 GPU 이미지 브러시로 반복한다. 기록 시 거친 기하 실현 자원을 쓰지 않아 확대 곡선을 보존하고, 셀 BBox 원점·간격·회전을 적용한다. 주 화면의 클립/프레임 상태에 영향을 주지 않는 별도 D2D 컨텍스트에서 기록한다.

색 변환과 알파 처리는 이미지 샘플링 격자에서 GPU 텍스처로 완성한다. 확대 보간 전에 CMYK를 변환해야 기존 RGB 보간과 결과가 맞고, 준비된 텍스처를 확대할 때마다 ICC 변환을 반복할 필요도 없다. 프로필 최대 8개, 색 변환 효과 최대 16개를 공유하며, 완료된 변환기의 원본 텍스처 입력을 해제한다.

겹치는 반복 셀, 배경에 의존하는 그룹·이미지·마스크를 담은 패턴, 과도하게 큰 템플릿은 기존 확장/CPU 영역 준비를 유지한다. 템플릿은 이미지·중첩 패턴 자원을 거절하고, 원래 MuPDF 타일 프로그램을 보관해 CPU 탈출 경로에서도 그릴 수 있다. 빈 패턴도 GPU 페이지 준비를 실패시키지 않는다.

이미지 원본은 한 축 8192픽셀/16Mi픽셀, 한 번 준비하는 텍스처는 8Mi픽셀, 프로필은 4MiB로 제한한다. Spot/Indexed·Matte 등 지원 조건을 벗어난 처리는 기존 경로를 유지한다. 마스크는 전달량이 1바이트여도 실제 GPU 결과 크기인 BGRA 4바이트로 예산을 계산한다. 이미지 전체 해독이 GPU로 옮겨진 것은 아니다.

## 측정 방법

- 기준: `fe3d7831`의 네이티브 DLL·Rust 확장을 별도로 보관해 비교. Intel Iris Xe Graphics, 같은 Python/PyMuPDF 환경.
- 두 구현을 같은 프로세스에 각각 로드하고 별도 D2D 표면을 만든다. 배율마다 예열 1쌍 후 3쌍을 교차 순서로 측정한다.
- 매번 PDF와 장면을 새로 준비하며, 컴파일·패킷 생성·GPU 업로드·첫 표시 후 픽셀 읽기까지 합산한다. 앱 시작과 PDF 파일 열기는 포함하지 않는다.
- 자원 준비 배율은 1배/4배이고 표시 영역은 1200×900 화면 맞춤으로 고정한다. **4배 결과는 400%용 자원의 새 준비 비용이며 실제 UI의 400% 스크롤 FPS 측정이 아니다.**
- 구간별 중앙값의 합은 전체 시간 중앙값과 다를 수 있다. 절대 시간은 시스템 부하에 따라 변하므로 같은 프로세스의 교차 비교를 사용한다.
- 원시 자료·스크립트·비교 PNG는 로컬 `.test-runtime/gpu-color-mask-pattern/`에 보관한다. `bench-paired.py`, `paired-{dermo,acb2019,acb2015,pattern}.json`이 최종 비교다. 초기 분리 프로세스 측정은 참고용이며 아래 표와 혼용하지 않는다.

## 새 장면 준비와 첫 표시 합계

| 문서 | 1배 기존 → 변경 | 4배 기존 → 변경 | 4배 단축 |
|---|---:|---:|---:|
| 더모아젠 | 1754.4 → 1786.7ms | 2716.7 → 2406.3ms | 11.4% |
| ACB 2019 | 1870.3 → 2148.5ms | 4362.1 → 2727.6ms | 37.5% |
| ACB 2015 | 1744.5 → 1689.5ms | 2971.7 → 2501.6ms | 15.8% |
| 합성 반복 패턴 | 138.5 → 8.7ms | 757.3 → 91.8ms | 87.9% |

ACB 2019의 1배 준비는 약 14.9% 느려졌다. 작은 화면의 최초 표시가 항상 빨라지는 변경은 아니다. 실문서의 주된 이득은 고배율 준비와 전달/RAM 장면 크기 감소다.

합성 패턴은 1024×1024 페이지에 8×8 벡터 셀을 반복한다. 기존 구현은 셀 수 제한을 넘어 CPU 영역 이미지로 준비했고, 새 구현은 벡터 셀 하나를 보관한다. 실제 세 포스터는 이번 측정에서 GPU 패턴을 쓰지 않았으며, 그 문서의 이득을 반복 패턴 개선으로 설명하지 않는다.

## RAM 장면과 압축 저장 크기

MB는 십진수이며 Python 객체 부대 비용·전체 프로세스 작업 집합·VRAM 사용량이 아닌 실제 장면 패킷 바이트다.

| 문서, 4배 | RAM 패킷 기존 → 변경 | 감소 | LZ4 봉투 기존 → 변경 |
|---|---:|---:|---:|
| 더모아젠 | 41.72 → 28.40MB | 31.9% | 2.98 → 3.36MB |
| ACB 2019 | 120.52 → 62.31MB | 48.3% | 14.61 → 10.52MB |
| ACB 2015 | 29.24 → 22.98MB | 21.4% | 7.81 → 7.92MB |
| 합성 패턴 | 32.24MB → 922B | 99.99% 이상 | 169,175 → 1,023B |

원래 색상과 마스크를 분리하면 투명 영역 아래의 색상 데이터도 보관하므로 LZ4 결과가 항상 작아지지는 않는다. GPU용 마스크는 BGRA로 완성하기 때문에 마스크 전달량 절감을 그대로 VRAM 절감으로 주장하지 않는다.

## 화면 차이와 한계

1200×900 전체 RGB 채널의 평균 절대 차이(255단계):

| 문서 | 1배 | 4배 | 4배 최대 채널 차이 |
|---|---:|---:|---:|
| 더모아젠 | 0.0414 | 0.0364 | 34 |
| ACB 2019 | 0.0555 | 0.1441 | 64 |
| ACB 2015 | 0.0361 | 0.0381 | 19 |
| 합성 패턴 | 17.3495 | 19.8750 | 198 |

실문서의 전체 평균 차이는 약 0.014~0.057%이지만, 개별 경계 픽셀의 차이는 더 크다. 고밀도 체크 패턴은 CPU 준비 이미지와 직접 벡터 표시의 안티앨리어싱 차이가 많은 경계에 누적되어 전체 평균 약 6.8~7.8%다. 해당 이미지도 눈으로 비교했고 셀 배치·색상·반복 범위를 확인했다. 모든 픽셀의 오차가 10% 이내라는 보장은 아니다.

합성 패턴의 4배 첫 그리기·읽기 구간은 29.0→90.2ms로 늘었지만, 준비 비용이 줄어 전체 합계는 단축됐다. 준비된 화면의 모든 그리기/스크롤 시간이 개선됐다고 주장하지 않는다. 곡선 패턴은 별도 8배 확대 검사로 벡터 경계를 비교했다.

원점이 0이 아닌 셀은 이전 Python 비교 추출기가 일부 BBox 클립을 잃어 비교 기준으로 부적절했다. 이 사례는 MuPDF CPU 출력을 기준으로 검증했으며 새 GPU 출력과 평균 차이 0을 확인했다.

## 검증·호환성

- CMYK 검정 성분, 별도 알파, RGB ICC, 공유 변환기의 서로 다른 이미지, 프레임 클립 중 업로드, 고배율 부분 영역과 전체 장면의 일치.
- 패턴 간격·회전·곡선·비영점 원점, Type3 글자 안에서 재배치된 패턴, 겹치는 셀의 기존 경로, 빈 패턴, 큰 셀 수에도 고정된 장면 크기.
- Rust 네이티브 작업자·SQLite·바이너리 캐시 왕복, 잘못된 입력, JPEG 원본과 GPU 마스크 병용.
- 관련 테스트 308개 통과, MSVC `/W4 /WX`와 Rust 확장·작업자 빌드, Python 구문·버전 일치·공백 검사 확인.
- 렌더러 ABI 28, MuPDF 입력 ABI 5, LFSC v4, 디스크 캐시 형식 26으로 동기화한다. 앱/설치 버전은 미배포 1.39.2 유지.

근거 API: [Direct2D ICC 색상 변환](https://learn.microsoft.com/en-us/windows/win32/direct2d/color-management), [명령 목록 기반 이미지 브러시](https://learn.microsoft.com/en-us/windows/win32/api/d2d1_1/nf-d2d1_1-id2d1devicecontext-createimagebrush%28id2d1image_constd2d1_image_brush_properties__constd2d1_brush_properties__id2d1imagebrush%29).
