# 고배율 GPU 이미지 영역 준비 — 2026-10-26

## 변경

앱/설치 프로그램은 미배포 1.37.1, 네이티브 ABI 24를 유지한다. 장면 필드 추가에 따라 디스크 장면 형식은 14로 변경했다.

소스 배율 bucket 4 이상에서 현재 보이는 페이지 영역과 상하좌우 최대 한 화면씩의 이동 여유분을 작업 프로세스에 전달한다. 이미지와 알파 마스크는 기존 다운샘플 격자를 유지한 채 필요한 사각형만 BGRA로 변환·보관한다. 선형 보간 경계에는 소스 texel 2개를 남긴다. 글자·선은 벡터로 유지하며, 복합 삽화의 임시 래스터도 영역으로 제한한다. 타일 패턴 내부 이미지는 반복 좌표 의미를 보존하기 위해 전체 소스 경로를 유지한다.

영역 장면은 뷰가 페이지당 하나만 보유한다. 전체 페이지 메모리/디스크 캐시에 넣지 않는다. 이동으로 준비 영역을 벗어나면 기존 전체 장면(없으면 CPU 미리보기/타일)을 보여주고 새 영역이 준비되면 교체한다. 성공한 영역은 나중에 다시 방문해도 요청할 수 있으며, 편집·문서 전환 시 폐기한다. 최종 GPU 이미지 한도는 기존 64MiB다.

## 실제 PDF / GPU 비교

Windows, Intel Iris Xe 하드웨어 GPU, 기존 네이티브 DLL, 1200×900 화면. 매 측정 새 retained scene을 생성하고 결과 재사용 없이 그리기 완료 + 동기 readback + end_frame을 측정했다. 준비된 그리기는 2회 예열 후 5회 중앙값이다. 초기 준비·업로드 시간은 포함하지 않는다.

ACB2019의 기존 전체 페이지 추출은 800%에서 64MiB 한도로 실패했다. 비교 화면을 만들기 위해 **검증 코드에서만** 전체 추출 한도를 256MiB로 올렸다. 알파 결합의 기존 한도는 유지했고, 이 참고 장면의 이미지 데이터는 232.38MiB였다. 제품 한도는 올리지 않았다. 기존에 저해상도 GPU 장면이 있으면 실패 시 그 장면을 계속 사용하는 동작과, 처음부터 GPU가 불가능한 경우를 구분해야 한다.

첫 시험 영역은 페이지 가로·세로 40% 위치에서 시작한다. 수치는 고유 BGRA 이미지 바이트이며 VRAM이나 앱 전체 메모리가 아니다.

|---|---:|---:|---:|---:|---|
| ACB2019 | 800% | 232.38MiB | 1.149MiB | 21.13ms | 3,620/1,080,000 픽셀, 최대 채널 차이 55 |
| ACB2019 | 1600% | 232.38MiB | 0.296MiB | 18.28ms | 픽셀 일치 |

| ACB2015 | 800% | 35.84MiB | 0.035MiB | 38.46ms | 픽셀 일치 |

영역 크기·위치가 다르면 메모리와 시간도 달라진다. UI의 이동 여유분을 제외한 정확한 화면 영역으로 측정했으므로 실제 UI 이미지 할당은 이 표보다 클 수 있다. 출력 차이에는 좌표 정밀도/보간 및 더 작은 이미지가 기존 알파 결합 한도 안에 들어오면서 생기는 필터링 차이가 포함될 수 있다. CPU 출력과의 완전 일치를 주장하지 않는다.

## 별도 프로세스 메모리 관찰

ACB2019 800%, 첫 시험 영역, 각 새 프로세스 1회 관찰: 한도를 높인 전체 참고 추출 peak RSS 491.20MiB → 영역 추출 258.11MiB. 영역 추출 시간 894.58ms. 전체 참고 추출 1,988.44ms. 기본 한도의 기존 추출은 이미지 한도 초과로 실패하므로 성공한 동일 품질의 기존 제품 경로와 직접 속도 비교할 수 없다. GPU 자원·GUI를 제외한 프로세스이며 단일 관찰값이다.

원본 이미지 디코딩과 일부 색 변환은 아직 전체 원본 크기의 일시 메모리를 사용한다. 이번 변경은 주로 변환 결과·전송·장면 이미지·GPU 업로드를 줄인다. 모든 PDF 효과나 매우 큰 화면을 무조건 GPU로 처리한다는 보장은 없으며 기존 자원 제한과 실패 처리를 유지한다.

## 검증 및 재현 자료

- 합성 PDF: 4방향 회전, 원본 픽셀 격자·알파·벡터 유지, 작은 예산에서 전체 추출 실패/영역 성공.
- 작은 복합 삽화: 보이는 부분만 할당, 화면 밖 이미지 극소화.
- 작업 프로세스: 영역 전달, 전체 페이지 디스크 캐시 우회, 전체 페이지 메모리 캐시 오염 방지.
- 뷰: 이동 시 전체 장면으로 안전하게 전환, 영역 재요청, 성공한 영역 재방문, 문서 초기화 시 해제.
- 개인 PDF와 원시 자료는 `tmp/gpu-viewport/`에만 둔다. `bench.py`, `photo_bench.py`, `memory.py`, JSON 측정값과 PNG가 있으며 배포·커밋 대상이 아니다.

검사 결과: 통합 회귀 328개 통과, 이후 추가한 검사 포함 집중 검사 17개 통과, 독립 네이티브 GPU 검사 9개 통과. 변경 Python 모듈 구문 검사와 `git diff --check` 통과.

## 이동 여유 범위 보강

기본 준비 범위는 3×3화면이다. 투영 면적이 1,200만 픽셀을 넘는 큰 창/고밀도 화면에서는 여유 비율을 줄인다(현재 화면 자체는 잘라내지 않는다). 페이지 경계에서는 범위를 자른다. 남은 여유가 40%가 되면 현재 장면이 아직 화면을 덮고 있어도 다음 준비를 요청한다. 연속 마우스 이동이 120ms 타이머를 계속 뒤로 밀지 않도록 기존 예약 시각을 유지한다. 늦게 도착한 옛 영역이 현재 화면을 덮지 못하면 현재 유효한 장면을 교체하지 않는다.

사진 영역을 상하좌우 한 화면씩 넓힌 추가 추출 검사: ACB2019 800% 2.37MiB, 1600% 0.61MiB, 3200% 0.16MiB. ACB2015 800% 5.73MiB. 모두 기존 64MiB 이미지 한도에서 성공했다. 위 본문 표는 여유분 없는 화면 영역 측정값으로 유지한다. 추가 자료 `tmp/gpu-viewport/pan-margin.json`. ReaderView 검사 81개 통과(선명한 화면 유지 중 선행 준비, 드래그 중 타이머 지연 방지 포함).
