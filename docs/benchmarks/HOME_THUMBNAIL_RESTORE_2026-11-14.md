# 홈 썸네일 재실행 복원

- 실제 캐시를 읽기 전용으로 확인했으며, 저장된 썸네일 10개가 현재 PDF의 파일 정보·엔진 버전과 일치했다. 재실행마다 PDF를 새로 그리는 문제는 확인되지 않았다.
- 기존에는 디스크 캐시가 있어도 별도 PDF 작업 프로세스를 시작하고 엔진을 로드한 뒤 PNG를 하나씩 다시 해독·전송했다. 새 경로는 PDF 엔진을 불러오지 않고 백그라운드에서 저장된 PNG를 묶어서 읽는다. 캐시가 없는 파일만 기존 PDF 작업자로 보낸다.
- 같은 썸네일 10개를 별도 캐시 폴더에 복사하고, 기존·변경 구현을 번갈아 두 번씩 새 서비스 인스턴스로 비교했다. 원본 PDF와 실제 사용자 설정은 변경하지 않았다.

| 캐시 요청 후 시점 | 기존 중앙값 | 변경 중앙값 |
|---|---:|---:|
| 첫 미리보기 준비 | 286.2ms | 20.8ms |
| 10개 모두 준비 | 383.0ms | 20.8ms |

기존 10개 복원은 346.8~419.2ms, 변경은 20.3~21.3ms였다. 변경 경로는 두 번 모두 PDF 작업 프로세스를 시작하지 않았다. 앱 전체 실행 시간과 실제 화면 그리기 시간은 포함하지 않는다. 첫 화면의 기존 80ms 요청 대기도 첫 표시에서 제거했으며, 이 효과는 표에 포함하지 않았다.

원시 자료와 비교 스크립트는 로컬 `.test-runtime/home-thumbnail-startup/`에 보관한다. `restore-results.json`이 정상 비교 결과이며, 초기 비교에서 복사한 코드의 실행 파일 경로가 어긋난 측정은 제외했다.

새 프로세스에서 MuPDF import 없이 복원, RAM에서 밀려난 썸네일 재복원, 미리보기 생성이 필요한 파일보다 캐시 먼저 표시, 잠긴 사용 시각 갱신, 숨긴 화면의 늦은 응답 무시, 손상·과대 PNG의 처리와 기존 캐시 용량·삭제 동작을 검증한다.
