# 읽기 전용 GPU 장면 분석 인덱스 공유 (2026-10-21)

기준은 Leaflet 1.37.0의 네이티브 구현이다. [장면 컴파일러 프로젝트](GPU_SCENE_COMPILER_PLAN.md)의 첫 단계로, 읽기 전용 분석 데이터와 컨텍스트별 실행 상태를 분리한다. 개발 버전은 1.37.1, 공개 ABI는 24다.

## 변경 범위

- bounds, scope index·범위, replay role, cull-block index·범위의 6개 배열을 `ReplayIndex`에 담고 생성 완료 후 `shared_ptr<const ReplayIndex>`로 게시한다. worker 복제는 배열 대신 동일 객체의 참조를 전달한다.
- 일반 command-list 장면에는 분석 객체를 만들지 않는다. GPU 그리기 순서, 마스크 생성→적용 장벽, clip·COPY 보호, 출력 밀도, 타일·gutter와 제출 경계는 그대로다.
- `SceneCommand`와 컨텍스트별 Path/Bitmap/StrokeStyle 래퍼, mutable gradient brush는 아직 작업마다 준비한다. 전체 장면 공유나 새 합성기의 완성을 뜻하지 않는다. 렌더 결과 캐시는 추가하지 않는다.

## 메모리 확인

시간 측정과 별도의 진단 빌드에서 원본과 worker의 인덱스 주소가 같고 공유 소유자 수가 2임을 확인했다. 아래는 장면별 배열의 유효 요소 payload이며 allocator·RSS·VRAM 측정값이 아니다.

| 문서 | native 명령 | scope | cull block | 작업별 배열 복사: 기준 | 공유 후 |
|---|---:|---:|---:|---:|---:|
| ACB 2019 | 324 | 77 | 5 | 10,068byte | 0byte |
| ACB 2015 | 31,302 | 10,864 | 297 | 1,050,414byte (약 1.00MiB) | 0byte |

ACB 2015는 `31,302 × (16 + 4 + 1 + 4) + (10,864 + 297) × 24`다. MSVC x64에서 `Scene`은 272→144byte, 별도 `ReplayIndex`는 144byte다. 인덱스 객체와 공유 제어 블록의 소규모 추가 비용이 있고, 원본 배열은 필요한 작업이 끝날 때까지 살아 있다. 명령·브러시와 GPU 표면 메모리까지 이만큼 줄었다고 해석하지 않는다.

## 비교 조건

- Intel Iris Xe hardware / 1200×900 물리px / 96 DPI / PyMuPDF 1.28.2 / 이미지 준비 배율 1. ACB 두 문서의 첫 페이지를 비교한다.
- 매 표본 새 장면 identity를 사용하고 두 DLL의 실행 순서를 교대한다. 준비 3회 후 요청 반환은 25회, 정밀 전체 완료는 15회 측정했다. 측정 중 다른 GPU 검사·빌드를 실행하지 않았다.
- PDF 해석·immutable geometry/bitmap 업로드·새 retained scene 생성은 아래 타이머 밖이다. 요청 반환에는 현재 UI 경로의 worker context·명령·brush 준비가 포함된다. 전체 완료는 30ms 간격으로 타일 준비·가져오기를 확인한다. Present/vsync와 90ms 입력 안정화는 제외한다.
- P95는 nearest-rank 값이다. 과거의 441ms나 다른 회차와 직접 빼지 않는다. 이 변경은 GPU 합성 명령을 바꾸지 않으므로 완료 시간의 변동을 전부 인덱스 공유 효과로 단정할 수 없다.

- 측정 후보 DLL SHA-256: `dea2de45c8111bf3688ef7720ca76ae635d0e25797cd6971e69a6bebc4e3e157`. 저장소의 최종 C++ 소스와 동일하며 빌드 경로는 다르다.
