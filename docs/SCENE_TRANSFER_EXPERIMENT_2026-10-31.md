# 장면 전달 형식 첫 비교

2026-10-31 · 미배포 1.37.3 · Rust 1·2번 적용 상태

## 후보와 결과

개인 worker의 pickle 전달에서 경로 명령 tuple을 float64 바이너리로 묶고,
수신 측 Rust에서 원래 tuple로 복원하는 후보를 구현했다. 스타일·이미지·그룹은
기존 pickle로 전달하고 동일 commands 객체는 전송 중 한 번만 인코딩했다.
명령 태그와 좌표의 가변 길이 레코드를 사용하며 float32 근사는 하지 않았다.

| 문서 | 기존 왕복 중앙값 | 후보 왕복 중앙값 | 기존 크기 → 후보 크기 |
|---|---:|---:|---:|
| ACB 2015 | 96.13ms | 137.23ms | 8,930,921 → 7,751,139 bytes |
| ACB 2019 | 89.56ms | 133.16ms | 28,557,127 → 27,889,364 bytes |

왕복은 메모리 내 직렬화 + 역직렬화이며 파일 입출력, PDF 추출, 프로세스 시작,
GPU 업로드·그리기를 포함하지 않는다. 각 문서에서 워밍업 3회 후 Python/후보 순서를
번갈아 7회씩 비교했고 각 표본 전에 GC를 실행했다(GC는 타이머 밖).
모든 복원 결과가 전체 VectorPage와 같음을 검사했다.

2015는 약 43%, 2019는 약 49% 느려져 **기본 경로에 채택하지 않았다**.
인코딩 중앙값은 2015 48.37→74.86ms, 2019 50.13→95.62ms였다.
복원도 각각 51.61→52.74ms, 39.10→42.69ms로 개선되지 않았다.
부분별 중앙값의 합과 왕복 중앙값은 동일하지 않을 수 있다.

이 후보는 전송 크기를 줄이지만 송신 전에 기존 Python 명령을 다시 순회하고,
수신 후 Python float/tuple을 다시 생성한다. Python pickle 자체도 C 구현이어서
Rust로 인코더만 바꾸는 것으로는 이 추가 비용을 상쇄하지 못했다.

제품은 기존 pickle 전달과 앞서 검증한 Rust 1·2번 구현을 유지한다.
실험용 encoder/decoder는 기본 확장에서 제거하고 다시 빌드했다.
경로 packing·geometry 경계값 테스트 7개가 통과했다. 버전 변경은 없다.

## 후속 구조의 조건

추가 후보는 수신 측에서 tuple로 복원하지 않고 packed 경로를 그대로 네이티브
도형 생성에 넘기는 것이다. 현재 리더의 경로 hash/중복 제거, 클립 판별,
장면 비용 계산, 이미지 재추출 recipe 및 디스크 캐시가 commands tuple을 사용한다.
이 소비 지점들을 함께 바꾸고 최초 추출부터 GPU 준비까지의 전체 비용을 비교해야 한다.
이번 결과는 그 구조 전체의 실패나 성공을 판정한 것이 아니다.

비공개 입력·원자료는 `tmp/rust-audit/transfer-results.json`에 보관한다.
실험용 Python 모듈과 Rust 소스는 `transfer-experiment/`, 비교 스크립트는
`transfer_bench.py`에 보관했다. 재실행 시 candidate_lib.rs로 별도 확장을 빌드해야 한다.
