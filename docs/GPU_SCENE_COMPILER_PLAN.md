# GPU 장면 컴파일러 구조 개편 — 천지개벽

시작: 2026-10-21 · 기준: Leaflet 1.37.0 · 첫 개발 버전: 1.37.1

목표는 복잡한 PDF를 그리는 파이프라인 자체의 준비·복사·합성 비용을 줄이는 것이다.
렌더 결과 캐시를 늘리는 작업과 구분한다. 현재 구현은 README, 단계별 설계와 검증 기준은 이 문서를 따른다.

## 1. 읽기 전용 장면과 실행 자원 분리

- 첫 구현: 명령 bounds, scope 인덱스·범위, 실행 role, cull block 인덱스·범위 6개 배열을 `ReplayIndex`로 묶는다. 생성 중에만 수정하고 `shared_ptr<const ReplayIndex>`로 게시한다. 작업 스레드는 동일 객체의 수명만 공유한다.
- 범위·마스크 전환·합성 순서는 1.37.0과 같다. 일반 command-list 경로에는 분석 객체를 추가 생성하지 않는다.
- 다음 구현: 전체 명령·gradient stop·transfer table·불변 자원 참조를 `SceneData`에 담아 읽기 전용으로 게시했다. 명령의 외부 resource/data 포인터는 남기지 않고 내부 binding index로 컨텍스트별 실행 자원을 연결한다. 빈 레이어 정리를 마친 뒤 인덱스를 지정한다.
- 경로·bitmap·stroke의 context 소유 래퍼와 mutable gradient brush는 `SceneBinding`으로 분리했다. 자원이 필요한 명령만 이 테이블에 들어간다. 정밀 작업 제출은 arena와 분석 데이터의 참조만 공유하고, binding 준비는 GPU 작업 스레드에서 수행한다. 취소를 주기적으로 확인하고 메모리·장치 오류를 기존 비동기 상태 경로로 보고한다.
- arena에는 같은 D2D 장치에서 쓸 수 있는 geometry/bitmap 등의 불변 COM 참조가 포함된다. 장치 사이에서 공유하거나 그대로 직렬화하는 순수 CPU 장면 형식까지 구현한 것은 아니다. worker context 초기화와 Python→네이티브 장면 생성도 아직 UI 경로에 남는다.
- 다음 작업: 명령·가변 데이터의 더 작은 연속 형식을 검토한다. 초기 Python→네이티브 전달, 원본 binding, 작업 context 초기화와 worker binding 시간을 구분해 측정한다.

## 2. 타일별 실행 계획

- 전체 명령을 타일마다 순회하는 대신 실제로 교차하는 명령과 필요한 조상 그룹·clip·mask 의존성을 연결한다.
- PDF 표시 순서를 유지하며 mask 생성→적용, backdrop 의존 혼합, COPY·knockout·비격리 그룹을 명시적인 장벽으로 다룬다. bbox만 보고 상태 전환을 생략하지 않는다.
- 타일 계획과 임시 버퍼의 메모리 상한·회수 정책을 명시한다. 전체 문서를 미리 그리거나 모든 페이지의 계획을 상주시켜서는 안 된다.
- 구현: 타일마다 기존 보수적 culling과 같은 순서로 명령 인덱스를 고르고, 상태 전환과 조상 의존성을 유지한 채 실행한다. COPY·knockout·비격리·마스크 아래의 빈 그룹은 유지하고, 영향 없는 격리 Normal 그룹만 제거할 수 있다.
- 해당 타일에서 선택한 자원 명령만 worker binding을 만든다. 다음 타일은 부족한 항목을 추가 준비하며 작업 종료 시 테이블을 회수한다. 원본 UI 장면의 binding은 기존처럼 전체를 준비한다. 결과 이미지 캐시는 추가하지 않는다.
- 선택 콘텐츠 범위로 격리 Normal 소스를 더 작게 잡는 후보도 비교했다. ACB 2015 맞춤에서 소스 면적은 약 5.6% 줄었지만 속도 이득이 확인되지 않고 경계 픽셀 차이가 생겨 적용에서 제외했다. 기존 합성 범위·순서·Flush 경계·벡터 밀도를 유지한다.
- 입력 명령 1,048,576개·깊이 4096개를 제한한다. 한 타일의 계획만 보관하며, 한도·구조·할당 실패 시 전체 binding과 기존 replay로 돌아간다. 한도는 항목 수이며 allocator까지 포함한 정확한 byte 상한은 아니다.

## 3. GPU 합성 실행기

- 단순 그룹부터 타일 계획을 실행하는 전용 합성 경로를 도입한다. 벡터·글자 래스터화는 검증한 Direct2D 경로를 이용하고, 지원하지 않는 합성은 기존 경로로 처리한다.
- 임시 표면·backdrop·coverage의 생존 구간과 제출 의존성을 계획에서 결정한다. Flush 제거 또는 호출 수 감소만으로 채택하지 않고 GPU 완료 시간과 출력으로 판단한다.
- 취소·창 닫기·문서 세대 변경 시 작업과 공유 데이터가 안전하게 해제되어야 한다. UI가 worker 완료를 기다리게 만들지 않는다.
- 2026-10-23 [중첩 마스크 합성 실험](GPU_NESTED_MASK_BENCHMARK_2026-10-23.md): 같은 배경·크기·원점의 단독 자식 clip/mask 두 단계를 한 셰이더로 처리하고 각 항의 UNORM8 반올림을 유지했다. 실제 통합은 ACB 2015에서 8~12쌍/프레임으로 제한됐고 복사 픽셀은 3~18% 줄었지만 완료 시간 이득이 재현되지 않아 기본 경로에 채택하지 않았다. 검증한 후보를 별도로 보관했다. 다음 계측은 수많은 작은 그룹의 복사·제출 비용과 그리기 실행 시간을 분리하는 것이다.
- 같은 날 [구간별 계측](GPU_STAGE_PROFILE_2026-10-23.md)을 완료했다. ACB 2015에서 명시적 Flush와 scratch 준비가 worker 경과 시간의 약 78~80%, 복사 호출 자체는 약 2~3%였다. scratch 새 할당은 프레임당 674~1,416개이고 복사의 95~98%가 4096픽셀 이하였다. 다음 후보는 작업 내 표면 생존 구간을 계획해 저장소를 묶어 준비하고 전용 합성기의 제출 경계를 줄이는 것이다. GPU timestamp는 CPU 공급 공백을 포함할 수 있는 timeline이며 셰이더·복사 엔진의 활성 시간을 완전히 분리한 값은 아니다. 기본 렌더 동작은 유지했다.
- 후속 [수명 계획·묶음 할당 비교](GPU_SURFACE_LIFETIME_BENCHMARK_2026-10-23.md)에서 타일별 임시 표면 계획과 D3D11 texture-array 할당을 구현하고 최대 256슬롯 방식을 채택했다. 기존 scratch와 byte 예산을 공유하고 계획 부족·할당 실패는 원래 경로로 처리한다. 직접 isolated clip source는 기존 할당을 유지하며 합성 순서·Flush 경계는 바꾸지 않는다. 최종 ACB 2015 맞춤 시간은 거의 같고 100%·200%는 약 28%·23% 단축됐다. 별도 진단의 peak RSS는 약 25MiB 낮았으나 DXGI 사용량은 모든 조건에서 줄지 않았다. 더 빠르지만 메모리가 늘어난 4096슬롯 후보는 기본으로 선택하지 않았다.
- [D3D11 직접 합성 실험](GPU_DIRECT_D3D11_BENCHMARK_2026-10-23.md)에서는 마지막 clip/mask 합성을 직접 Draw로 옮기고 배경 복사 유지·결과 복사 두 방식을 비교했다. 정적 장치 자원 공유, 상태 복원·잠금, unsupported fallback과 픽셀 일치를 검증했지만 완료 시간 이득이 재현되지 않았다. 결과 복사 재측정에서 ACB 2015 맞춤·200%는 약 22%·38% 느려져 채택하지 않았다. 별도 비계측 메모리 관찰에서는 peak RSS가 약 38MiB 낮았다. 현재 256슬롯/D2D 합성은 유지하며, 더 큰 독립 패스를 묶어 전환·제출을 줄이는 전용 실행기는 후속 과제다.

## 4. 구조 안정화 이후의 개선

- 후속 [작은 복합 삽화 소스 컴파일](GPU_COMPLEX_REGION_COMPILER_BENCHMARK_2026-10-23.md)을 기본 GPU 장면 추출에 적용했다. 작은 isolated knockout 후보만 원래 callback에서 기록하고 복잡한 경우 그 그룹 자체를 투명 이미지로 바꾸며, 주변 글자·배경·clip·후속 객체는 기존 GPU 순서로 유지한다. 전체 사전 조사와 전체 페이지 crop 덮어쓰기를 사용하지 않는다. 새 소스는 장면당 64개/8MiB와 기존 전체 이미지 예산을 공유한다. ACB 2015 새 PDF부터 준비·upload·정밀 완료까지 7회 중앙값은 3.06→1.87초, 별도 peak RSS는 약 160MiB 낮았다. 색·AA 차이를 허용한 변경이며 2019 화면은 byte 일치했다. scene format은 11로 바꿨고 ABI 24는 유지한다.
- 2026-10-23 [작은 복합 삽화의 영역 단순화 조사](GPU_COMPLEX_REGION_SIMPLIFICATION_2026-10-23.md): ACB 2015의 작은 knockout 그룹 25개가 Python 장면 항목의 86%를 차지했다. 이를 7개 영역으로 묶어 매 작업마다 CPU crop을 새로 만들고 나머지를 GPU로 그리는 개인 실험은, crop·업로드·새 장면 생성·완료·진단 readback을 합친 중앙값을 두 비교에서 약 59~75% 줄였다. 색·경계 차이가 크고 최초 display list 생성·장면 추출 비용은 별도이며 긴 지연도 남아 있어 기본 동작에는 적용하지 않았다. 원본에 대한 픽셀 일치 조건을 완화한 후보 탐색이며, 결과 캐시를 재사용한 개선은 아니다. 공개 분석 도구를 추가했고, 다음 제품 후보는 작은 복합 그룹을 Python 명령으로 전부 확장하기 전에 선택하는 영역 실행 계획이다.
- 투명 그래디언트 근사는 이 단계에서 검토한다. 표현 가능한 색·알파 gradient 결합, 적응형 LUT와 부드러운 mask 해상도 조정을 각각 측정한다.
- 글자·벡터·하드 클립의 출력 밀도를 유지한다. 비선형 transfer와 급격한 알파 변화는 별도로 보호한다.
- 오차 허용 기준과 적용 조건, 원래 합성으로 되돌아가는 조건을 확정한 뒤 기본 적용 여부를 정한다.
- 2026-10-22 [마스크 정수화·저정밀 실험](GPU_MASK_PRECISION_BENCHMARK_2026-10-22.md)에서 마지막 마스크 합성의 산술 형식만 따로 비교했다. 정수화는 화면을 유지했지만 완료 시간이 조건별로 섞였고 중간 화면 메모리는 같았다. min16은 반올림·경계 검사를 일부 실패해 기본 strict float를 유지한다. gradient 생성이나 복잡한 혼합 전체의 근사를 채택한 것은 아니다.

## 단계별 채택 기준

- 동일 ACB 2019·2015 포스터, 1200×900 viewport, 맞춤·100%·200%, 새 장면을 매 표본마다 만든다. 문서와 결과물은 소스에 포함하지 않는다.
- 초기 장면 생성, 작업 제출, 첫 타일, 전체 정밀 완료, GPU 진단 readback을 구분한다. 중앙값과 P95를 함께 기록하고 측정 중 다른 GPU 검사·빌드를 실행하지 않는다.
- 첫 단계는 1.37.0 대비 BGRA 완전 일치를 확인한다. 이후 의도한 반올림 변경과 근사는 별도 비교로 기록한다.
- 배열·버퍼 용량 감소와 RSS/commit/VRAM 실측을 구분한다. 컨텍스트별 자원 복사와 공유 객체의 추가 비용도 포함해 설명한다.
- 기존 GPU 검사에 작업 교체·원본 해제·DPI 변경·취소 검사를 더한다. 공개 ABI와 CPU fallback을 유지한다.

진행 상태: 분석 인덱스 공유와 읽기 전용 명령 arena에 이어 타일 계획과 선택 binding을 구현했다. [타일 단계 비교](GPU_TILE_PLAN_BENCHMARK_2026-10-21.md)에 후보별 속도·자원 준비·픽셀 차이와 한계를 기록한다. [arena 단계 비교](GPU_SCENE_ARENA_BENCHMARK_2026-10-21.md)의 UI 요청 개선과 명령·테이블 절감은 이전 단계의 결과이며, 전체 GPU 완료 개선과 구분한다. 첫 분석 공유 단계의 [비교와 한계](GPU_SHARED_INDEX_BENCHMARK_2026-10-21.md)도 이력으로 보존한다. 전용 합성기·투명 그래디언트 근사는 후속 단계다.
