# 미세 격리 효과 합성 생략 실험 — 기본 적용 보류 (2026-10-20)

기준은 main의 a8dbd37 DLL(범위 인덱스 단순화까지 포함)이다. 이 후보는 화면에서 기여가 작은 복잡한 효과를 생략하는 근사화다. 두 회차에서 화면 맞춤 성능이 +4.8% 단축과 -10.9% 악화로 엇갈려 기본 적용을 보류하고 소스·DLL을 기준 상태로 되돌렸다. 아래 구현과 검사는 로컬 실험판에 대한 기록이다. 렌더 결과 재사용이나 전체 타일 해상도 축소는 추가하지 않는다. 앱·설치 프로그램은 미배포 1.37.0, 공개 ABI는 24다.

## 구현과 품질 기준

- 기존 Normal 격리 그룹·단일 도형 클립 통합 대상 중, 클립의 변환된 경계가 가로·세로 각각 1물리px 이내이며 면적이 1/4px 이하일 때 그룹 전체를 건너뛴다. 일반 단일 glyph·벡터 경로, 큰 효과와 기존 simple layer 경로는 이 근사화 대상이 아니다.
- 변환된 클립의 실제 경계를 사용한다. 회전·shear의 축 정렬 외접 경계로 검사하며 DPI를 물리 픽셀로 환산한다. 축소 화면에서 생략한 효과도 확대되어 기준을 넘으면 원래 명령으로 합성한다.
- 각 타일에서 1byte/물리px 표를 비우고, 생략한 그룹의 경계가 닿는 모든 픽셀을 표시한다. 이미 표시된 픽셀에 닿는 후속 그룹은 실행한다. 여러 미세 효과가 같은 픽셀에 겹칠 때 모두 사라지는 것을 막는다. 이 표는 렌더 결과를 저장하지 않으며, 최대 516×516 타일에서 약 260KiB의 CPU 메모리를 쓴다. 할당 실패 시 근사화를 중지한다.
- 현재 primitive가 COPY이면 적용하지 않는다. 마스크 생성 중인 조상이나 혼합 모드가 Normal이 아닌 조상이 있어도 생략하지 않는다. 장면 전체에 Normal/Multiply/Screen 이외의 혼합이 하나라도 있으면 이후 비선형 합성에 작은 차이가 증폭될 수 있어 근사화를 끈다. worker 복제에도 이 판정을 전달한다.
- 범위 끝이 부분 replay 요청을 넘으면 건너뛰지 않는다. 원래 512px 타일·2px gutter와 명령 취소 처리는 유지한다. 직접 장면 재생 API, CPU 표시, PDF 저장·인쇄 내용은 바꾸지 않는다.
- **픽셀 완전 일치를 보장하는 최적화가 아니다.** 미세 효과가 옅어지거나 없어질 수 있다. 경계 면적 제한이나 픽셀당 한 번이라는 조건을 전체 문서의 채널 오차 수학적 보장으로 해석하지 않는다. 아래의 실제 ACB 비교와 별도 합성 검증을 구분한다.

## 비교 조건

- Windows / Intel Iris Xe hardware / PyMuPDF 1.28.2 / 숨김 HWND / 1200×900 물리px / 96 DPI. ACB 2019·2015 첫 페이지의 화면 맞춤·100%·200%를 비교하며 이미지 준비 배율은 1이다.
- 최종 조건당 준비 3회 + 측정 15회, 두 회차. 기준/후보를 번갈아 실행하고 순서를 교대하며, 두 번째 회차는 DLL 준비 순서도 뒤집는다. 측정 중 GPU 테스트·빌드를 병행하지 않는다.
- 매 표본 새 장면 identity로 페이지·그룹·기존 정밀 타일 결과 재사용을 막는다. immutable geometry·이미지 업로드는 타이머 밖에서 준비한다.
- 정밀 요청부터 viewport atlas 준비·가져오기 완료까지다. 원래 30ms 완료 확인 간격을 사용한다. 최초 PDF 열기·추출·업로드·확대 이미지 재추출, 입력 안정화 90ms와 Present/vsync는 제외한다. P95는 nearest-rank 값이다.
- 절대시간은 시스템/GPU 부하에 따라 달라지므로 과거의 441ms나 예비 후보와 직접 빼지 않고 같은 회차의 두 DLL을 비교한다. 전체 파일 열기 속도나 연속 스크롤 FPS 측정은 아니다.

ACB 2015의 전체 완료 중앙값 감소율은 화면 맞춤 -10.9~+4.8%, 100% +0.7~+5.4%, 200% +1.1~+13.8%. 양수는 단축이며 음수는 악화다. 문서·배율별 차이와 P95를 함께 해석하고 모든 GPU/PDF의 가속률로 일반화하지 않는다.

## 후보 선택과 구조 확인

- ACB 2015 상위 장면의 Normal 격리 그룹+직후 클립에서 화면 맞춤 투영 경계 면적이 1px 이하인 구조는 1,455개였다. native simple 경로·예외 조건이 있으므로 실제 생략 횟수와 같지 않다. ACB 2019에는 이런 작은 그룹 구조가 없다.
- 기존 aggressive band merge 실험도 켜 보았으나 두 포스터의 추출 항목 수는 각각 323개·33,260개로 같아 이번 대상의 명령량을 줄이지 못했다. 실험판에도 그 설정을 켜지 않았다.
- 별도 준비 3회+측정 5회 예비 표본에서 면적 한도 1/64, 1/16, 1/4px를 비교했다. 이 초기 세 후보는 같은 픽셀에서 누적 면적만 제한하는 버전이며 최종의 픽셀당 한 번 조건과 다르다.

| 면적 한도 | ACB 2015 화면 맞춤 | 100% | 200% |
|---|---:|---:|---:|
| 기준 a8dbd37 | 656.30ms | 347.83ms | 440.66ms |

- 이 예비 세 후보의 세 보기 BGRA는 모두 기준과 같았다. 최종 성능 판단에는 위 최종 후보 두 회차만 사용한다.
- 초기 1/4px 후보의 별도 진단 DLL에서 ACB 2015 화면 맞춤 한 번을 실행했을 때 중앙 타일은 검사 241개·면적 통과 99개·생략 99개, 다른 한 타일은 검사 16개·통과/생략 각 2개였다. 나머지 7개 타일은 0개였다. 진단 계측 시간은 성능 표에 섞지 않는다. 이 101개는 최종 픽셀당 한 번 정책의 횟수로 주장하지 않는다.
- 최종 픽셀당 한 번 정책의 별도 진단에서는 중앙 타일 검사 278개·면적 통과 136개·생략 62개, 다른 한 타일은 16개·2개·2개였다. 나머지 7개는 0개여서 viewport 전체에서 64개 그룹 합성을 생략했다. 부모가 실행되면 하위 그룹도 검사하므로 초기 후보와 검사 수가 다르다. 이는 해당 화면 맞춤 한 번의 명령 수 확인이며 모든 표본/배율의 횟수로 일반화하지 않는다.

## 적용 판단

- ACB 2015 화면 맞춤에서 회차별 방향이 달랐고, 100%의 감소 폭은 0.7~5.4%에 머물렀다. 확대 200%의 1.1~13.8% 감소만으로 범용 이득을 확정하지 않는다.
- 실제 ACB 저장 화면 12개는 기준과 모두 일치했지만, 합성된 최악 조건에서 채널 차이 64까지 허용해야 하는 후보였다. 일관된 이득에 비해 품질 부담이 커 기본 경로로 채택하지 않았다.
- ACB 2019에는 생략 가능한 미세 그룹이 없다. 2회차 100%의 40.7% 차이는 이 최적화의 효과로 설명할 수 없으며 30ms 폴링과 실행 변동이 포함된 값이다.
- 실험 소스·DLL·추가 회귀 검사는 로컬 `tmp/gpu-approx-20261020/retired-subpixel`에 보존했다. 이 보고서에 기록된 근사화는 배포 코드에 포함하지 않는다.

## 실험판 회귀 검사·한계

- 관련 테스트 102개 통과: gpu_raster 80개, d2d_backend 9개, gpu_composite_integration 13개. 기존 마스크·15 blend mode·UNORM8 반올림·viewport culling·중첩·고DPI·취소 검사를 포함한다.
- 새 겹침·예외 검사는 DPI 2개×상태 6개×반복 3개×변환 4개=144개 조건을 같은 worker·타일에서 일반 합성과 비교한다. 128개 미세 효과가 겹쳐도 모두 없어지지 않고, COPY·비격리 부모·현재/뒤이은 비선형 혼합·hard-step soft mask를 보존하는지 확인한다. 일반 기준은 투명 형제 그리기로 단일 자식 조건을 해제한다.
- 0.49×0.49px 효과는 생략하고 0.51×0.51px 효과는 원래대로 그리는 경계 검사를 추가했다. 불리한 단색 합성의 허용 최대 채널 차이는 전자 64, 후자 3이다. 따라서 일반 PDF의 모든 픽셀이 몇 단계 이내로만 달라진다고 보장하지 않는다.
- 600×100 viewport의 타일 경계(x=44, 556) 양쪽에 미세 효과를 8회씩 겹치고, 분수 이동·반사에서 일반 합성과 최대 채널 차이 8 이하를 확인한다. 위 144개 미세 효과 검사도 허용 차이는 8이다. 별도 private 동일 조건 검사에서 일반 상태 최대 차이는 1, 비격리 부모는 2였고 보호 경로는 0이었다.
- C++ /W4 /WX 및 FXC ps_4_0 /Gis 빌드, Python 구문 검사와 git diff --check를 확인한다. GPU timestamp·VRAM 최고 사용량은 측정하지 않았다. 프로세스 RSS/commit은 두 DLL을 함께 가진 값이다.
- 저장 화면은 조건별 첫 준비 실행(index 0)이다. 모든 반복 표본의 픽셀이나 모든 PDF·장치의 품질 보장이 아니다.
