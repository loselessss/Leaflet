# 화면 밖 명령 묶음 제외 비교 (2026-10-19)

직전 파이프라인 최적화가 적용된 1.37.0 개발 DLL과, 그 위에 화면 밖 명령 묶음 제외를 추가한 DLL을 비교했다. 이전 보고서의 main 4901da6 기준과 혼동하지 않는다.

ACB 2015의 화면 맞춤 완료 중앙값은 두 차례 모두 약 16~17% 줄었다. 100%는 약 3~6% 줄었지만 긴 지연과 첫 타일에서 일관된 우위는 없었다. 200%와 ACB 2019의 중앙값 차이는 작아 뚜렷한 가속으로 해석하지 않는다.

## 구현

- 기존에는 개별 명령·단일 그룹을 제외했다. 이번 후보는 같은 단계에 있는 연속 그리기 명령과 완결된 하위 범위를 보수적인 합집합 경계로 묶어, 보이지 않는 묶음의 명령 순회·개별 검사도 한 번에 건너뛴다.
- 묶음은 약 128개 명령 구간을 기준으로 나누고, 32개 미만인 짧은 구간이나 단일 항목은 별도 묶음으로 만들지 않는다. 원래 명령과 표시 순서는 유지한다.
- 마스크 생성→적용 전환과 확인할 수 없는 경계에서 묶음을 끊는다. 미완결 범위의 index는 버리며, 부분 재생 요청의 끝을 넘어가지 않는다.
- 새 index는 명령 위치·범위 끝·페이지 경계만 보유하고 새 장면과 함께 만들며 worker에 복사한다. 픽셀 결과 캐시를 추가하지 않는다. 기존 보이는 영역·2px 여유·회전·DPI·투명도 합성은 유지한다.
- 정밀 worker에 적용하며 일반 화면의 품질 단계나 파일 저장 내용은 바꾸지 않는다. 기존 개별 제외도 그대로 수행하므로 GPU 그리기 호출 감소량을 이번 측정에서 별도로 주장하지 않는다.

## 조건

- Windows / Intel Iris Xe hardware / PyMuPDF 1.28.2 / 1200×900 물리 픽셀 / 96 DPI.
- ACB 2019·2015 첫 페이지를 화면 중앙에 맞추고 화면 맞춤·100%·200%를 비교한다. 이미지 준비 배율은 1로 고정하고 확대 후 이미지 재추출은 제외한다.
- 매번 새 장면 identity를 사용해 페이지·그룹·이전 정밀 타일 결과를 재사용하지 않는다. 공통으로 준비한 geometry·이미지 업로드 자원은 유지한다.
- 조건당 준비 3회 + 측정 15회. 두 DLL을 번갈아 실행하고 순서를 교대한다. 별도 프로세스로 한 차례 더 반복하되 두 DLL의 준비 순서도 뒤집었다. 조건당 총 30개 표본을 얻었다. 표는 각 회차의 15개 표본을 따로 보여준다.
- 실제 리더의 30ms 완료 확인 간격을 사용한다. 시간은 정밀 작업 요청부터 전체 viewport atlas의 준비·가져오기 완료까지이며, 확인 대기와 타일 가져오기가 포함된다. 최초 PDF 열기·추출·업로드·90ms 입력 안정화·화면 Present/vsync는 제외한다. FPS나 전체 파일 열기 가속 수치가 아니다.
- 비교 중 다른 테스트·빌드를 동시에 실행하지 않았다. 회차 사이에도 시스템/GPU 상태가 달라 절대시간이 변하므로 같은 회차의 전후를 비교한다. 수 ms 차이는 확실한 개선으로 간주하지 않는다.

## 해석과 한계

- 이 후보는 ACB 2015 화면 맞춤에서 재측정해도 같은 방향의 개선이 있어 유지한다. ACB 2019와 200% 확대에서는 큰 차이를 확인하지 못했다. 개별 제외가 이미 적용된 경로이므로 주로 남은 명령 순회·검사 비용을 줄이는 변경이다.
- GPU 단계별 timestamp나 하드웨어별 통계 검정은 수행하지 않았다. 시스템 상태에 따른 표본 편차가 크므로 특정 GPU 작업을 병목으로 확정하거나 전체 PDF의 개선율로 확대하지 않는다.
- RAM 수치는 두 DLL의 렌더러를 함께 보유한 프로세스의 누적 peak RSS다. 빌드별 메모리 비교가 아니며 VRAM 최고 사용량은 측정하지 않았다. GPU 결과 캐시나 픽셀 해상도는 늘리지 않았다.

- 1회차 ACB 2019까지 peak RSS: 749.1 MiB.
- 1회차 ACB 2015까지 peak RSS: 1161.3 MiB.
- 2회차 ACB 2019까지 peak RSS: 743.8 MiB.
- 2회차 ACB 2015까지 peak RSS: 1293.9 MiB.

## 재현 및 로컬 자료

```powershell
.venv/Scripts/python.exe -m tests.benchmark_gpu_pipeline <PDF_2019> <PDF_2015> `
  --library previous=tmp/gpu-cull-20261019/baseline.dll `
  --library culling=native/bin/spdf_d2d_renderer.dll `
  --output tmp/gpu-cull-20261019/comparison --repeats 15 --poll-ms 30
```

두 번째는 --library 순서를 뒤집고 출력 폴더를 confirmation으로 바꾼다. 원시 표본·DLL 해시는 각 폴더의 results.json, 첫 출력은 빌드별 BGRA에 있다. 픽셀 비교는 로컬 tmp/gpu-cull-20261019/pixel_comparison.json에 있다. 원본 PDF·화면·기준 DLL은 소스 관리에 포함하지 않는다.
