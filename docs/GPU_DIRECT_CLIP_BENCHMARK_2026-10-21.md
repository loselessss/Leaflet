# 빈 GPU 명령 제거·직접 도형 클립 합성 비교 (2026-10-21)

기준은 main의 a8dbd37 DLL이다. 렌더 결과 재사용을 늘리지 않고, 장면의 빈 native 레이어 명령과 격리 그룹의 중간 coverage 비트맵을 줄인다. 앱·설치 프로그램은 미배포 1.37.0, 공개 ABI는 24를 유지한다.

## 구현과 적용 범위

- 장면 생성 때 명령이 없는 native 도형/사각 클립과 불투명도 레이어의 시작·종료 쌍을 제거한다. 안쪽 레이어만 있었던 빈 바깥 레이어도 제거한다. 명령 배열을 축소한 뒤 범위·제외 인덱스를 만들므로 원본과 worker의 명령 보관·복사·검색 대상이 함께 줄어든다.
- 리소스 소유권 검사를 마친 명령만 처리하며 잘못된 사각형·불투명도·비유한 변환은 제거하지 않는다. 캡처 기반 composite/mask 범위와 그 안의 build/apply 전환은 비어 보여도 보존한다. COPY나 backdrop에 영향을 줄 수 있기 때문이다.
- 기존 Normal 격리 그룹·단일 도형 클립 통합 대상에서 별도의 coverage 비트맵을 없앤다. 자식 명령을 투명 source에 그린 뒤, bitmap brush와 FillGeometry로 원래 도형과 그룹 불투명도를 한 번에 적용한다. 중간 mask 할당·clear·래스터화와 FillOpacityMask 경로를 줄인다. 실제 GPU pass 수를 timestamp로 측정한 주장은 아니다.
- cropped source의 원점을 역행렬로 brush 좌표에 맞춘다. 부모로 복원할 좌표와 클립을 그릴 좌표를 별도로 보관해 중첩 그룹에서도 같은 위치에 합성한다. antialiasing은 유지하지만 UNORM8 경계 반올림은 소폭 달라질 수 있다.
- 원래 COPY·마스크 생성 보호 조건과 simple layer 경로, 전체 target 사각형 생략은 유지한다. 유한한 역행렬이 없는 변환은 일반 합성으로 처리한다. 풀의 source를 다시 쓰기 전 Flush는 남긴다.
- 미세 효과 자체를 없애거나 타일 해상도를 낮추지 않는다. 직접 재생 API는 기존 캡처 합성을 유지하고, 빈 native 레이어 정리만 함께 적용한다. PDF 저장·인쇄 내용, 512px 타일·2px gutter, 기존 결과 캐시 정책은 바꾸지 않는다.

## 메모리 구조 확인

별도 진단 DLL로 ACB 2015 장면의 native 컨테이너 크기·capacity·요소 크기를 기록했다. 진단 파일은 같은 장면 생성 두 번을 기록하므로 행을 합산하지 않고 장면 하나를 비교한다. 이 계측 DLL의 시간은 성능 표에 사용하지 않는다.

| 항목 | 기준 | 최종 |
|---|---:|---:|
| native 명령 수·capacity | 33,270 | 31,302 |
| 제거한 명령 | — | 1,968개: 빈 사각 클립 984쌍 |
| 명령 요소 크기 | 200byte | 200byte |
| 유효 scope 수 | 10,864 | 10,864 |
| 명령별 보조 배열 요소 합계 | 25byte | 25byte |

- 보조 배열은 bounds 16byte, scope index 4byte, cull-block index 4byte, replay role 1byte다. 원본 장면 하나에서 명령·배열 저장 공간이 `1,968 × 225 = 442,800byte`, 약 **0.42MiB** 줄었다. 같은 명령·배열을 가진 worker 복사본 하나까지 합하면 약 **0.84MiB**다. scope/cull-block 저장 공간은 이 감소량에 포함하지 않는다.
- eligible 격리 클립의 GPU capture는 source+mask 두 비트맵에서 source 하나로 줄었다. 같은 크기라면 그 capture의 픽셀 저장량은 절반이며, 516×516 최대 타일 크기의 비트맵 하나는 약 **1.02MiB**다. 실제 절약량은 클립 crop 크기와 동시에 열린 그룹 수에 따라 달라진다. 모든 그룹이 최대 타일 크기인 것은 아니다.
- 장면 생성 시 배열 축소는 일시적인 재할당을 할 수 있다. 위 CPU 수치는 유지되는 컨테이너 저장량이고 GPU 수치는 해당 capture의 픽셀 payload다. 드라이버·allocator·scratch pool을 포함한 프로세스 RSS/실제 VRAM 전체가 같은 양만큼 줄었다는 측정은 아니다. capture에 추가된 geometry 참조·좌표의 소규모 메타데이터도 전체 메모리 주장과 구분한다.

## 비교 조건

- Windows / Intel Iris Xe hardware / PyMuPDF 1.28.2 / 숨김 HWND / 1200×900 물리px / 96 DPI. ACB 2019·2015 첫 페이지의 화면 맞춤·100%·200%를 비교한다. 이미지 준비 배율은 1이다.
- 조건당 준비 3회+측정 15회. 두 DLL을 번갈아 실행하고 순서를 교대한다. 확인 회차에서는 초기 DLL 준비 순서도 반대로 둔다. 측정 중 GPU 테스트·빌드·PNG 분석을 병행하지 않는다.
- 매 표본 새 장면 identity를 사용해 페이지·그룹·정밀 타일 결과 재사용을 막는다. immutable geometry·이미지 업로드는 타이머 밖이다. 요청부터 viewport atlas 준비·가져오기 완료를 30ms 간격으로 확인한다.
- 최초 PDF 열기·추출·업로드, 확대 이미지 재추출, 90ms 입력 안정화와 Present/vsync는 제외한다. P95는 15표본의 nearest-rank 값이다. 과거 441ms와 직접 빼지 않고 같은 회차의 DLL을 비교한다.
- 확인 회차의 ACB 2015 화면 맞춤 기준 DLL에서 한 표본이 30초 제한을 넘었다. 해당 항목의 불완전 표본과 짝 후보 값은 요약에서 제외하고, 새 프로세스에서 두 DLL을 모두 준비 3회+측정 15회로 재측정한 `2R`을 사용한다. 원래 오류를 포함한 원자료는 보존한다. 다른 문서·배율은 원래 확인 회차 값이다.

ACB 2015 전체 완료 중앙값 감소율은 화면 맞춤 +4.7~+7.0%, 100% +2.2~+4.3%, 200% -0.2~+12.0%였다. 양수는 단축, 음수는 악화다. 메모리·명령량 감소는 별도로 확인한 이득이며, 이 속도 범위를 모든 PDF·GPU에 일반화하지 않는다.

## 후보를 구분한 결과

- 빈 레이어를 보관한 채 replay에서만 건너뛴 초기 후보는 ACB 2015에서 화면 맞춤 1,232.8→1,203.0ms, 100% 1,139.1→1,183.6ms, 200% 560.4→594.6ms였다. 저장 화면은 같았지만 속도 이득이 일관되지 않아, 최종판은 명령 저장 공간도 줄이는 생성 시 압축으로 바꿨다.
- 직접 도형 합성만 적용한 중간 후보는 ACB 2015 화면 맞춤 526.5→468.9ms, 100% 410.7→405.2ms, 200% 465.7→501.9ms였다. 두 문서 세 보기의 저장 화면 6개는 모두 기준과 같았다. 최종판에는 빈 명령 압축과 유한 역행렬 검사도 포함하므로 이 값을 최종판 수치로 쓰지 않는다.
- 미세 효과 자체를 생략한 별도 후보는 화면 맞춤의 회차별 방향이 달랐고, 최악 합성 조건의 오차 부담도 컸다. [미세 효과 실험 기록](GPU_SUBPIXEL_EFFECT_BENCHMARK_2026-10-20.md)만 남기고 적용하지 않았다.

## 검증과 한계

- 관련 테스트 **101개 통과**: gpu_raster 80개, d2d_backend 9개, gpu_composite_integration 12개. C++ /W4 /WX와 FXC 엄격 빌드도 통과했다.
- 새 빈 레이어 검사는 DPI 2개×Normal/COPY/비격리/mask 상태 4개×변환 4개의 32조건에서, 빈 레이어가 없는 worker 화면과 BGRA 전체를 정확히 비교한다. 다른 좌표·opacity 0·재귀적으로 빈 레이어를 여러 번 넣고, 그 뒤의 그리기와 바깥 clip/pop 상태가 같은지 검사한다.
- 새 bitmap 좌표 검사는 600×100 viewport의 타일 경계를 가로지르는 도형 안에 다른 색의 이미지와 Multiply를 그리고, 반투명 그룹을 네 번 겹친다. DPI 96/144, 이동·반사·기울이기의 6조건에서 일반 마스크 합성과 최대 채널 차이 6 이하를 확인한다. 기존 mask-based fusion도 이 추가 조건에서 최대 4 차이가 있었다. 이는 검사한 합성 조건의 허용치이며 모든 PDF의 전역 오차 보장이 아니다.
- 기존 격리 클립 회귀 검사의 중첩·COPY·비격리·knockout·다른 혼합·mask-build·반복 scratch 덮어쓰기 등 240조건은 기존 허용치 3을 그대로 유지한다. 마스크 LUT·15 blend mode·투명도·취소·viewport culling 검사도 유지한다.
- 저장 화면은 조건별 첫 준비 실행(index 0)이다. 모든 반복 표본의 픽셀, 모든 PDF·GPU를 검증한 결과가 아니다. 30ms 폴링과 시스템/GPU 부하가 측정에 포함되므로 작은 차이나 제어 문서의 큰 변동을 일반적인 가속으로 해석하지 않는다.
