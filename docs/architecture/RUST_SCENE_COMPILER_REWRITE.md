# Rust GPU 장면 컴파일러 전면 교체

구현·검증: 2026-10-31~2026-11-01. 미배포 버전 1.37.3 유지.

## 기본 경로 전환 완료

앱의 Document.gpu_vector_page와 GPU 작업 프로세스는 모두
pdfeditor.rust_scene_compiler.compile_vector_page를 사용한다.
Python 추출기로 중간 장면을 만든 다음 Rust로 옮기던 시제품을 교체했다.

- native/mupdf_scene.h는 정확히 같은 버전의 MuPDF SDK로 페이지를 한 번 수집하고
  경로·글자·이미지·음영·스코프 자원을 보유한다. Python device 콜백은 없다.
- Rust scene_compiler/native_input.rs가 clip/group/mask/tile 범위를 검사하고,
  복합 삽화 단순화, 알파 이미지 결합, 클립에 따른 이미지 영역, 자원별 밀도와
  전체 이미지 예산을 결정한다. SDK 어댑터는 요청받은 자원과 픽셀만 제공한다.
- 선형·방사형 그래디언트의 형상과 색상표, 선 스타일, 글자 geometry group,
  이미지 채널 변환, 장면 소유권·자원 중복 제거·실행 명령은 Rust가 구성한다.
  채움 글자, 윤곽선 글자, 텍스트 클립과 지원되는 그래디언트는 벡터다.
- 마스크의 휘도와 전달 함수는 SDK에서 실제 coverage로 평가한 뒤 Rust의
  알파 장면으로 들어간다. 타일·일반 음영과 복합 영역은 필요한 경우만 래스터화한다.
- 완성된 LFSC v2 패킷을 rust_scene_import.h가 GPU에 한 번에 업로드한다.
  GUI는 경로·글자·도형 객체를 만들거나 명령별 ctypes 호출을 하지 않는다.
- 큰 패킷의 작업 프로세스 전송에는 기존 Rust의 제한된 무손실 블록 병렬 압축을
  유지한다. MuPDF 객체는 호출 스레드에 남고 독립 버퍼만 Rust 스레드가 처리한다.
- 누락된 네이티브 모듈·잘못된 입력·예산 초과는 CPU 화면으로 돌아간다.
  Python 컴파일러로 재시도하지 않는다. 제한 시간은 수집과 자원 생성 중 검사하며,
  기존 작업 세대·프로세스 취소·장치 손실 및 CPU 미리보기 경로를 유지한다.

기존 vector_page_from_pymupdf와 compile_scene는 비교 기준과 과거 정책 회귀 검사에만
남아 있다. 앱의 두 컴파일 진입점은 이들을 호출하지 않는다. 새 경로 검사는 기존
추출기와 좌표 변환 함수를 실패하도록 막은 상태에서도 PDF에서 GPU 패킷까지 만든다.

## 메모리·표현 범위

이미지는 페이지 전체에서 64MiB 예산을 나눠 사용하고 자원은 128MiB,
명령은 1,048,576개, 스코프 깊이는 4,096단계, 전송 패킷은 256MiB로 제한한다.
고배율에서는 뷰포트와 주변 준비 영역에 필요한 이미지 부분만 만든다.
원래 이미지의 픽셀 격자를 유지해 작은 이미지 확대 시 불필요한 투명 테두리가
생기지 않으며, 사진 보간과 이진·스텐실 아트의 표본 규칙은 Rust에서 결정한다.

작은 녹아웃 삽화는 128~65,536개 명령, 페이지 면적 0.5% 이하, 최대 64영역을
후보로 삼는다. 비격리 녹아웃 그룹은 기존에 허용한 격리 근사를 사용한다.
텍스트가 들어간 후보는 통째로 래스터화하지 않는다. 일부 투명도·음영 경계가
CPU 또는 이전 GPU와 다를 수 있으므로 CPU 모드를 정확도 기준으로 남긴다.

## 반복 성능 비교

각 문서·경로를 새 프로세스에서 5회씩, 순서를 번갈아 총 20회 실행한 중앙값.
기준은 전면 교체 직전의 Rust 도형 연산·네이티브 경로 수집까지 적용된 Python
장면 컴파일러다. Rust 도입 이전 전체와의 비교 수치가 아니다.

총 시간은 PDF 열기, 장면 컴파일, 메모리 산정, 작업 전달용 dump/load,
네이티브 업로드와 1200×900 맞춤 화면의 GPU 완료/readback을 포함한다.
프로세스·모듈 시작, PDF 스냅샷 작성 및 실제 파일 IPC는 제외한다.
첫 CPU 미리보기 표시 시간이나 스토어 설치본의 전체 시작 시간도 아니다.

| 항목 | ACB 2015 기존 → Rust | ACB 2019 기존 → Rust |
|---|---:|---:|
| GPU 준비~화면 완료 | 1,498.3 → 955.5ms (-36.2%) | 1,097.4 → 907.7ms (-17.3%) |
| PDF 열기+컴파일 | 991.2 → 594.9ms | 781.3 → 673.1ms |
| 작업 전달 dump/load | 58.7 → 2.4ms | 55.3 → 20.7ms |
| GPU 자원 업로드 | 209.1 → 165.4ms | 157.3 → 133.9ms |
| 장면 보관 비용 | 9.07 → 3.07MiB (-66.2%) | 26.70 → 12.58MiB (-52.9%) |
| 전송 크기 | 7.44 → 3.07MiB | 7.47 → 2.54MiB |
| 프로세스 최대 RSS | 301.0 → 256.7MiB | 432.9 → 262.7MiB |

장면 보관 비용은 기존 Python 장면과 새 불변 패킷을 같은 캐시 산정 함수로 잰 값이다.
임시 Rust IR을 포함한 작업 전체의 메모리는 별도 최대 RSS 행으로 구분했다.
2015의 GPU 그리기 자체는 185.2 → 198.6ms로 소폭 느렸다. 개선은 주로 준비·전송에서
나왔으며, 모든 개별 그리기 단계가 빨라졌다는 의미는 아니다.

첫 후보는 2015에서 퇴행했다. 원인은 큰 배경 그래디언트의 CPU 래스터화였고,
선형·방사형을 Rust 벡터 명령으로 옮겨 제거했다. 최종 측정은 이 수정 후의 값이다.

## 화면과 회귀 검증

기존 회귀와 새 경로 검사를 합쳐 762개가 통과했다. Windows의 임시 설정 파일
잠금으로 한 번 실패한 검사는 별도 프로세스에서 다시 통과했다. 로컬 실문서 9종도
Python 추출기를 강제로 차단한 상태에서 모두 네이티브 장면으로 컴파일했다.

ACB 2015/2019 각각 맞춤·100%·200%·800%에서 해당 배율과 주변 뷰포트에 맞춰
두 컴파일러의 장면을 새로 만들고 동기 GPU 완료 화면을 비교했다. 총 8개 화면의
벡터 글자와 선, 그림·사진·배경을 확인했다. byte 동일성을 주장하지 않는다.

| 평균 채널 차이 / 255 | ACB 2015 | ACB 2019 |
|---|---:|---:|
| 맞춤 | 0.2410 | 0.2466 |
| 100% | 0.6912 | 1.0245 |
| 200% | 0.8892 | 0.2686 |
| 800% | 0.9384 | 0.0013 |

평균은 화면 전체 기준이며 일부 경계의 국소 차이를 숨길 수 있다. 800%의 최대
채널 차이는 각각 146, 2다. 투명도·보간에 따른 차이가 있으므로 정확도 확인은 CPU 모드다.
작은 CMYK·알파 이미지의 색상과 확대 보간, 윤곽선 글자와 텍스트 클립,
마스크·전달 함수·중첩 혼합·타일, 잘못된 입력과 시간 제한도 별도 검사한다.

개인 PDF와 생성 화면/원시 측정은 tmp/rust-audit 아래에만 둔다.
재현 명령:

```text
python -m tests.benchmark_rust_compiler --runs 5 --output <JSON> <PDF...>
python -m tests.audit_native_scene_zoom --output <JSON> <PDF...>
python -m tools.ci.run_tests --single tests.test_native_scene_compiler
python -m tools.ci.run_tests
```

버전은 1.37.3으로 유지하고 양 언어의 변경 이력·릴리스 노트에 누적했다.
릴리스와 MSIX 생성은 별도 요청 때 진행한다.
